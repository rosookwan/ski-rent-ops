# 힉스필드(Higgsfield) 시안 라이브러리 · ski-rent-ops 전용

작성일: 2026-09-20

이 폴더는 힉스필드로 만든 **스키노트 POS 시안만** 모아 두는 곳이다. 같은 힉스필드 계정에서 다른 프로젝트(예: 테니스 클럽 앱) 시안도 만들고 있으므로, 프로젝트별로 섞이지 않게 아래 규칙을 지킨다.

## 1. 힉스필드 쪽 사정 (2026-09-20 확인)

- 힉스필드 MCP에는 **폴더·라이브러리·컬렉션을 만드는 도구가 없다.** 생성 기록(`show_generations`)은 계정 전체가 한 목록으로 나온다.
- 계정을 나누는 단위는 **워크스페이스**뿐이다. MCP로는 목록 조회(`list_workspaces`)와 전환(`select_workspace`)만 되고 생성은 안 된다. 현재 계정에는 이름 없는 개인 워크스페이스 1개(크레딧 1,734, max 플랜)만 있다.
- 워크스페이스는 힉스필드 사이트에서 만든다. 만든 뒤 `select_workspace`로 전환하면 이후 생성·크레딧·업로드가 모두 그 워크스페이스로 잡힌다. 전환 상태는 세션이 바뀌어도 유지되므로 다른 프로젝트 작업 전에는 `clear`로 되돌린다. 크레딧은 워크스페이스별로 따로 잡히므로 새 워크스페이스에는 별도 크레딧이 필요할 수 있다.

## 2. 분리 규칙 (이 저장소에서 지키는 것)

| 구분 | 규칙 |
|---|---|
| 저장소 폴더 | `design/higgsfield/<묶음>/` 아래에 요청서 `requests.json`, 결과 등록부 `results.json`, 내려받은 PNG, 보기용 `index.html`을 함께 둔다. 묶음 이름은 `pos-main-v1`처럼 `대상-라운드`로 짓는다. |
| 원본과 미리보기 | 원본 PNG(46장 · 약 127MB)는 시안 브랜치 `claude/pos-ui-improvement-q9yqku`와 힉스필드에만 둔다. `main`과 구현 브랜치에는 같은 이름의 가벼운 미리보기(`.jpg`)만 둔다(2026-09-21 결정 · `docs/42` 12절). 새 시안도 같은 방식으로 한다: 원본은 시안 브랜치에 커밋하고, 여기에는 미리보기만. |
| 화면 표기 | 모든 시안의 헤더 왼쪽에 보라색 `스키노트` 워드마크와 매장명을 넣는다. 힉스필드 히스토리에서 썸네일만 봐도 이 프로젝트임을 알 수 있다. |
| 프롬프트 첫 문장 | 첫 문장에 `스키노트` POS(스키 렌탈샵 카운터) 화면임을 적는다. 히스토리의 프롬프트로 걸러낼 수 있다. |
| 작업 ID 등록 | 생성이 끝나면 `results.json`에 job id · 모델 · 크기 · 원본 URL · 파일명을 적는다. 다시 볼 때는 히스토리를 뒤지지 않고 `show_generation_by_ids`에 이 job id를 넘긴다. 참조 이미지로 쓸 때도 이 job id를 `image_references`로 넘긴다. |
| 워크스페이스 | 이 프로젝트용 워크스페이스가 생기면 `results.json`의 `workspace`에 id를 적고, 생성 전에 `select_workspace`로 전환한다. |

## 3. 생성 설정

| 항목 | 값 |
|---|---|
| 모델 | `gpt_image_2_5` (variant `flare`) · 한글 글자 렌더링과 참조 이미지 편집이 되는 모델 |
| 품질·해상도 | quality `high`, resolution `2k` |
| 비율 | `27:16` (1.6875) · 1024×600 POS 표시 영역(1.7067)에 가장 가까운 지원 비율 |
| 비율(데스크톱) | `16:9` · 관리 콘솔처럼 MacBook 브라우저에서만 보는 화면. 기준 1440×810. 출력 2688×1520 |
| 비율(휴대폰) | `9:16` · 세로 화면. 기준 360×640(작은 휴대폰에서 주소창이 보일 때). 출력 1520×2688 |
| 비용 | 장당 3 크레딧 (`get_cost` 사전 확인값, 2026-09-20) |
| 일관성 | 첫 화면(앵커)을 먼저 만들고, 나머지는 앵커 결과의 job id를 `image_references`로 넘겨 같은 셸·색·글자 크기를 유지한다. |

## 4. 검수와 재생성 기준 (2026-09-21)

- **검수**: 결과를 내려받아 구역별로 1:1 크기로 잘라 문구를 읽고, 글자 크기는 픽셀로 잰다. 2k 출력(2592px)은 1024px 프레임의 2.531배라서 16px 굵은 한글의 글자 높이는 36px, 18px은 40px, 22px은 50px이다.
- **재생성은 구조 문제일 때만**: 레일 메뉴 오류, 잘린 카드, 말줄임표, 글자 크기, 주황 버튼 난립, 메뉴·버튼·상태 같은 업무 용어 오기. 고객 이름·전화번호·금액·매장명 같은 **샘플 데이터의 오탈자·누락은 기록만 하고 다시 뽑지 않는다**(사용자 지시 · 크레딧 절약).
- 다시 뽑을 때는 발견한 문제만 프롬프트 끝에 덧붙이고 `requests.json`의 `promptRevision`에 사유를 적는다. 한글 문구와 설정 값은 그대로 둔다.
- 활성 메뉴는 이름과 함께 **"위에서 몇 번째 버튼"** 으로 적는다. "Active rail item 2 준비·지급"처럼 번호로 시작하는 이름만 적으면 모델이 "둘째 칸"으로 읽어 레일 순서가 깨졌다(`pos-main-v1` P04·P05).
- 작은 글자(칩·범례·전화번호)는 요청보다 1~3px 작게 그려지는 경향이 있다. 시안에서는 메모로 남기고, 구현할 때 CSS로 16px 이상을 고정한다.
- **셸이 다른 화면은 기준 화면부터.** 관리(레일이 다름) · 팝업(부모 화면 위) · 기사 태블릿(레일 없음·보라)은 각각 한 장을 먼저 뽑아 직접 검수하고, 그 job id를 나머지의 둘째 참조로 넣는다. 팝업은 [부모 화면, 팝업 기준] 두 장을 참조로 준다. 헤더는 프롬프트에 "매장명·알림 종·나가기까지 항상 완전"이라고 적는다(`pos-rest-v1`).
- 탈락한 후보와 1차 시도는 저장소에 넣지 않고 `results.json`에 job id·URL·판단만 남긴다.
- **그림은 크기를 보증하지 않는다.** 모델은 글자와 바를 실제보다 작게 그려서 "1024×600에 다 들어간 것처럼" 보이게 한다. 채택한 화면은 묶음 폴더의 `fit-check/`처럼 요청서의 글자 크기 그대로 HTML로 그려, 문서의 최저 표시 영역(필수 1024×600, 낮고 좁은 창 907×648 · `docs/38` 7-3)에서 잘림을 픽셀로 잰다. 크레딧이 들지 않는다.
