# Claude Design에 순서대로 전달할 시안 프롬프트

같은 디자인 프로젝트에서 1번부터 하나씩 전달합니다. 결과를 확인하고 다음 번호로 넘어갑니다. 각 코드 블록을 별도로 복사하며, 전체 문서나 여러 번호를 한 번에 붙이지 않습니다.

범위는 현재 정리한 운영 보드와 장비 대여·요금·견적·결제 기록·마감 화면입니다. 사전 사이즈 입력폼과 QR 이용 안내는 이후 시안으로 남깁니다. 모든 금액·고객·발송 결과는 가상 시연 자료입니다.

## 1. 공통 디자인과 화면 틀

```text
스키렌탈샵 직원용 웹앱/PWA의 클릭 가능한 시안을 만들어줘. 카운터 PC·터치모니터와 차량 태블릿에서 사용하며, 중장년 직원도 쉽게 읽고 누를 수 있어야 해.

이번 단계는 공통 디자인과 화면 틀만 만들어줘.
- 매장 화면 1440×900, 차량 가로 태블릿 1280×800을 기준으로 구성.
- 두 화면의 디자인을 다르게 해줘. 매장은 Makaryo POS를 참고한 주황 포인트의 모니터 화면: 상품 선택/고객·반납/견적 패널. 차량은 Task management & to-do list app을 참고한 보라 포인트의 갤럭시 탭 화면: 날짜·업무 목록과 큰 방문 카드. 원본 휴대폰 화면을 확대하지 말고 가로 태블릿에 맞춰 재배치.
- 밝은 배경, 흰 패널, 짙은 글자. 배달은 파랑, 수거는 주황, 완료는 초록으로 글자와 색을 함께 표시.
- 본문 약 20px, 중요한 시간·장소는 32~40px, 터치 버튼 높이는 64px 전후.
- 매장 메뉴: 오늘 업무 / 새 대여 / 반납 확인 / 하루 마감 / 관리.
- 간단·자세한 모드 전환. 모드는 정보량만 바꾸고 직원 권한은 유지.
- 상호·역할·연결 상태·마지막 갱신 시각 표시. 상호는 ‘샘플스키샵’.

샘플 데이터와 모의 동작으로 시안을 만들고, 실제 전화·문자·결제·서버 연결은 하지 마. 미리보기에는 데모임을 표시해줘. 이후 요청은 이 디자인과 공통 데이터를 유지하며 해당 기능만 추가해줘. 지금은 세부 업무 화면을 먼저 만들지 마.
```

## 2. 카운터의 오늘 업무 보드

```text
기존 공통 디자인을 유지하고 ‘오늘 업무’ 화면만 추가해줘.

- 필터: 전체 / 배달 / 수거 / 매장 직접 반납 / 매장 확인 대기 / 완료.
- 보기 전환: 시간순 / 장소별. 장소별 안에서도 시간순으로 정렬.
- 각 건에 시간, 장소, 이름, 연락처, 실제 장비 수량, 담당 차량, 상태 표시.
- 배달 상태와 반납 상태를 별도로 표시해줘. 예: ‘배달 완료 · 수거 대기’.
- 기사님이 물건을 받으면 ‘수거 완료’, 매장이 최종 확인해야 ‘반납 완료’야. 수거 완료 건은 매장 확인 대기에 표시.
- 간단 모드는 큰 카드, 자세한 모드는 여러 건을 비교하는 목록으로 구성.
- 예정 시간 지남, 장소 변경됨, 일부 수거 상태를 글자로도 표시.

만선 티롤 앞 등을 포함해 상태가 서로 다른 샘플 6건을 보여줘. 실시간 변경은 모의 동작으로 표현하고, 새 자료 때문에 누르던 카드가 갑자기 다른 위치로 움직이지 않게 해줘. 필터·정렬·상세 열기까지 클릭 가능하게 만들어줘.
```

## 3. 새 대여 접수와 2일·3일 입력

```text
기존 화면을 유지하고 ‘새 대여’ 접수 화면을 추가해줘.

- 이름·연락처 입력과 기존 고객 검색·선택. 대표자 이름 또는 전화번호 일부로 검색하고 동명이인은 연락처를 보고 직접 선택. 고객 상세에는 날짜·일수·장비별 수량·당시 금액의 이용 이력, 신규 등록·정보 수정 버튼을 배치. 고객을 선택해도 과거 요금·할인을 자동 적용하지 마.
- 위에서 공통 이용 기간을 [1일][2일][3일][직접 입력]으로 한 번 선택. 이용 날짜와 반납 예정 시각도 함께 표시.
- 이용 시작일·종료일 날짜 선택도 제공하고 기본값은 오늘. 오늘 수령해 내일~모레 이용하는 건도 입력 가능해야 해. 기간 버튼은 선택한 시작일부터 계산하고, 시작일 변경 시 현재 일수를 유지. 반납 타임은 이용 종료일 기준으로 계산하고 수령일과 청구 이용일은 구분해줘.
- 반납 예정은 [오후타임 후][야간타임 후][익일 오전][직접 시간 선택] 큰 버튼으로 받아줘. 직접 선택에서는 날짜+시간 입력. 타임 선택에서는 실제 날짜와 정렬 기준 시간을 함께 표시.
- 익일 오전은 마지막 이용일의 다음 날이야. 12/20~21 이틀 이용이면 12/22 오전 반납이며 청구 일수는 2일 유지. 타임 선택만으로 리프트권을 추가하거나 요금을 변경하지 마.
- 상품 선택 영역 맨 위를 [장비] [리프트권] 탭으로 나눠줘. 장비는 스키, 보드, 의류, 바이저헬멧, 헬멧, 고글, 보호대. 날짜 버튼을 골라 그날 이용할 수량을 큰 −/+ 버튼으로 입력. 첫날 4개·둘째 날 3개가 가능하고 날짜 이동 시 다른 날 값은 유지해야 해. ‘이 수량을 모든 이용일에 적용’으로 복사 후 개별 수정도 가능하게 해줘.
- 수령 방법은 매장 수령/차량 배달, 반납 방법은 직접 반납/차량 수거를 각각 선택. 필요한 날짜·시간·장소만 펼쳐줘.
- 리프트권은 별도 탭에서만 선택. 첫날 4매·둘째 날 3매처럼 날짜별로 입력하고 날짜 버튼에 매수를 표시. 성인/소인·이름 검색·자주 사용/전체 권종·타임권/시간권 분류 제공. 오른쪽 견적에는 선택한 날짜·권종·매수만 표시. 팝업의 별도 적용 단계 없이 바로 초안에 반영하고, 공통 장비 일수를 다시 곱하지 마.
- 장비 첫날 4개·둘째 날 3개면 20,000원 × 4 + 20,000원 × 3 = 140,000원. 날짜별 합계 7을 실제 지급·수거 수량으로 사용하지 마. 일별 최대 4개를 제안하고 실제 지급·마지막 수거 수량을 따로 확인. 4개 지급·3개 마지막 수거로 확인하면 기사님에게는 3개만 전달해줘. 중간 배달·수거를 자동 처리했다고 표시하지 마.
- 글자·터치 버튼 크기는 유지하고 상하 여백만 적당히 줄여줘. 한 화면에 억지로 넣기 위해 전체를 작게 만들지는 마.

대표 시연 건 R-001: 스키 1대 20,000원/일 + 의류 1개 10,000원/일, 2일이면 40,000원+20,000원=60,000원. 수량은 각각 1로 유지하고 ‘1대 × 2일’처럼 계산을 보여줘. 3일 선택 시 90,000원이어야 해.
특정 상품만 기간을 바꾸는 기능은 자세한 모드에 넣어줘. 자정 통과만으로 청구 일수를 늘리지 말고 적용 이용일을 확인할 수 있게 해줘.
```

## 4. 상품·가격·매장 관리자

```text
기존 화면을 유지하고 관리자용 ‘상품·가격 설정’을 추가해줘.

- 상품 이름·카테고리·단위·사용 여부·1일 정가를 편집하는 목록과 편집 패널.
- 스키/보드 기본 구성, 의류·보호대의 개/세트 단위를 표시.
- 기본 다일 요금은 1일 가격×일수. 선택 설정으로 2일·3일 ‘전체 기간 가격’을 입력하고 계산 미리보기 제공. 전체 기간 가격에 일수를 다시 곱하지 마.
- 정가/단골/제휴업체별 요금표. 날짜·시즌별 요금은 자세한 설정에 배치.
- 리프트권은 스키장·권종·날짜 조건·판매가·선택 공급가·추가 할인 허용 여부를 별도 관리.
- 가격 미등록은 ‘미등록’, 무료 제공은 명시적인 0원으로 구분.
- 가격을 변경해도 이미 확정한 견적·대여 금액은 유지.
- 매장 반납 타임의 이름·기준 시간·마지막 이용일 대비 날짜 차이·적용 기간 설정. 시안 시간은 오후16:30/야간22:00/익일09:00으로 쓰고 예시라고 표시. 기존 접수의 타임 이름·예정 일시는 그대로 보관하고 자동 변경하지 마.

관리 안에 매장 정보·장소·문자 기본 문구 설정도 탭으로 둬. 다른 렌탈샵 확장을 고려해 관리자 미리보기에서 샘플 A/B 매장을 바꿔볼 수 있게 하고, 각 매장의 설정·데이터를 구분해줘. 기사님 화면에는 이 관리 기능을 노출하지 마.
```

## 5. 단골·제휴 할인과 견적서

```text
기존 새 대여 화면에 ‘가격·할인 확인’과 ‘견적서 미리보기’를 연결해줘.

- 정가/단골/제휴업체 중 요금표 하나를 선택. 단골과 제휴를 자동 중복 적용하지 마.
- 상품 줄마다 장비당 정액 할인 선택. 스키 2대에 장비당 5,000원이면 총 10,000원 할인하고 대여 일수는 다시 곱하지 마.
- 장비당 할인과 총 금액 할인 모두 기본 [단골 5,000원][단골 10,000원]. 퍼센트·접수 화면 할인 등록은 빼고 기본 금액 변경은 추후 관리자 기능으로 남겨줘. 메인 총 할인 버튼은 누를 때마다 누적하며 같은 버튼 반복도 합산. 적용 횟수와 [한 번 취소][전체 해제]를 표시하고 장비당 할인 후 총 할인을 적용. 총 할인 해제는 장비당 할인을 유지해야 해.
- 총 금액 할인은 할인 가능한 상품에만 적용. 리프트권은 해당 상품의 할인 허용 설정을 따라야 해.
- 정가, 적용 요금, 추가 할인, 최종 금액을 구분해 보여줘. 음수 금액은 막아줘.
- [견적서]를 누르면 A4 미리보기: 매장·고객·상품·실제 수량·이용일수·단가·할인·총액·수령/반납 일정·견적번호와 버전.
- 인쇄/PDF 저장 진입을 만들고, 견적 저장과 대여 확정을 별도 버튼으로 구분.

R-001의 정가 60,000원에 전체 추가 할인 5,000원을 적용하면 최종 55,000원이어야 해. 견적 출력만으로 수납이나 차량 업무를 생성하지 말고, [대여 확정]에서 해당 건을 오늘 업무에 연결해줘. 같은 건이 중복 생성되지 않게 해줘.
```

## 6. 차량 태블릿의 간단·자세한 모드

```text
기존 매장 화면과 데이터를 유지하고 차량 기사님 화면을 추가해줘. 가로 태블릿 1280×800 기준이야.

- 매장 POS와 다른 디자인으로 만들어줘. Task management & to-do list app의 보라색 포인트, 날짜·업무 카드 구성을 참고해서 갤럭시 탭 가로 화면으로 재설계. 간단 모드의 전화·문자·완료 버튼은 72px 전후로 크게 배치.
- 간단 모드: 현재 건과 다음 건 중심. 배달/수거 구분, 장소, 시간, 실제 물품 수량을 가장 크게 표시.
- 반납은 ‘오후타임 후’ 같은 문구를 크게, ‘12/21 · 기준16:30’은 바로 아래 표시. 실제 예정 날짜와 기준 시간으로 정렬하고, 3일 대여 후 익일 오전이나 직접 지정한 날짜도 날짜 선택에 포함해줘.
- 버튼: 전화 / 출발 문자 / 배달 완료 또는 수거 완료. 자세한 연락 동작은 다음 단계에서 연결.
- 자세한 모드: 배달·수거 전체 목록, 시간순/장소별 정렬, 담당 업무 필터, 메모·부분 수거.
- [전체 현황]에서 직접 반납 예정·완료도 확인. 기본 목록은 차량이 처리할 배달·수거 건.
- 기사님은 수거 완료까지만 처리하고 최종 반납 완료 버튼은 제공하지 마.
- 상단에 업무 시작, 연결·마지막 갱신, 충전·화면 유지 상태를 모의 표시.

R-001은 2일 대여여도 스키 1대·의류 1개로 보여줘. 완료 처리가 매장 화면의 같은 건에 반영되게 해줘. 모드 선택은 기억하고, 운행 중에는 장소·시간 표시와 짧은 음성 안내 중심으로 구성해줘. 전화·문자·상태 조작은 정차 후 사용하도록 배치해줘.
```

## 7. 전화·문자·기사님 알림

```text
기존 업무 카드의 연락 버튼과 매장→차량 알림을 모의 동작으로 연결해줘. 실제 통화·발송은 하지 마.

- [전화]는 번호가 큰 통화 연결 시안, [연락처 보기]는 번호 확인·복사.
- 출발 문자에는 [5분][10분][15분] 선택과 발송 버튼.
- 수거 문구: “[샘플스키샵] 수거 차량이 출발하였습니다. 약 5분 내 도착 예정이니 만선 티롤 앞에서 장비와 함께 대기해 주세요.”
- 배달 문구는 배달 장소에서 수령을 준비하도록 변경.
- 발송 시각·문구·성공/실패 이력과 중복 클릭 방지 상태 표시.
- 매장에서 [기사님 알림]을 누르면 차량의 해당 카드 강조 + 상단 배너 + 짧은 알림음. 소리는 [업무 시작] 후 재생.
- 요청됨/차량에 전달됨/기사님 확인함을 구분. 기사님이 [확인]해야 매장에 확인 시각 표시.

연결 끊김과 재연결도 시안에서 전환해볼 수 있게 해줘. 오래 지연된 ‘5분 내 도착’ 문자를 재연결 때 자동으로 보내지 말고, 완료·취소한 건의 오래된 알림은 종료해줘.
```

## 8. 매장 최종 반납 확인

```text
기존 데이터를 이용해 카운터의 ‘반납 확인’ 화면만 추가해줘.

- 목록을 매장 확인 대기 / 직접 반납 예정 / 일부 반납 / 완료로 구분.
- 고객·연락처·기사님 수거 시각·물품별 대여 수량·수거 수량·매장 확인 수량·남은 수량 표시.
- 정상 건은 [전체 확인·반납 완료]로 처리하고, 일부만 있으면 상품별 확인 수량을 조절.
- R-001에서 스키 1대만 확인했다면 의류 1개가 남아 전체 반납 완료되지 않아야 해.
- 직접 반납은 차량 수거 단계를 거치지 않고 매장에서 확인.
- 리프트권은 장비 반납 수량에서 제외.
- 완료 처리를 잘못 눌렀을 때 되돌리기와 변경 이력 제공.

최종 확인 뒤 선택할 [이용 감사 문자] 버튼과 문구 미리보기를 추가해줘: “[샘플스키샵] 이용해 주셔서 감사합니다. 다음 방문에도 더 만족하실 수 있도록 노력하겠습니다.” 발송은 모의 동작으로 해줘.
물품 반납 상태와 결제 상태는 독립적으로 유지하고, 반납 처리로 결제나 문자가 자동 실행되지 않게 해줘.
```

## 9. 결제 기록·미수금·보증금

```text
기존 대여 상세에 ‘대금 기록’ 패널을 추가해줘. 접수 이후 어느 단계에서도 열 수 있게 하고 실제 결제망은 연결하지 마.

- 최종 금액 / 받은 대금 / 환불액 / 남은 미수금을 크게 표시.
- 현금·카드·이체로 결제 기록을 추가하고 분할 수납 지원.
- 보증금 수령·반환은 대여 대금과 별도 영역·잔액으로 관리.
- 청구 대상은 고객 또는 제휴업체. 제휴 할인을 받았다는 이유만으로 업체 후불로 바꾸지 마.
- 금액 감소 조정과 실제 환불을 구분하고 담당자·시각·이력 표시.
- 중복 클릭으로 대금 기록이 두 번 생기지 않게 해줘.

R-001의 확정액 55,000원에서 현금 20,000원, 카드 30,000원을 받으면 미수는 5,000원. 보증금 현금 10,000원을 추가로 받아도 미수는 그대로 5,000원이어야 해. 이체 5,000원을 기록하면 미수는 0원.
‘미수 남음’과 ‘물품 반납 완료’를 동시에 표시할 수 있게 해줘. 간단 모드는 큰 금액과 입력 버튼, 자세한 모드는 전체 기록을 보여줘.
```

## 10. 하루 마감 보고서와 화면 연결

```text
기존 거래·대금 기록으로 ‘하루 마감’ 화면을 추가해줘.

- 간단 모드: 신규 확정액, 받은 대금, 환불, 순수납, 미수금, 보증금 잔액, 물품 확인 대기.
- 자세한 모드: 결제수단·상품·단골/제휴별 내역, 할인 내역, 현금 대조. 각 숫자를 누르면 근거 거래 목록으로 이동.
- 영업일 선택, 시작 시재, 실제 마감 현금 입력, 예상 현금과 차이 표시.
- 예상 현금에는 현금 대금과 보증금 입출금을 반영하고 카드·이체는 제외.
- 마감 미리보기/확정본, 인쇄·PDF 진입, 마감 후 정정 이력 제공.

R-001만 포함한 검산 장면: 확정액 55,000원, 첫날 현금 대금 20,000원+카드 30,000원, 미수 5,000원, 현금 보증금 10,000원. 시작 시재 50,000원이면 마감 현금은 80,000원. 다음 날 이체 잔금 5,000원을 받으면 그날 수납에만 기록하고 확정액을 다시 더하지 마.
반납 완료·견적 출력·다일 이용으로 거래 금액이 중복 집계되지 않게 해줘. 마지막으로 기존 화면의 접수→견적→대여 확정→차량 처리→매장 반납→마감 연결을 점검하고, 디자인을 새로 갈아엎지 말고 끊긴 연결만 보완해줘.
```
