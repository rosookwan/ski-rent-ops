## 구현 범위

이번 작업은 매장 모니터와 차량 태블릿에서 **화면을 이동하며 업무 흐름을 검토하는 시안**입니다. 입력·검색·탭·미리보기는 동작하지만 거래 저장·결제·발권·문자 발송·실제 인증은 없습니다. 서버 API와 브라우저 영구 저장소를 사용하지 않습니다. 새로고침하면 임시 로그인부터 다시 시작합니다.

| 화면 | 확인할 수 있는 흐름 |
|---|---|
| 임시 로그인 | 매장 POS / 차량 태블릿 진입, 로그아웃, 고객 화면 진입 |
| 오늘 현황 | 수령 예정·대여 중·최종 확인 대기·미수, 오늘 준비할 일, 차량 다음 일정 |
| 새 대여 접수 | 고객 검색, 미래 이용일, 장비와 리프트권 분리, 날짜별 수량, 장비당 할인·총 할인, 견적 확인 |
| 렌탈현황·상세 | 고객·연락처 검색, 이용일·상태 필터, 장비·리프트권, 수령·반납, 수납·환불, 변경 이력 |
| 배달·수거 | 차량 배달·수거·매장 직접 반납, 업무 상세, 기사님 확인 요청 화면 |
| 차량 태블릿 | 간단·자세한 모드, 업무·날짜 선택, 시간·장소 정렬, 연락·문자·완료 확인창 |
| 거래처 장부 | 리프트권 매입·판매, 장비 빌려오기·빌려주기, 미수·미지급, 장비 반환, 정산·상계 미리보기 |
| 하루 마감 | 고객/거래처 수납·지급, 미수, 결제수단, 현금 대조, 보고서·마감 확인창 |
| 사전 입력·준비 | 폼 발송·응답 목록, 응답 상세, 일행별 사이즈·이용일, 수령일 기준 준비표, 폼 질문 설정 |
| 고객관리 | 대표자 이름·연락처 검색과 대여 상세 연결 |
| 재고·정비 | 장비 가용 수량, 권종 재고, 거래처 장비, 정비 상태 미리보기 |
| 매장 설정 | 장비 종류·단가·다일 요금, 권종·매입가, 정액 할인, 운영 기준·직원 설정 미리보기 |
| QR 이용 안내 | QR 안내판·인쇄 미리보기, 매장 내용·반납 장소·FAQ 설정, 고객용 안내 페이지 |

‘접수 저장’은 통합 시안에서 견적 미리보기로 연결했습니다. 다른 저장·발송·완료 버튼도 샘플 원장을 바꾸거나 외부 동작을 실행하지 않습니다. 첫 시안 파일은 당시 기록을 위해 유지했습니다.

설정 화면에서 바꾼 값은 다른 화면의 실제 가격·재고에 반영되지 않습니다. 차량 샘플 업무와 새 화면의 샘플 원장은 각각 예시를 보여줍니다. 서로 다른 기기에 실시간으로 동기화되는 서비스가 아닙니다.

## Figma 참고를 적용한 방식

| 구분 | 원본에서 가져온 구성 원리 | 적용 |
|---|---|---|
| 매장 POS | Makaryo의 흰 패널, 옅은 회색 바탕, 주황색 선택·실행 버튼, 상품/고객/금액 영역 | 접수·목록·설정·정산까지 동일한 폰트·탭·입력창·표·대화상자 |
| 차량 태블릿 | Task management의 보라색 요약 영역, 연보라 바탕, 둥근 업무 목록 | 큰 장소·반납 타임, 간단/자세한 모드, 72px 주요 버튼 |
| 한글 구성 요소 | Wanted Design System을 참고한 한글 타이포그래피와 상태 의미 | Pretendard 고정, 줄바꿈·굵기·보조 설명 정리, 상태를 색과 글자로 함께 표시 |
| 고객용 휴대폰 | 짧은 단계별 입력과 좁은 안내 화면 | 일행 입력 4단계, FAQ 펼침, 반납 장소·방문 안내 바로가기 |

원본 Figma 전체를 자동 변환한 결과는 아닙니다. 원본 자료의 배치와 스타일을 스키샵 업무에 맞게 다시 구성했습니다. 차량 버튼은 정차 후 조작하는 흐름을 전제로 하며 실제 Galaxy Tab의 거치 거리·반사광·글자 크기는 현장 검토가 남아 있습니다.

## 주요 입력과 수량 기준

- 장비는 실제 개수와 이용 일수를 구분합니다. 스키 1개·의류 1개를 이틀 사용하면 60,000원인 기존 예시를 유지했습니다.
- 장비와 리프트권 모두 날짜별 수량을 달리 선택할 수 있습니다. 첫날 4개, 둘째 날 3개와 실제 지급·마지막 수거 수량은 같은 개념으로 취급하지 않습니다.
- 반납 예정은 오후타임 후·야간타임 후·익일 오전 또는 날짜·시간 선택으로 표현합니다.
- 장비당 정액 할인과 전체 정액 할인을 구분하고, 기본 5,000원·10,000원 버튼을 누를 때마다 전체 할인이 누적됩니다. 리프트권은 장비 할인 대상에서 제외합니다.
- 사전 사이즈 입력은 1~31일의 이용 날짜에서 일행별 이용일을 고를 수 있습니다. 3일째만 타지 않는 일행도 표현하며, 이전 단계로 돌아가도 작성 중인 정보가 유지됩니다.
- 오늘 장비를 받아 내일부터 사용하는 고객은 오늘의 준비표에 표시합니다. 폼 응답은 예약·가격을 자동 변경하지 않습니다.
- 차량 수거와 매장 최종 반납 확인을 구분합니다. 거래처 장비 잔량과 거래처 금전 잔액도 별개입니다.

## 빌드와 공개 주소

`scripts/build.py`는 저장소 안의 CSS·JavaScript·폰트·아이콘·QR 이미지를 합쳐 `dist/index.html`을 만듭니다. Python 표준 라이브러리만으로 빌드하며 Codex 설치나 CDN 접속이 필요하지 않습니다. 글꼴·아이콘의 출처와 라이선스는 [vendor 안내](../design/vendor/README.md)에 있습니다.

- 매장/차량 진입: https://rosookwan.github.io/ski-rent-ops/
- 고객 이용 안내: https://rosookwan.github.io/ski-rent-ops/?view=guest-guide
- 고객 입력폼 체험: https://rosookwan.github.io/ski-rent-ops/?view=guest-form

공개 입력폼은 가상 고객으로 시작하는 공통 데모 링크입니다. 실제 고객별 발송에는 추후 매장·예약별 제한된 토큰과 만료·동의·제출 처리 기능이 필요합니다. 이 공개 페이지에 실제 개인정보를 수집하는 기능은 없습니다.

`main` 푸시 시 GitHub Actions에서 구문 검사와 빌드 후 Pages로 배포합니다. 브라우저 검사는 README의 로컬 실행 절차 또는 `SKI_DEMO_URL`에 공개 주소를 지정해 수행합니다. 최초 공개 주소의 응답과 진입 흐름은 배포 완료 후 재확인합니다.

## 실제 운영으로 확장할 때

먼저 한 매장의 운영값과 업무 흐름을 화면으로 확인한 다음, [다른 매장 확장 구조](04-multi-shop-architecture.md)에 따라 매장별 데이터·권한·가격표를 연결합니다. 현재 UI의 매장명, 제품, 장소, 타임, 할인, 거래처는 실제 서비스에서 각 매장 설정으로 이동합니다.

후속 순서는 실제 인증과 매장 분리 → 예약·대여 저장 → 실시간 차량 공유 → 실제 지급·수거·최종 반납 수량 기록 → 수납·장부·마감 → 고객별 폼·QR 내용 발행 → 문자·전화·화면 유지의 실제 기기 검증입니다. 간단/자세한 모드는 화면 밀도이며 관리자 권한을 부여하는 설정이 아닙니다.
