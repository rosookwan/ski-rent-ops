# 배달·수거·반납 운영 보드

상태: 대화에서 합의한 1차 기능과 이를 구현하기 위한 세부 기준 · 2026-09-07

## 목적과 사용자

카운터에서 고객 이름·연락처·장비 수량·반납 시간·장소를 기록하고 기사님이 다시 메모해 가는 과정을 하나의 공유 보드로 바꿉니다. 시간·장소 변경과 업무 완료 여부도 양쪽 화면에 반영해 확인 전화와 문자를 줄입니다.

| 사용자 | 담당 업무 |
|---|---|
| 매장 관리자 | 매장 설정, 직원 권한, 상품·가격 설정, 전체 업무 확인 |
| 카운터 직원 | 접수·수정, 배달·수거 요청, 연락, 최종 반납 확인. 금액 기능은 부여된 권한 범위에서 사용 |
| 차량 기사님 | 맡은 배달·수거 확인, 고객 연락, 출발·배달 완료·수거 완료 처리 |

간단·자세한 모드는 정보량을 바꾸는 화면 설정입니다. 자세한 모드로 바꿔도 관리자 권한이나 매장 최종 반납 권한이 생기지 않습니다.

## 접수 정보

| 구분 | 정보 |
|---|---|
| 공통 | 접수번호, 대표자 이름, 연락처, 선택 메모 |
| 장비 | 상품별 실제 수량. 첫 화면에는 스키·보드·의류·헬멧·보호대 등을 큰 수량 버튼으로 표시 |
| 수령 방법 | 매장 수령 또는 차량 배달 |
| 배달 | 예정 날짜·시간, 장소, 배달할 상품·수량 |
| 반납 방법 | 매장 직접 반납 또는 차량 수거 |
| 반납·수거 | 오후타임 후 / 야간타임 후 / 익일 오전 / 직접 시간 선택, 실제 예정 날짜·기준 시간, 장소, 대상 상품·수량 |
| 업무 정보 | 담당 매장, 차량·기사 배정, 현재 상태, 마지막 변경 시각 |

수령 방법과 반납 방법은 독립적으로 선택합니다. ‘배달 + 직접 반납’, ‘매장 수령 + 차량 수거’, ‘배달 + 차량 수거’, ‘매장 수령 + 직접 반납’을 모두 지원합니다.

한 고객의 물품을 시간·장소별로 나눠 처리해야 하면 같은 대여 건 안에서 배달 또는 수거 업무를 분리할 수 있도록 데이터 구조를 둡니다. 기본 접수 화면은 각 업무 한 건으로 시작합니다.

장소는 매장별 등록 목록에서 선택합니다. ‘만선 티롤 앞’ 같은 표시 이름과 내부 장소 ID를 함께 사용해 줄임말 때문에 다른 장소로 묶이지 않게 합니다. 임시 장소 직접 입력은 예외 기능으로 제공합니다.

## 반납 예정 입력

카운터는 큰 버튼으로 **[오후타임 후] [야간타임 후] [익일 오전] [직접 시간 선택]** 중 하나를 고릅니다. 차량 수거와 매장 직접 반납에 같은 입력 방식을 사용합니다. 배달 일정은 반납 예정과 별도로 지정합니다.

| 선택 | 날짜 해석 | 화면 예시: 12/20~21 이틀 이용 |
|---|---|---|
| 오후타임 후 | 마지막 이용일의 오후타임 종료 이후 | 12/21 · 오후타임 후 · 기준 16:30 |
| 야간타임 후 | 마지막 이용일의 야간타임 종료 이후 | 12/21 · 야간타임 후 · 기준 22:00 |
| 익일 오전 | 마지막 이용일의 다음 날 오전 | 12/22 · 익일 오전 · 기준 09:00 |
| 직접 시간 선택 | 직원이 날짜와 시간을 직접 지정 | 12/21 · 17:20 |

위 시각은 시안용 설정 예시이며 실제 스키장의 운영시간을 확인한 값이 아닙니다. ‘익일’의 기준을 접수한 오늘로 해석하지 않습니다. 3일 이용이 12/22에 끝나면 익일 오전은 12/23입니다. 선택 결과의 실제 날짜와 시간을 즉시 표시합니다.

- 타임 이름, 기준 시간, 마지막 이용일에 대한 날짜 차이, 적용 기간은 매장별 설정으로 관리합니다. 자정 이후 종료하는 야간 타임은 다음 날 시각으로 표현할 수 있어야 합니다. 첫 시안의 설정 화면은 세 타임의 시각만 편집합니다.
- 기준 시간은 정렬과 배차를 위한 값입니다. 리프트 종료 이후의 이동 시간까지 정확히 약속한 도착 시각으로 표시하지 않습니다. 필요한 경우 직접 날짜·시간으로 변경합니다.
- 선택한 타임 ID·이름과 해석한 반납 날짜·시간, 기준 설정 버전을 접수 당시 값으로 보관합니다. 관리자가 기준을 바꿔도 저장된 업무를 일괄 재계산하지 않습니다. 기존 건은 직원이 변경 내용을 확인하고 저장해야 차량에도 변경됩니다.
- 직접 입력한 반납일이 마지막 이용일보다 빠르면 날짜와 이용 기간을 확인하도록 안내합니다. 기간을 조용히 줄이거나 요금을 바꾸지 않습니다.
- 타임 선택은 리프트권 구매와 독립적입니다. 리프트권을 구매하지 않아도 선택할 수 있으며, 선택만으로 리프트권을 추가하지 않습니다.
- ‘익일 오전’ 선택으로 청구 일수가 자동 증가하지 않습니다. 오전 반납 허용 범위·연장 요금은 별도 매장 정책이며, 무료 반납을 의미하지 않습니다.

## 상태와 완료 기준

| 흐름 | 상태 | 담당 |
|---|---|---|
| 매장 수령 | 수령 대기 → 수령 완료 | 카운터 |
| 차량 배달 | 배달 대기 → 배달 출발 → 배달 완료 | 기사님 |
| 차량 수거 | 수거 대기 → 수거 출발 → 수거 완료 | 기사님 |
| 수거 이후 | 수거 완료 → 매장 확인 → 반납 완료 | 매장 |
| 직접 반납 | 매장 반납 예정 → 매장 확인 → 반납 완료 | 매장 |

- 배달 상태와 반납 상태를 따로 표시합니다. 예: ‘배달 완료 / 수거 대기’.
- **수거 완료:** 기사님이 고객에게 대상 물품을 모두 받은 상태입니다. 차량에 물건이 있을 수 있습니다.
- **반납 완료:** 매장에서 대상 물품의 수량과 상태를 최종 확인한 상태입니다.
- 매장 확인은 카운터의 작업이며, 확인을 마칠 때 반납 완료로 저장합니다. 수거 완료 건은 ‘매장 확인 대기’ 목록에서 찾습니다.
- 일부만 받으면 ‘일부 수거’와 잔여 품목·수량을 표시합니다. 나머지는 계속 미처리로 남깁니다.
- 매장 확인에서도 일부만 확인할 수 있습니다. 누락 수량이 남은 대여 건을 자동으로 전체 완료시키지 않습니다.
- 직접 반납 건은 차량의 수거 완료 단계를 거치지 않습니다.
- 장비 반납과 결제 완료는 별도입니다. 미수금이 있어도 장비를 실제로 받았다는 사실을 기록할 수 있어야 합니다.
- 잘못 처리한 완료는 권한에 맞게 되돌리고, 사유와 변경 전후 상태를 기록합니다.

## 화면 구성

카운터는 전체 현황에서 배달, 수거, 직접 반납, 매장 확인 대기, 완료 내역을 확인합니다. 차량 기본 화면은 오늘의 배달·수거 업무를 보여주고 ‘전체 현황’에서 직접 반납 예정·완료도 확인할 수 있게 합니다. 여러 차량을 쓰면 기본 범위는 배정된 차량 업무입니다.

정렬은 ‘시간순’과 ‘장소별’ 두 가지를 우선 제공합니다. 실제 예정 날짜로 업무를 나누고, 각 날짜 안에서는 해석된 기준 시간으로 정렬합니다. 장소별 보기 안에서도 시간순으로 정리합니다. 카드에는 ‘오후타임 후’ 같은 현장 표현과 실제 날짜·기준 시간을 함께 표시합니다. 날짜 선택 목록에는 다일 대여의 익일 반납과 직접 지정한 날짜도 포함합니다.

배달·수거는 글자와 색을 함께 사용합니다. 직접 약속한 시간이 지난 미처리 건은 ‘예정 시간 지남’, 타임 선택 건은 ‘기준 시간 지남’으로 구분합니다. 타임 종료 분에 맞춰 자동으로 연체 판정·독촉 문자·추가 요금을 발생시키지 않습니다.

매장은 Makaryo POS를 참고한 모니터용 상품·고객·견적 패널로, 차량은 Task management를 참고한 갤럭시 탭용 업무 카드로 설계합니다. 공통 데이터와 상태 의미를 공유하되 화면 배치·색상·여백·핵심 버튼의 크기는 다르게 적용합니다.

| 항목 | 간단 모드 | 자세한 모드 |
|---|---|---|
| 차량 표시 | 현재 건·다음 건 중심, 큰 장소·시간·수량 | 전체 목록, 필터, 부분 처리·메모·이력 |
| 차량 버튼 | 전화, 출발 문자, 배달 완료 또는 수거 완료 | 잔여 수량, 문자 이력, 상태 정정 등 |
| 매장 표시 | 새 접수, 반납 확인, 기사님 알림 | 전체 내역 검색·수정, 진행 상황·금액 이력 |
| 공통 | 충분히 큰 글자와 버튼, 색상+문구 | 기능이 늘어도 작은 글씨에 의존하지 않음 |

기기별 모드 선택을 기억합니다. 실시간 갱신 중에는 사용자가 누르려는 카드나 버튼이 갑자기 다른 위치로 이동하지 않도록 처리합니다. 연결 상태와 마지막 동기화 시각은 두 모드 모두 표시합니다.

차량의 운행 중 확인은 다음 장소·예정 시간 표시와 짧은 음성 안내를 중심으로 설계합니다. 전화·문자·상태 변경 조작은 정차 후 사용하도록 배치합니다. 큰 글자 모드를 주행 중 자유로운 조작을 보장하는 기능으로 설명하지 않습니다.

## 고객 연락

| 버튼 | 동작 |
|---|---|
| 전화 | 지원 기기의 전화 기능으로 연결. 태블릿의 실제 통화 가능 여부는 기종·회선 확인 필요 |
| 연락처 보기 | 전화번호를 크게 표시하고 복사 |
| 배달 출발 문자 | 해당 고객·배달 장소·선택한 예상 시간을 넣어 발송 |
| 수거 출발 문자 | 해당 고객·수거 장소·선택한 예상 시간을 넣어 발송 |
| 이용 감사 문자 | 매장 최종 반납 확인 이후 카운터에서 선택 발송 |

기본 예상 시간은 5분으로 하고 5·10·15분 버튼으로 변경합니다. 자동 경로 계산에서 얻은 도착 시간으로 표시하지 않습니다.

배달 출발 문구:

> [{매장명}] 배달 차량이 출발하였습니다. 약 {예상분}분 내 도착 예정이니 {배달장소}에서 장비 수령을 준비해 주세요.

수거 출발 문구:

> [{매장명}] 수거 차량이 출발하였습니다. 약 {예상분}분 내 도착 예정이니 {수거장소}에서 반납하실 장비와 함께 대기해 주세요.

마무리 문구:

> [{매장명}] 이용해 주셔서 감사합니다. 다음 방문에도 더 만족하실 수 있도록 노력하겠습니다. 조심히 돌아가시고, 좋은 하루 보내세요.

발신번호·문구는 매장별 설정입니다. 사용자가 버튼을 눌러 보내며, 상태 변경이나 화면 열기만으로 고객에게 문자를 자동 발송하지 않습니다. 프로그램은 서버의 문자 서비스에 연결하는 구조를 전제로 합니다.

발송 요청·처리 결과·실패·시각·실제 문구를 기록합니다. 발송 결과를 고객의 열람 여부로 표시하지 않습니다. 연속 클릭·재시도로 같은 발송이 중복되지 않게 합니다. 통신이 끊긴 동안 눌렀던 ‘5분 뒤 도착’ 문자를 한참 뒤에 자동으로 보내지 않도록, 출발 안내는 연결 복구 후 사용자가 새로 발송하도록 합니다.

## 기사님 우선 처리 요청

카운터의 해당 업무 카드에서 ‘기사님 알림’을 누르면 해당 차량에 알림음과 강조 표시를 전달합니다. 상단 알림 영역에도 업무 종류·고객·장소를 보여줍니다. 기사님이 ‘확인’을 누르면 카운터에 확인 시각을 표시합니다.

구분할 결과는 ‘요청됨’, ‘차량에 전달됨’, ‘기사님 확인함’, ‘전달 실패 또는 만료’입니다. 서버가 요청을 받았다는 사실만으로 기사님 확인 완료를 표시하지 않습니다. 통신 단절 시 전달 대기임을 보여주고, 취소·완료되거나 유효시간이 지난 업무의 오래된 알림을 재생하지 않습니다.

## 실행 방식과 현장 설정

- 첫 버전은 웹앱/PWA입니다. 매장과 차량에 각각 실행 아이콘을 두고 역할에 맞는 화면으로 엽니다.
- 차량은 안드로이드 우선이며 기종은 아직 정하지 않았습니다. 데이터 연결, 충전 거치, 통화 방식은 실제 장비 선택 때 확인합니다.
- 충전 중 화면 유지 설정과 웹의 화면 유지 기능을 함께 검증합니다. 충전 중 화면 유지가 앱 자동 실행이나 전원이 꺼진 기기의 자동 부팅까지 뜻하지는 않습니다.
- ‘업무 시작’에서 소리 재생과 연결 상태를 확인합니다. 다른 앱에 다녀오거나 연결이 복구되면 서버 상태를 다시 동기화합니다.
- 연결이 끊기면 마지막 수신 자료임을 표시합니다. 로컬에서 눌렀으나 서버가 확인하지 않은 처리는 ‘전송 대기’로 구분합니다.
- 오래된 정보를 바탕으로 상태를 바꾸려 하면 최신 상태를 확인합니다. 새로 변경된 시간·장소를 조용히 덮어쓰지 않습니다.
- 실제 기기에서 화면 유지·알림이 요구 수준에 못 미치면 차량에 한해 안드로이드 앱 기능을 추가합니다.

기술 확인 근거: Android는 [전원 연결 중 화면 유지 설정](https://developer.android.com/studio/debug/dev-options)을 제공하고, 웹 화면 유지에는 [활성 화면 등 조건](https://developer.mozilla.org/en-US/docs/Web/API/Screen_Wake_Lock_API)이 있습니다. 브라우저의 소리 재생에는 [사용자 조작 등 정책](https://developer.chrome.com/blog/autoplay)이 적용됩니다. 확인일은 2026-09-07이며 실제 기종의 동작은 현장 시험으로 확인합니다.
