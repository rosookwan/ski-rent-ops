# 업무 UI 1.0 적용과 검증

작성일: 2026-09-08

[UI 개선 4 검토](19-ui-v4-review.md)의 수량·부분 처리·가독성 문제를 수정하고 새 업무 모듈을 기존 앱에 연결했다. 원본 Downloads 시안은 수정하지 않았다.

## 적용 내용

| 화면 | 연결한 업무 |
|---|---|
| 리프트권 예약 | 대표자 한 번 입력, 여러 날짜·3/4/6시간권 수량, 오늘·내일 합계, 이용일/발권일 조회, 일부 발권·기존 보유권 배정, 예약 변경·취소·복원 |

| 방문 순서 | 위/아래/맨 위/시간순 복원, 변경 전후 순위와 시각 안내, 기존 우선 확인 유지, 선택한 고객 유지 |

차량 적재는 실제 지급과 구분한다. 매장 인계는 새로운 고객 회수로 세지 않는다. 예약 취소·복원은 실물 재고를 만들거나 옛 배정을 되살리지 않는다. 리프트권 회수 기준 금액과 발권처 실제 환불액은 별도다.

## 직접 확인한 화면과 흐름

- 차량 **1024×600**: 우선 확인·순서 변경 두 배너가 함께 떠 있어도 고객·장소·스키/의류/헬멧 세 품목과 72px 처리 버튼이 모두 보인다. 상세 본문의 clientHeight와 scrollHeight가 모두 112px로 품목 영역에 추가 스크롤이 없다. 단순/자세히 토글은 없앴다.
- 매장 **1024×768·1366×768**: 본문 16~18px를 유지했다. 접수 수량 버튼은 48×48px이고 상품·합계·저장 버튼이 보인다. 입력폼 목록에서 팀 행이 중첩되어 연락처·장소가 여러 줄로 밀리던 구조를 고쳐 팀마다 독립된 한 행으로 표시한다. 긴 21명 명단 앞에 인쇄·준비·지급 버튼을 배치했다.
- 고객 **360px 폭**: 새 폼 대표자 이름·연락처가 이어지고 167cm·245mm가 다른 옵션 선택·제출 후에도 유지된다. 고객 입력 본문 clientWidth/scrollWidth는 모두 321px로 가로 잘림이 없었다.
- 오전 고객의 스키 2대·6시간권 2매 중 스키 1대와 권 2매를 수거했다. 차량 스키는 1→2대, 6시간권은 3→5매로 바뀌고 미수거 스키 1대가 남았다. 오후 고객에게 권 2매만 전달하자 6시간권만 5→3매로 줄었다.
- 환불 예정 4시간권 2매 중 1매만 환불 완료했다. 차량 4시간권은 5→4매로 바뀌고 남은 1매의 업무와 환불 결과 버튼이 유지됐다.
- 카운터에서 4시간권 2매를 추가 적재하여 차량 합계 5→7매를 확인했다. 수량 선택 전에 예비용/고객 전달용을 고를 수 있고, 환불 배정권은 기존 환불 용도를 유지한다.
- 새 예약 고객의 물품을 모두 수거해도 반납 목록에서 사라지지 않고, 매장 확인 대기 필터에 차량 보관 4개로 남는 것을 확인했다.
- 매장 맨 위 이동 후 차량에서 이전/새 순위 안내를 확인했다. 순서 확인을 눌러도 기존 우선 확인 요청은 미확인으로 남고 선택 고객도 유지됐다.
- 이름·연락처 한 번으로 내일 3시간권 4매·4시간권 3매와 모레 6시간권 2매를 등록했다. 내일 합계에 반영되고 일부 발권 2매만 확보량에 추가됐다.
- 고객 1/2명 부분 제출 → 매장 확정 → 준비 → 실제 지급 흐름을 클릭했다. 표에 입력한 키·발 값이 유지되고 실제 지급 인원만 완료됐다.
- A4 **21명 = 20명 + 1명, 2쪽**을 실제 Chrome 인쇄 창에서 확인했다. 인쇄 취소 후에도 ‘실제 출력 확인 필요’가 유지됐으며 준비·지급 상태가 바뀌지 않았다. 실물 종이는 출력하지 않았다.
- 스티커 미리보기의 대표자·연락처·품목 합계·배달 장소를 확인했다. 화면에서도 80×50mm 용지 형태로 표시하며 내부 차량 ID는 출력에서 제외했다. 실제 라벨 프린터 하드웨어는 검증하지 않았다.

자동 검증: `npm test` **66개 통과**, `npm run check` **JavaScript 36개와 기존 인라인 스크립트 검사·정적 빌드 통과**. 도메인·API·SQLite·알림·기존 자료 이관과 새 UI 데모 서비스가 대상이다. 이전 화면 전용 브라우저 스크립트는 최신 UI 통과 근거로 사용하지 않는다.

## 공개 체험과 운영 기능의 경계

GitHub Pages 배포 대상은 **같은 페이지 메모리를 공유하는 체험 UI**다. 새로고침하면 초기화되며 매장·차량의 서로 다른 기기에서는 공유되지 않는다. 샘플은 오늘 오전 9시 기준으로 구성해 권 재전달을 체험할 수 있다.

SQLite API와 문자·인쇄 어댑터 인터페이스는 저장소에 포함했다. 운영 API 서버, 실제 로그인·영구 고객 저장·기기 간 동기화·문자 업체·리조트 시스템·라벨 프린터 연결은 별도 운영 전환이 필요하다. 인원별 준비 장비를 적재한 배달의 일반 업무 취소는 막아 놓았으며, 실제 운영에서 배달 취소·회차가 필요하면 장비 인계와 인원 배정을 함께 해제하는 전용 처리가 필요하다.

빌드 결과는 `dist/index.html`과 독립 업무 번들 `dist/ski-workflows.js`이며 GitHub Actions 검증 후 Pages로 배포한다. [공개 체험](https://rosookwan.github.io/ski-rent-ops/)

## 후속 수정: 차량 우선 확인 종과 배너 범위

사용자 피드백에 따라 배너를 오른쪽 업무 상세 영역에 맞췄다. 1024×600에서 왼쪽 목록 끝은 x=296, 알림과 상세의 왼쪽은 x=310으로 서로 침범하지 않는다. 두 알림 모두 높이 64px이며 글자 잘림 없이 표시된다. 품목 하단 y=466은 처리 영역 상단 y=496 위에 위치한다.

흔들리는 종·전체 배너 확인을 복구하고 상단 소리 버튼을 추가했다. 4초 알림음과 반복 설정은 유지하며 안내 알림이 남은 경우에도 마지막 주의 요청 확인 즉시 중지한다. 추가 런타임 검사 3개를 포함해 `npm test` 69개가 통과했다. [알림 복구 상세](17-notification-release.md#업무-ui-연결-후-차량-알림-복구)

## 후속 수정: 태블릿 주소창을 고려한 차량 상단

실제 태블릿 사진에서 날짜가 다음 줄로 밀리고 별도 요청 띠까지 겹쳐 물품 영역이 가려지는 문제를 확인했다. `방문 업무 · 적재 내역 · 처리 내역 → 우선 확인/순서 변경 → 알림 소리`를 같은 도구줄에 놓고, 날짜 세 컨트롤은 기존 최상단의 빈 왼쪽 공간으로 옮겼다. 날짜 입력은 기기의 기본 날짜 선택기를 유지하되 너비를 188px로 고정하고 묶음 줄바꿈을 막았다. 방문·적재·처리 탭 모두 같은 위치에서 알림과 날짜를 사용한다.

알림은 두 건과 `외 N건`을 한 줄로 보여준다. 요청 전체를 누르면 해당 알림만 확인하며, 순서 변경은 고객/업무명과 `3→1번째`를 분리해 순위가 잘리지 않게 했다. 환불 순서 알림은 `2매 환불`처럼 간결하게 표시한다. 긴 이름과 전체 요청 내용·시각은 알림함에서 확인할 수 있다. 기존 종 애니메이션·소리 제어·업무 선택·실물 수량 처리는 유지했다.

Chrome에서 뷰포트를 960×480, 1024×480, 1138×510, 1280×520, 1280×600, 1366×768로 바꾸어 직접 확인했다. 우선 요청 3건과 순서 변경 1건이 있어도 날짜 줄은 48px, 업무 도구줄은 약 59px로 유지됐다. 960×480 및 1024×480에서 세 품목 본문의 clientHeight/scrollHeight는 모두 85px로 추가 스크롤이 없으며, 물품 하단 y=374는 처리 영역 상단 y=382보다 위에 있다. 72px 버튼과 처리 영역 하단 y=471이 화면 안에 들어온다. 모든 측정 크기에서 페이지 가로 넘침이 없다.

날짜 직접 선택·오늘/내일 조회, 적재/처리 탭 이동, 추가 알림함 열기, 순서만 확인한 뒤 우선 요청·선택 고객·보관 수량 유지, 소리 켜기/끄기, 수량 입력창 연결을 확인했다. 브라우저 실행 오류는 0건이다. Samsung Internet 실기기의 기본 날짜 팝업과 실제 스피커 청음은 이번 데스크톱 검증에 포함하지 않는다.

## 후속 수정: 보관 수량 팝업과 자동 소리 준비

차량의 상시 보관 띠를 없애고 날짜 옆에 `장비 2개`·`리프트권 10매` 같은 두 버튼으로 합계를 표시했다. 장비에는 스키·보드·의류·헬멧을 포함하고 팝업에는 각 품목의 원래 단위를 표시한다. 리프트권 팝업은 권종별 매수를 표시한다. 현재 차량에 실제로 있는 수량을 사용하므로 조회 날짜나 탭을 바꿔도 합계는 유지된다. 매장의 적재·인계 화면에 있는 보관 표는 유지했다.

팝업은 상단 y=64에서 열리고, 장비와 리프트권을 안에서 전환할 수 있다. 960×440에서도 팝업 하단은 y=406, 본문 clientHeight/scrollHeight는 모두 200px여서 기본 품목을 한 번에 볼 수 있다. 닫기 후 원래 버튼으로 포커스가 돌아오고 선택 업무는 그대로다.

우선 요청·순서 변경의 확인 표시는 밑줄을 없애고 48px 높이의 버튼 형태로 바꿨다. 제목 18px·대상 16px·확인 16px이며 64px 알림의 세로 중앙과 정확히 일치한다. 두 알림이 함께 있어도 중앙 오차는 0px이다. 960×480의 세 품목 본문은 85px에서 160px로 75px 늘었다. 960×440·960×480·1024×480·1138×510·1280×600·1366×768에서 가로 넘침과 수량 가림 없이 72px 처리 버튼까지 보이는 것을 확인했다.

실제 화면에서 스키 1대와 6시간권 2매 수거 후 장비 합계 2→3개, 권 합계 10→12매를 확인했다. 권 2매 재전달 후 12→10매, 4시간권 1매 환불 후 10→9매와 팝업의 4시간권 5→4매를 확인했다. 적재·처리 탭, 날짜 변경에서도 동일한 보관 수량을 유지한다.

차량의 상단 소리 토글을 제거하고, 차량 소리 기본값을 켬으로 변경했다. 브라우저가 허용하는 차량 진입 등의 실제 클릭에서 오디오를 준비하고 주의 요청이 있을 때만 울린다. 시험 소리를 자동으로 재생하지 않는다. 기존 알림 설정과 명시적으로 저장한 설정은 유지한다. 자동 준비·재시도·일반 안내만 있을 때 무음·개별 확인 후 중지 등을 포함한 `npm test` 72개와 정적 검사를 통과했다. Chrome 알림함에서 별도 소리 버튼 조작 없이 `켜짐` 상태를 확인했으며 실제 태블릿 청음 시험과는 구분한다.
