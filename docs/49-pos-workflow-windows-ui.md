# 49. 발권·마감·사이즈 입력·알림 A3 화면 정리

2026-09-21. `docs/46` A3. 사용자 요청("다음 진행")에 따라 P27·P28·P14·P31·P32 시안과 `docs/35`의 해당 업무를 대조하고 구현했다. 기존 Pretendard와 공용 글자 크기를 유지하고 새 글꼴·글자 축소·강제 줄바꿈을 넣지 않았다.

## 변경 사항

- 발권 창은 대표자·매수 제목, 발권·배정된 수량, 추가 발권 −/+, 접수 매수·미수 요약으로 정리했다. 발권처 입력을 유지하고 권종·유효시간·재사용 조건은 `권 조건 확인`에서 연다. `예비권 확인`은 기존 재고 절차로 이어진다.
- 마감 확정은 정산 화면 위에서 현금 대조 → 미처리 이월 → 확정의 세 단계로 진행한다. 실제 현금·차이·사유를 한 줄씩 보고, 인계 사유는 버튼으로 고른다. 시작 현금과 거래처 확인을 왕복해도 입력값을 보존한다.
- `준비·지급 → 사이즈 입력 현황`에서 내일까지 수령할 미지급 장비가 있는 팀을 카드로 본다(기한 지난 미지급 포함). 고객 제출 대기·매장 확인 필요·규격 적용 완료를 구분하고, 집계는 준비 대상 일행에게 적용한 발·의류 규격만 센다. 실제 장비 규격과는 별도다.
- 대표자만 적은 접수는 개인별 입력을 요구하지 않는다. `준비표·스티커`로 이어서 준비에서 실물 규격을 확인한다. 일행이 있는 접수의 대상·차수 선택은 별도 창으로 열고, 입력 요청 내역은 화면 높이에 따라 쪽을 나눈다.
- 사이즈 요청 창은 대상·차수·받는 번호·실제 발송 기록·안내 문구를 보여 준다. 선택한 일행의 링크만 준비하며 자동 발송하지 않는다. 기존 고객 입력 원본·접수 적용·준비표·스티커 절차는 유지했다.
- 알림 창은 미확인/전체 선택 상태와 미확인 수를 표시한다. 상세 열기, 실제 확인 처리, 기기 소리, 새로고침의 기존 동작을 유지한다.

## 시안과의 대응

| 시안 | 실제 화면·코드 | 유지한 차이와 이유 |
|---|---|---|
| P27 발권 | `pos-ticket-form.js`의 `open`·`render`, `pos-fulfillment.js`의 발권 입구 | 이미 발권·배정한 권은 읽기 전용 수량이다. 예비권은 실제 권을 고르는 기존 흐름에서 배정한다. `실제 발권·배정 기록` 뒤에도 고객에게 지급하는 확인은 별도다. 미수는 리프트권만의 금액처럼 보이지 않게 `접수 전체 미수`로 표시한다. |
| P28 마감 확정 | `pos-finance.js`의 `showClosing`·`captureClosing` | 시안의 `차이 기록` 대신 기존 필수 차이 사유를 바로 입력한다. 팀별 인계 담당자·다음 확인일·사유를 유지하고, 기존 `다음`·`이전`·`오늘 마감 확정` 문구를 쓴다. |
| P14 사이즈 입력 현황 | `pos-size-status.js`, `pos-preinput.js`의 `render`·`formsPanel` | 현재 접수의 미지급 품목·실제 일행·적용한 규격을 쓴다. 대표자 접수에 가짜 일행을 만들지 않는다. 준비표 입구는 팀 카드에 두고 원본 출력 절차로 연결한다. |
| P31 사이즈 요청 | `pos-preinput.js`의 `requestModal`·`requestPeople` | 문자 자동 발송을 추가하지 않는다. 준비·발송 기록을 구분하며 버튼은 기존 `N명 입력 링크 준비`다. 일행·차수 선택은 본문 높이를 지키기 위해 별도 창으로 연다. |
| P32 업무 알림 | `pos-notifications.js`의 `open` | 알림 수와 내용은 실제 기록이다. 열람만으로 확인 완료 처리하지 않으며, 높이에 따라 기존 2/3행 쪽 나눔을 쓴다. |

A3에서 확인한 업무 흐름:

1. 발권 수량 변경·권 조건 왕복 때 발권처와 선택값 보존. 취소 후 지급 창 복귀와 기록 보존. 발권·배정 후에도 고객 지급은 미처리 상태.
2. 권 조건 창을 왕복해도 오래된 자료로 발권하지 않음.
3. 현금 차이 사유·인계 담당자 필수, 마감 취소 시 기록 보존, 거래처 창 왕복 입력 보존, 오래된 마감 거부와 정상 확정.
4. 대표자만 있는 접수는 개인별 입력 없이 준비표로 이동.
5. 선택한 일행의 링크만 준비하고 자동 발송하지 않음.
6. 알림을 열어 보는 것만으로 확인 처리하지 않음.

기존 사전입력 검사에는 **제출만 한 규격은 집계하지 않고, 매장 적용 후에만 집계하는 확인**을 추가했다. [사전입력 10개 검사](pos-ui-a3/preinput-checks.json) · [실제 적용 규격 집계](pos-ui-a3/applied-size-summary-1024x600.png).

```bash
npm run build
npm run dev
npm run test:pos:operating
npm run test:pos:fulfillment
npm run test:pos:tickets
npm run test:pos:management
npm run test:pos:preinput
npm run test:pos:keypad
SKI_SCREENS_OUT=work/pos-ui-a3-validation/captures npm run pos:screens
SKI_DRIVER_OUT=work/pos-ui-a3-validation/captures npm run pos:screens:driver
npm run pos:screens:fulfillment
npm run pos:screens:adjustments
npm run pos:screens:windows
SKI_SCREENS_OUT=work/pos-ui-a3-validation/captures SKI_RULES_TABLE=0 node scripts/check-pos-ui-rules.cjs
npm run check
npm run test:workflows:unit
npm run test:returns
npm run test:notifications
npm run test:pwa
```

`pos:screens:windows`는 `work/pos-ui-a3`에 실제 화면 48장, 비교 그림 5장과 측정 기록을 만든다. 출력 위치는 `SKI_WINDOWS_SCREENS_OUT`으로 바꾼다. `SKI_WINDOWS_QUICK=1`은 개발 중 1024×600만 보는 옵션이며 완료 검증에는 사용하지 않는다. 기존 포스·기사·A1·A2 PNG는 회귀 검사만 하고 다시 커밋하지 않았다.
