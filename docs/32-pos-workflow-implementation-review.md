# POS 업무 개선 구현 검수표

검토일: 2026-09-13 · 기준: [개발계획 R01–R09 / A01–A28](30-pos-workflow-development-plan.md), [M1–M8 마일스톤](31-pos-workflow-milestones.md)

## 검수 범위와 판정 방법

현재 확인 대상은 **로컬 운영 API + SQLite, 해당 API에 연결하는 `/pos`·`/guest` 화면, 별도의 정적 메모리 체험 화면**이다. 운영용 POS는 인증된 매장·기사 범위의 공통 명령을 사용한다. 정적 체험 화면의 저장은 운영 데이터 영속성의 증거가 아니다.

이 표의 `로컬 근거 있음`은 구현 소스와 해당 도메인·브라우저 검수 시나리오를 확인했다는 뜻이다. 검증한 업무별 소스와 재현 경로를 연결하고, 문서 끝에 최종 통합 실행 수치를 기록한다. 로컬 테스트 합격은 실제 운영 배포 인수를 대신하지 않는다. `부분 확인`은 구현 또는 인수 조건 일부가 남은 항목이며, `현장 대기`는 실제 환경 확인이 필요한 항목이다.

**실물 POS, 실제 차량 단말, 실물 프린터 출력, 실제 SMS 전달, 실제 카드 승인·취소, 운영 배포, 초보 직원 사용성 시험은 이 문서에서 통과 처리하지 않는다.** GitHub 마일스톤은 구현·로컬 검증 결과를 반영해 재조회했다. 전체 인수 조건이 남아 Open 상태를 유지한다.

결과 JSON과 화면은 개발 작업 중 생성된 로컬 자료다. 최종 인수 시 스크립트를 다시 실행해 최종 코드와 같은 결과인지 확인한다. 같은 폴더에 남은 과거 `failure.json`은 최근 성공 결과와 생성 시각을 대조하며, 파일 존재만으로 현재 실패나 성공을 판단하지 않는다.

## 운영 전에 남겨 둘 명시적 경계

1. **저장 환경**: 정적 Pages 체험과 로컬 API 운영 화면을 구분한다. API 로컬 실행·SQLite 테스트는 운영 서버 배포와 백업 운영의 증거가 아니다.
2. **인증**: 운영 `/pos`는 서버의 인증키/매장/기사 범위를 사용하며 새로고침 시 다시 인증한다. 직원 목록의 역할 선택만으로 서버 로그인 계정을 발급하거나 권한을 바꾸지 않는다.
3. **금전 정책**: 조기반납·연체·파손/분실 금액은 직원이 확인한 청구 조정/실제 환불로 기록한다. 보증금·거래처 미배분 금액을 자동 상계하지 않는다. 카드·이체 수단 선택은 외부 실제 처리의 기록이다.
4. **거래처 마감**: 명시 약정잔액과 미배분 돈, 빌린/빌려준 실물 의무를 각각 보존한다. 약정 미등록은 미지급 0원 확정과 다르다. 고객 인계 내용을 거래처 확인 때문에 재입력시키지 않는다.
5. **영업일**: KST 날짜 기반 처리와 보존 마감은 구현돼 있으나 야간 컷오프는 보관된 미확정 정책이며 자동 적용하지 않는다.
6. **사전입력·출력**: 준비한 링크, 고객의 실제 API 제출, 직원 반영, 출력 원본, 브라우저 미리보기, 실제 발송·인쇄 결과를 구분한다. 브라우저 인쇄 요청만으로 실물 출력 성공을 기록하지 않는다.
7. **결과 불명 재확인**: 전송 전에 AES-GCM으로 요청을 보관하며 인증키 원문·고객 평문을 저장하지 않는다. 같은 서버·직원 키로 재로그인하면 같은 요청을 복구하고 성공 뒤 제거한다. `smoke-pos-operating.cjs`의 실제 로컬 API 결제 응답 유실→새로고침→재로그인→동일 요청 재확인 검수에서 중복 수납 없이 원기록을 복구했다. 실제 매장 망 장애 인수는 별도다.
8. **현장 사용성**: 계획의 초보자 3명, 10초 이내 메뉴 탐색, 도움 없는 위치 탐색 80% 목표, 잘못된 수량/고객 확정 0건은 관찰 기록이 없어 달성 판정하지 않는다.

## 최종 검수 실행 연결

아래는 검수 재현 경로이며 이 문서에 고정한 합격 개수가 아니다.

- `npm test`: 도메인·서비스·HTTP·SQLite·알림·이관·복구 회귀.
- `node scripts/smoke-pos-operating.cjs`: 실제 로컬 운영 `/pos`와 HTTP/SQLite, 접수·추가·수납·반납·권한·재시작.
- `node scripts/smoke-pos-fulfillment.cjs`: 활성 지급·반납·교환·정정·분실·여러 차량·대량 목록.
- `node scripts/smoke-pos-preinput.cjs`: 운영 고객 입력·부분 응답·추가 인원·준비표/스티커·이력.
- `node scripts/smoke-pos-management.cjs`: 재고·거래처·고객·설정·명시 상계·보존 마감 거래처 목록.
- `node scripts/capture-pos-release.cjs`: 필수 세 화면 크기와 단체 접수의 캡처·geometry 결과.

추가로 실제 운영 환경에서 인수해야 할 항목은 자동 스크립트 합격으로 대체하지 않는다. 운영 호스트·실물 단말·발송/결제/출력 제공자·정책이 확정되면 각 항목의 실행일·담당자·결과 증빙을 이 표에 연결한다.
