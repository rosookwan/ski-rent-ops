## 화면 기준

- POS는 1024×768과 1366×768에서 확인한다. 넓은 표는 표 안에서 움직이고, 접수 합계·저장·견적 버튼은 하단에 남는다.
- 차량은 CSS 뷰포트 1024×520, 1024×600, 1024×650, 1280×600, 1024×800을 사용한다. 1024×520은 브라우저와 작업 표시줄이 보이는 탭 S6 사진을 보수적으로 재현한 조건이며, 기기의 실측 CSS 해상도를 뜻하지 않는다.
- 차량의 장소·예정 시간·고객·연락처·품목 수량은 간단/상세 모두 내부 스크롤 없이 표시하고, 현재 작업 버튼은 72px 이상이다. 낮은 화면의 다음 일정은 가로 카드로 압축한다. 긴 작업 팝업은 내부 스크롤을 허용한다.
- 고객 입력과 안내는 390px 최대 폭으로 분리했다. 360px에서도 입력 단계 이동 버튼과 안내 상단 메뉴가 유지된다. PC/POS 해상도 규칙을 적용하지 않는다.
- 실제 탭 S6에서의 터치·브라우저 설정·앱 설치 모드는 별도 현장 확인 대상이다. 이번 릴리스에서 PWA/네이티브 앱으로 전환하지 않았다.

### 오늘 현황 스크롤 보정

2026-09-08 Chrome의 콘텐츠 영역 907×710에서 업무 카드 폭은 약 443px인데 행의 최소 폭이 716px로 고정되어 가로 스크롤과 큰 열 간격이 발생했다. 차량 다음 일정은 내용이 가용 높이를 19px 초과했다.

업무 행의 열 폭을 유동적으로 바꾸고, 좁은 POS에서 차량 카드 폭을 300px로 조정했다. 낮은 창에서는 업무 행·헤더·푸터의 여백을 줄이고 차량 수량을 한 줄로 배치한다. 높이 700px 이하에서는 제목 옆에 날짜를 놓고 요약·바로가기 카드의 여백을 추가로 줄인다. 업무 내용·상태·차량 정보·버튼은 유지한다.

907×710, 907×648, 1024×648, 1366×648과 기존 POS 두 해상도에서 샘플 업무 4건 및 차량 다음 일정이 가로·세로 스크롤 없이 보이는지 검사한다. 카드의 스크롤 크기뿐 아니라 각 행·셀과 차량 버튼이 표시 영역 안에 있는지도 검증한다. 업무가 늘어나거나 내용이 길어져 실제 공간이 부족한 경우를 위한 스크롤 기능은 유지한다.

### 접수 상품과 타임 기준 개선

- 기간과 선택 일자는 요약 줄 전체를 눌러 변경한다. 일수를 선택하면 기간 설정 창이 바로 닫히며, 시작·종료일을 직접 입력할 때는 ‘기간 적용’으로 마친다. 날짜별 상품 선택은 선택 후 접힌다. 잘못된 기간은 오류를 표시하고 적용하지 못하게 한다.
- 좁은 창에서 스키·보드 첫 행의 이름·가격·수량 버튼이 모두 보이도록 상품 영역을 확보했다. 선택한 상품에는 옅은 주황색 배경을 적용했다.
- 실제 장비는 평소 한 줄로 접어 둔다. 일자별 수량 또는 지급·마지막 수거 수량이 다르면 내역 맨 위로 이동하고 펼쳐서 보여 준다. 수량 변경 후 확인 필요 상태도 유지한다.
- 총 금액 할인과 장비당 할인, 설정의 버튼 이름을 ‘할인 5,000원’·‘할인 10,000원’으로 맞췄다. 금액 계산과 취소 방식은 유지한다.
- 접수의 ‘타임 기준’은 매장 설정의 ‘운영·직원’으로 연결한다. 타임 이름·시간·마지막 이용일/다음 날 기준을 추가·수정·삭제할 수 있다. 빈 이름·중복 이름·잘못된 시간은 반영하지 않는다.
- 설정은 작성 중인 접수에 적용한다. 이미 저장한 접수는 유지하며, 선택 중인 타임을 삭제하면 그 날짜·시간을 직접 입력 값으로 보존한다. 타임이 없어도 직접 시간 선택을 사용할 수 있다.
- 일별 수량이 다른 접수에서 실제 수량 확인을 마치면 같은 반납 엔진의 신규 접수 저장으로 이어지도록 연결했다. 요금 합산 수량과 실제 지급 수량을 구분하며 중복 접수하지 않는다.
- 설정은 현재 브라우저의 메모리 체험에 한정된다. 새로고침하면 초기화되며 다른 기기와 동기화하지 않는다.

### 접수 1b안: 요약 줄 + 설정 창

3차 참고 파일 `03 새 대여 접수 - 좁은 화면 안.dc.html`의 **1b** 배치를 적용했다. 이용 기간과 수령·반납을 상품 영역 위의 요약 두 줄로 옮기고, 아래에 있던 별도 수령·반납 카드를 없앴다.

- 요약 줄은 글자·여백·화살표 모두 눌러 설정 창을 연다. 설정 창의 제목과 완료 버튼은 고정되고, 긴 입력 내용만 안에서 스크롤한다. 닫거나 Escape를 누르면 입력한 내용은 유지하며 포커스가 요약 줄로 돌아온다.
- 장비는 기존 7개 품목을 3열로 배치한다. ‘이 수량을 모든 이용일에 적용’은 상품 칸을 차지하지 않는 별도 하단 버튼이다. 높이 740px 이하에서는 장비/리프트권 탭과 선택 일자를 한 줄로 묶어 세로 공간을 확보한다.
- 907×648, 907×710, 1024×768, 1366×768에서 기본 반납 일정과 3일 대여의 장비 7종 및 수량 버튼이 모두 보이는지 확인한다. 상품명은 18px 이상, 수량 버튼은 44px 이상이다. 품목 수나 요약 문구가 늘어 공간을 넘으면 상품 목록 안에서 스크롤할 수 있다.
- 수령·반납 요약에는 실제 선택된 방법·장소·날짜·타임·시간을 표시한다. 의류·리프트권의 방법이나 날짜가 다르면 별도로 강조한다. 설정 창에서 직접 시간과 품목별 반납을 바꿀 수 있고, ‘타임 기준’은 기존 매장 설정으로 이어진다.
- 기간별 수량, 리프트권, 복사, 할인, 견적, 실제 수량 확인과 신규 접수 저장을 유지했다. 6일 이상 대여의 날짜 선택도 사용할 수 있다.

## 반납 데이터 연결

`src/returns/domain.js`의 수량·정정 규칙과 API 계약을 유지하고, `design/app/returns.js`에서 화면을 연결했다. `seedOperations`가 기존 접수의 명시된 실제 장비 수량과 리프트권 배열을 반납 엔진에 넣는다. 날짜 수나 품목 표시 문자열에서 실제 수량을 추정하지 않는다.

- 기존 화면 사이의 샘플 차이는 매장 원장에 맞췄다. 김영희는 스키 2·의류 2·헬멧 1, 박준호는 스키 2·보드 1과 야간권 1, 이수진은 보드 2·의류 2다.
- 새 접수는 `create`만 수행한다. 매장에서 실제 전달할 때 `issue`로 확인해야 고객 보유/미반납 수량에 포함된다. 새로 저장하는 접수의 의류와 리프트권은 매장 직접반납이 기본이며 날짜·방법을 따로 변경할 수 있다.
- 기존의 ‘마지막 수거 수량’ 입력이 실제 지급량과 다르면 전체 지급량을 회수 대상으로 보존한다. 먼저 돌려받은 물품을 반납 확인에서 기록하도록 안내한다. 다일 요금과 실제 수량 계산은 유지했다.
- 차량 업무는 접수 ID와 품목별 날짜·시간·장소로 묶는다. `prepareVehicleReturn`에 현재 방문의 대상만 전달하므로 다른 날짜 물품이 전체 수거에 들어가지 않는다. 차량 카드의 리프트권은 매수 합계로 표시하고, 명령에는 개별 권종 ID를 유지한다.
- 차량 수거는 차량 보관으로 기록한다. `confirmVehicle`은 선택한 차량 인수 기록의 미확인 수량만 매장으로 옮긴다. 차량 인수분을 직접반납으로 중복 처리하지 않는다.
- 부분 수거에서 못 받은 의류·리프트권은 예정일을 유지한 채 직접반납으로 바뀐다. 별도 사유 입력을 추가하지 않았다.
- 정정은 선택한 기록에서 실제 받은 새 총수량으로 적용한다. 취소는 해당 기록의 수량을 0으로 되돌린다. 이후 반납 계획은 유지한다. 이미 매장이 확인한 수거 기록은 매장 확인을 먼저 정정해야 차량이 취소할 수 있다.
- 요청 ID와 버전을 명령에 고정하고, 버전 충돌이면 최신 내용을 보여준 뒤 다시 확인하도록 한다. 자동 재실행하지 않는다.
- 리프트권 탭의 ‘오늘 매장 확인’과 기준 금액은 직접반납/매장 인계 기록을 합산한다. 차량 수거 단계에서는 이 금액이 늘지 않는다. 기존 API의 `recoveredQuantity`/`recoveryValueWon` 의미는 바꾸지 않았다.
- ‘현재 미반납’은 차량 보관을 포함한 현재 잔량이다. 과거 날짜의 잔량으로 표시하지 않는다. 정정은 원래 확인일의 집계에 반영하며 이 금액은 고객 환불액이나 현금 수입이 아니다.

## 운영 연결 범위

GitHub Pages는 한 브라우저의 메모리 체험이다. 새로고침하면 접수·반납 변경, 반납 타임 설정과 로그인이 초기화된다. 전화·문자, 실제 결제·환불, 발권, 고객 영구 저장, 서버에 설정 저장, 기기 간 공유는 연결하지 않았다. 별도의 SQLite API 서버나 인증 설정을 배포·변경하지 않았다.

기존 화면의 계약·결제·재고·준비 상태 중 미리보기로 제공하던 기능은 유지했다. 반납 수량 변화가 실제 재고 원장이나 회계 장부를 수정하는 운영 서비스로 확장된 것은 아니다.
