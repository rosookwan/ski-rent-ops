# 시험 시나리오와 결정 기록

문서 작성일: 2026-09-07

아래 항목은 앞으로 구현한 프로그램을 시험할 기준입니다. 문서·가상 계산 예시·인터랙티브 시안이 준비되어 있으며, 시안의 브라우저 검증 범위는 [디자인 참고 자료와 시안](07-design-reference-and-preview.md)에 기록합니다. 실제 서버·기기 간 통신·차량 현장 시험을 통과했다는 의미는 아닙니다.

| D22 | 타 스키샵 리프트권 매입·판매와 장비 빌려오기·빌려주기를 별도 페이지에서 관리 | 사용자 요청 · 화면 설계 |
| D23 | 거래처 받을 돈/줄 돈과 물품 반환 상태를 구분, 상계는 명시적 정산 기록 | 설계 권고 |
| D24 | 렌탈현황, 장비·가격·권종 설정, 사전 입력폼 설정·발송·준비표 화면 | 사용자 요청 · 화면 설계 |
| D25 | 매장 고정 안내 페이지를 QR로 인쇄, 내용 수정 시 주소 유지 | 사용자 질문에 대한 설계 권고 |

0.8의 신규 화면과 구현 후 확인할 S01~S15 사례는 [전체 화면 구성과 확장 계획](08-screen-map-and-expansion-plan.md)에 정리합니다. 신규 페이지의 구현·운영 검증 완료를 의미하지 않습니다.

## 운영 보드 시험

| 번호 | 시나리오 | 기대 결과 |
|---|---|---|
| O01 | 카운터에서 고객과 배달·수거 접수 | 차량에 동일 정보 표시, 입력 중복 없음 |
| O02 | 배달 + 직접 반납 접수 | 차량에는 배달 업무, 매장에는 직접 반납 예정 표시 |
| O03 | 매장 수령 + 차량 수거 접수 | 배달 업무가 생기지 않고 수거 업무만 생성 |
| O04 | 시간순·장소별 보기 전환 | 같은 장소로 묶이며 각 그룹 안에서는 시간순 |
| O05 | 카운터가 시간·장소 변경 | 차량에 변경 표시, 오래된 내용과 구분 |
| O06 | 스키 2대 중 1대만 수거 | 일부 수거, 잔여 스키 1대 표시 |
| O07 | 수거 완료 후 차량에 물품 보관 | 매장 확인 대기, 최종 반납 완료가 되지 않음 |
| O08 | 매장 최종 수량 확인 | 해당 수량만 확인, 모두 확인되면 반납 완료 |
| O09 | 출발 문자 버튼 연속 클릭 | 한 번만 발송, 발송 문구·시각·결과 확인 |
| O10 | 통신 끊김 중 출발 문자 클릭 후 늦게 복구 | 오래된 도착 안내가 자동 발송되지 않음 |
| O11 | 카운터 기사님 알림 | 해당 차량 소리·강조, 실제 기사 확인 시각이 카운터에 표시 |
| O12 | 차량 미연결·완료된 업무에 알림 | 전달 대기·실패·만료를 사실대로 표시, 오래된 알림 재생 방지 |
| O13 | 완료 취소·중복 요청·동시 수정 | 변경 이력 보존, 중복 처리 없음, 충돌 시 최신 정보 확인 |
| O14 | 직접 반납 완료 후 감사 문자 선택 | 매장 역할로 최종 확인, 문자 발송 상태는 별도 기록 |
| O15 | 오후·야간 타임 또는 직접 날짜·시간 선택 | 선택한 표현과 실제 예정 일시를 매장·차량·견적에 동일하게 표시 |
| O16 | 12/20 시작 1·2·3일 대여에 익일 오전 선택 | 각각 12/21·22·23 반납. 청구 일수·물품 수량은 유지 |
| O17 | 반납 타임 설정을 변경 | 기존 접수의 날짜·시간 유지, 작성 중·새 접수에 새 기준 적용 |
| O18 | 마지막 이용일보다 빠른 날짜·빈 시간 직접 입력 | 안내 후 저장 차단, 기존 업무는 유지 |
| O19 | 월·연도가 바뀌는 반납일 직접 지정 | 실제 해당 날짜의 목록에 표시, 날짜순 정렬 유지 |
| O20 | 직접 반납에 익일 오전 지정 | 매장 일정에 해당 날짜·타임 표시, 차량 수거 업무 생성 안 함 |
| O21 | 타임 기준을 넘김 | 기준 시간 경과 표시만으로 연체·독촉·요금을 자동 발생시키지 않음 |

## 실제 기기 시험

매장 PC 또는 터치모니터 1대와 실제 차량 태블릿 1대에서 진행합니다. 읽기·버튼 조작은 실제 사용자와 함께 정차 상태에서 확인합니다.

| 번호 | 시나리오 | 기대 결과 |
|---|---|---|
| H01 | 아이콘 실행·업무 시작 | 역할과 저장된 모드로 진입, 연결·소리 확인 |
| H02 | 실제 업무 시간 동안 충전 연결 | 화면이 유지되고 목록·알림이 계속 갱신 |
| H03 | 전화 화면에 다녀오기·PWA 다시 열기 | 최신 업무 재동기화, 완료 처리 중복 없음 |
| H04 | 차량 이동 구간의 연결 끊김·복구 | 마지막 수신 시각·미전송 처리 표시, 안전한 재동기화 |
| H05 | 음량·알림 설정·주변 소음 변화 | 실제 차량에서 소리가 들리고 미확인 강조가 남음 |
| H06 | 간단·자세한 모드 전환 | 글자·버튼이 읽히며 기능을 찾을 수 있고 선택을 기억 |
| H07 | 실제 전화 버튼 | 해당 태블릿·회선에서 통화 가능한지 확인. 미지원이면 연결 방식 결정 |
| H08 | 새 자료가 도착하는 중 버튼 누르기 | 카드 재정렬로 다른 고객을 잘못 처리하지 않음 |
| H09 | 매장 모니터와 차량 태블릿에서 같은 접수 열기 | 매장은 상품·고객·견적, 차량은 방문·연락·완료 중심. 스타일은 달라도 날짜·수량·상태 의미는 동일 |

## 가격·견적·마감 시험

| 번호 | 시나리오 | 기대 결과 |
|---|---|---|
| P01 | 스키 1대·의류 1개, 공통 2일, 단가 20,000원·10,000원 | 40,000원 + 20,000원 = 60,000원. 준비·반납 수량은 각각 1 |
| P02 | 같은 물품 공통 3일로 변경 | 60,000원 + 30,000원 = 90,000원, 실제 수량은 그대로 |
| P03 | 같은 상품 일부만 다른 기간 | 줄 또는 개별 기간으로 구분, 공통 기간 변경이 개별 지정값을 덮어쓰지 않음 |
| P04 | 2일 총액 36,000원인 장비 2개 | 총 72,000원. 이용일수를 다시 곱하지 않음 |
| P05 | 하루 20,000원, 다음 날 25,000원 | 별도 기간 요금이 없으면 합계 45,000원 |
| P06 | 자정을 넘는 같은 야간 이용 | 매장 이용일 규칙 적용, 자동으로 2일 청구하지 않음 |
| P07 | 3일 장비 + 첫날 후야·둘째 날 오후 리프트권 | 장비만 3일 계산, 리프트는 실제 날짜·권종·매수로 계산 |
| P08 | 단골과 제휴 관계가 동시에 존재 | 사용할 요금표 하나를 명확히 선택, 자동 중복 할인 없음 |
| P09 | 리프트 추가 할인 제외 설정 + 장비 전체 할인 | 리프트 금액 유지, 대상 장비에만 배분 |
| P10 | 정액 할인 배분과 원 단위 나머지 | 상품별 합계와 총액 일치, 음수 금액 없음 |
| P11 | 상품 가격 누락·의도적인 무료 제공 | 누락을 0원으로 계산하지 않으며 무료는 명시적 사유 기록 |
| P12 | 관리자 가격표 변경 | 과거 견적·확정 건 유지, 새 견적부터 변경 가격 사용 |
| P13 | 견적 여러 번 출력 후 대여 확정 버튼 재시도 | 출력만으로 거래·수납 없음, 확정 대여·차량 업무는 한 번만 생성 |
| P14 | 3일 거래 첫날 일부 결제·둘째 날 잔금·셋째 날 반납 | 확정액 한 번, 수납은 실제 날짜별, 반납으로 금액 중복 생성 없음 |
| P15 | 현금 보증금 수령·반환 | 대여 대금에서 제외, 현금 서랍 계산에는 실제 입출금 포함 |
| P16 | 100,000원 결제 후 10,000원 감액·환불 | 감액과 환불을 각각 기록, 최종 잔액 0원 |
| P17 | 후불 제휴업체가 여러 건 일괄 결제 | 거래별 배분, 미배분 금액 표시, 업체 미수 감소 |
| P18 | 이름 또는 연락처 일부로 고객 검색 | 이름·번호가 일치하는 매장 내 후보 표시, 동명이인 직접 선택 |
| P19 | 고객 선택 후 신규 접수 저장 | 고객 정보 연결, 장비별 실제 수량·이용 기간·금액을 이력에서 확인. 과거 요금 자동 적용 안 함 |
| P20 | 오늘 수령, 내일~모레 이용 날짜 선택 | 기본 2일 요금, 반납 타임은 모레 또는 그 익일 기준, 오늘 차량 수거로 섞이지 않음 |
| P21 | 시작일 이동·종료일 직접 입력·기간 버튼 | 시작일 변경 시 기간 유지, 종료일 변경 시 일수 계산, 기간 버튼은 선택한 시작일 유지 |
| P22 | 총 금액 할인 5,000원 두 번 + 10,000원 한 번 | 20,000원 누적, 횟수 표시. 한 번 취소 시 마지막 10,000원만 제거 |
| P23 | 스키 2개·의류 1개 하루 50,000원, 스키 장비당 5,000원 + 총 할인 20,000원 | 장비당 할인 10,000원, 최종 20,000원. 총 할인 전체 해제 시 장비당 할인은 유지 |
| P24 | 스키 2개·의류 1개 이틀, 스키 장비당 5,000원 + 총 할인 5,000원 | 100,000−10,000−5,000 = 85,000원. 리프트 1매 추가 시 130,000원. 장비당 할인에 일수를 곱하지 않음 |
| P25 | 종료일이 시작일 이전·빈 날짜 | 안내 후 저장 차단, 기존 접수 값 유지 |
| P26 | 할인 대상 금액보다 많이 총 할인 누적 | 실제 적용액은 대상 금액 한도, 0원 미만 차단, 취소·해제 가능 |
| P27 | 마감 후 과거 거래 정정 | 기존 마감 확정본 유지, 정정 내역·새 버전 표시 |

## 실제 운영 전에 필요한 설정값

문서 작성과 화면 설계는 이 값이 아직 없어도 진행할 수 있습니다. 실제 가격·발송·정산을 사용하기 전에 매장의 값을 입력합니다.

- 스키·보드 기본 구성과 의류·보호대의 수량 단위.
