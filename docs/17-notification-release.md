# 매장·차량 알림 구현 기록

작성일: 2026-09-08 · 대상: [운영 화면 체험](https://rosookwan.github.io/ski-rent-ops/) · 계획: [알림 개발계획서](15-notification-development-plan.md)

매장과 차량 상단에서 새 업무 소식을 확인할 수 있다. 종을 누르면 오른쪽 알림함이 열리고, 알림 행 전체를 누르면 해당 내용만 확인 처리한다. 반납 수량과 실제 업무 완료 상태는 알림 확인으로 바뀌지 않는다.

## 화면에서 사용하는 방법

1. `매장 POS`로 들어가 상단 종을 연다. 예시 수거 내역을 누르면 확인 상태가 바뀌며 `반납 내역 보기`로 업무를 확인할 수 있다.
2. `배달·수거`에서 기사님 확인 요청을 보내고 상단의 `차량 화면`으로 전환한다. 새 요청이 종과 요청 띠에 표시된다. 알림 행 또는 요청 띠 전체를 누르면 같은 확인 상태로 반영된다.
3. 차량 알림함 아래의 `매장에 요청`으로 수량 확인·고객 연락 문제 등을 보낼 수 있다. 고객·업무를 선택하고 큰 빠른 선택 버튼이나 직접 입력을 사용한다. 매장으로 돌아오면 해당 요청이 표시된다.
4. `보낸 요청`에서 요청됨, 전달됨, 상대방 확인함을 구분한다. 발신 화면에서 목록을 읽는 동작은 상대방의 확인을 대신하지 않는다.
5. 알림함 아래 `알림 소리`를 눌러 켠다. 30초 또는 60초와 볼륨을 선택하고 `소리 들어보기`로 시험한다. 매장 설정의 `알림` 탭에서도 바꿀 수 있다.

Pages는 가상 자료를 사용하는 한 페이지의 메모리 체험이다. 같은 페이지에서 매장↔차량을 전환해 사용하며 새로고침하면 예시로 돌아간다. 서로 다른 PC·태블릿의 실시간 공유와 실제 직원 로그인은 아직 연결하지 않았다.

## UI 구성

| 항목 | 적용 |
|---|---|
| 디자인 | 기존 Makaryo 계열의 주황색 POS, 보라색 차량 화면, Pretendard와 기존 아이콘 사용 |
| 알림함 | 오른쪽 단일 패널. 미확인·전체·보낸 요청, 내용 상세, 요청 작성, 소리 설정 |
| 종 | POS 48px, 차량 56px 터치 영역. 미확인 개수 표시. 종 아이콘만 약 ±11도 흔들고 쉼 |
| 확인 | 전체 행을 터치. 종 열기·목록 스크롤만으로 확인하지 않음. 별도 작은 확인 버튼 없음 |
| 새 알림 도착 | 상단 개수만 갱신하고 열린 입력창·고객·업무는 유지. 열린 목록은 `새 소식 보기`로 갱신해 행 위치 유지 |
| 차량 배너 | 요청 띠 전체를 눌러 확인. 종과 같은 상태 사용 |
| 작은 화면 | 1024×520에서 소리 설정과 요청 입력의 주요 항목·보내기 버튼까지 한눈에 표시. 긴 목록·긴 상세만 내부 스크롤 |
| 접근성 | 키보드·Escape·닫은 뒤 포커스 복귀·새 알림 안내. 움직임 줄이기 설정에서는 흔들림 해제 |

로컬 `.fig` 자료의 제공 썸네일과 현재 구현을 함께 참고했다. 별도 폰트·아이콘 서비스 요청을 추가하지 않았다. 고객용 안내·사전 입력·로그인 화면에는 직원 종이 표시되지 않는다.

## 구현한 알림과 업무 구분

| 발생 원인 | 수신과 내용 | 이번 연결 범위 |
|---|---|---|
| 차량 수거 | 매장에 실제 수거 수량과 고객 잔여 수량 | 공통 반납 이벤트·화면 연결 |
| 수거량 0 | `수거하지 못했어요`와 남은 물품 | 허위 수거 완료 표시 없음 |
| 매장 우선 요청 | 담당 차량에 요청. 매장은 원래 요청에서 수신·확인 상태 조회 | 양쪽 UI·저장 API |
| 기사님 도움 요청 | 매장 알림함에 요청 내용 | 양쪽 UI·저장 API |
| 반납 일정 변경 | 담당 차량에 변경 전후 일정 | `planReturn` 이벤트 연결 |
| 수량 정정·기록 취소 | 반대 담당에게 변경 안내. 이전 수거 알림 종료 | 공통 반납 이벤트 연결 |
| 매장 인계 확인 | 해당 수거 알림 종료. 차량에 소리 반복 없는 인계 결과 | 수거 기록별 잔량 기준, 다른 수거 기록은 보존 |
| 새 수거 접수 | 담당 차량에 새 수거 일정 | 공통 접수 생성 이벤트 |
| 차량 재배정 | 이전 차량의 고객 정보 제거·변경 안내, 새 차량에 배정 알림 | `assignVehicle` API. 연락처 화면의 차량 선택과는 별도 |
| 배달·수거 업무 배정·수정·취소 | 안정적인 업무 ID와 버전으로 저장 후 알림 생성 | `task` API. 기존 배달 보드의 모든 동작을 이 API에 연결한 상태는 아님 |

알림 확인과 수신 기록은 접수의 `version`, 요금, 결제, 고객 보유·차량 보관·매장 확인 수량에 영향을 주지 않는다. 처음 확인한 사람과 시각을 보존한다. 업무와 알림이 함께 변경되는 경우 한 저장 트랜잭션을 사용하며, 알림 저장 실패 시 업무도 롤백한다.

## 소리 동작

- 기본은 꺼짐이다. `알림 소리`를 켜면 반복 알림이 활성화된다. `소리 들어보기`는 켜짐 설정을 바꾸지 않고 한 번 시험 재생한다. 미확인 알림이 없어도 시험 소리는 끝까지 재생한다.
- 주의가 필요한 미확인 알림이 있으면 활성 화면에서 설정 간격으로 약 4초의 `띠링띠링` 알림음을 재생한다. 두 음이 올라가는 종소리를 세 차례 울리고 잔향으로 마무리한다. 한 개의 타이머와 재생 상태로 소리가 겹치지 않게 한다. 확인하면 뒤에 예정된 음까지 즉시 취소한다.
- 마지막 대상 알림 확인, 로그아웃, 화면 숨김, 소리 끄기 시 재생을 중지한다. 화면 복귀 시 밀린 횟수만큼 몰아서 재생하지 않는다.
- 시험 소리와 반복 알림을 구분한다. 알림을 모두 읽으면 반복만 멈추며, 사용자가 누른 시험 재생은 유지한다. 화면이 보이는 동안에는 포커스가 입력창 밖으로 이동해도 반복을 유지한다. 로그아웃·화면 숨김·끄기는 시험 재생도 중지한다.
- 매장과 차량의 설정은 구분한다. API에서는 인증된 `deviceId`가 있으면 기기별로, 없으면 사용자와 수신 범위별로 보관한다. 공개 체험 설정은 메모리에만 보관한다.
- 브라우저의 재생 준비 상태와 오류를 표시한다. 시스템 음량, 실제 스피커 출력, 화면 잠금·다른 앱·절전 중 반복 재생은 자동 검사만으로 보장하지 않는다.

2026-09-08 PC 피드백 수정: 기존 알림 종료 처리가 시험 소리까지 즉시 끊어 실제 신호가 0이 되는 문제를 재현하고 수정했다. 이전 재생 횟수 검사만으로는 발견하지 못했던 경우로, 오디오 출력 경로에 분석기를 연결해 신호도 검사한다. 종에 적용되던 상단 버튼의 여백·정렬을 분리해 POS와 차량 모두 중심 오차 0px을 확인했다. iframe에는 오디오 권한을 명시적으로 위임하며, 사용자 클릭 뒤 오디오 시작과 브라우저 차단 시 안내는 유지한다. [Chrome의 iframe·Web Audio 정책](https://developer.chrome.com/blog/autoplay).

추가 소리 조정: 차량에서도 알아차리기 쉽도록 0.5초 미만의 짧은 신호를 약 4초의 종소리로 바꿨다. 볼륨 설정과 30/60초 반복 간격은 유지한다. 검사에서는 3초 이후에도 신호가 있고 4.6초 안에 끝나는지, 재생 도중 확인하면 남은 음도 나오지 않는지 확인한다.

## 저장 API와 운영 연결

기존 SQLite 반납 서버를 확장했다. [로컬 API 실행 방법](10-return-functions.md#로컬-저장-api-실행)으로 같은 서버를 실행하며, 공개 Pages 빌드에 API 토큰이나 운영 서버 주소를 넣지 않는다.

| HTTP | 경로 | 응답·동작 |
|---|---|---|
| GET | `/api/notifications?filter=all&cursor=0&limit=50` | 수신 범위별 목록, 미확인 수, `nextCursor`. 필터는 `all`/`unread`, 최대 100개 |
| GET | `/api/notifications/sync?cursor=0` | 변경된 알림, 현재 미확인 수, 갱신용 `cursor`, `reset` |
| GET | `/api/notifications/sent` | 같은 발신 범위에서 보낸 요청의 수신·확인 상태 |
| GET | `/api/notifications/tasks` | 매장 또는 담당 차량의 저장된 업무 |
| GET | `/api/notifications/preferences` | 인증 사용자·기기에 해당하는 소리 설정 |
| POST | `/api/notifications/commands` | `request`, `received`, `ack`, `preferences`, `task` 명령 |

모든 알림 API는 기존 Bearer 인증을 사용한다. 매장·역할·차량·기기는 서버 인증 정보로 결정하며 본문으로 바꿀 수 없다. 계획서의 개별 확인 URL 대신 기존 반납 API와 같은 단일 명령 형태로 구현했다.

```js
// 명령마다 새 requestId를 만들고, 응답 유실 시에는 같은 객체로 다시 시도한다.
const request = SkiNotificationClient.command('request', {
  orderId: order.id,
  expectedVersion: order.version,
  message: '이 업무를 먼저 확인해 주세요.'
});
await client.execute(request);
```

목록 페이지의 `cursor`는 목록 위치이고 `/sync`의 `cursor`는 변경 번호다. 두 값을 혼용하지 않는다. 변경 조회의 `reset: true`는 로컬 알림을 응답 전체로 교체하는 의미다. 개별 알림은 ID별 최신 `revision`으로 합친다. 확인·종료된 알림도 변경 조회에 포함해 예전 미확인이 남지 않게 한다. 소리 설정과 보낸 요청은 각각의 조회로 갱신한다.

HTTP 클라이언트는 기본 3초 간격으로 조회한다. 연결 실패는 상태 콜백으로 전달하며 명령을 자동 재전송하지 않는다. 중지 후 도착한 응답은 무시한다. 실제 운영 화면에 연결할 때 로그인·수신 범위 변경마다 클라이언트를 교체하고 기존 캐시·폴링·소리를 정리해야 한다.

DB 스키마 2는 `notification_state`에 매장별 알림·확인·요청 중복 기록·업무·설정을 저장한다. 기존 접수와 이벤트 테이블은 보존한다. 최초 시작 시 스키마 1에서 추가 테이블을 생성하며 과거 모든 업무를 새 미확인 알림으로 재생하지 않는다. 운영 전환 시 중지한 DB의 일관된 백업을 보관하고, 이전 앱으로 돌아갈 때는 같은 시점의 DB 백업도 함께 복원한다. 이전 앱은 스키마 2를 지원하지 않는다.

알림 UI 검사는 1024×768·1366×768 POS, 907×648·907×710의 낮은 POS 창, 1024×520·600·800 차량을 확인한다. 1024×520의 요청 입력과 소리 설정은 컨텐츠 높이·스크롤 높이를 비교해 불필요한 내부 스크롤도 검사한다. Pages 흐름의 외부 변경 요청과 JavaScript 실행 오류는 0건이다.

인증된 두 HTTP 클라이언트가 로컬 서버에서 요청과 확인을 주고받는 통합 시험, SQLite 재시작 후 확인 상태 보존, 스키마 1 마이그레이션, 알림 저장 실패를 강제로 발생시킨 수거 트랜잭션 롤백을 검증했다. 실제 두 기기 운영 시험을 대신한 것으로 기록하지 않는다.

검사 명령은 README에 있으며, 캡처·JSON 결과는 Git에서 제외한 `work/notifications-*`에 생성한다. Pages 배포는 반납·알림 단위 검사와 정적 빌드를 통과한 커밋을 사용한다. 배포 후 공개 HTML과 빌드 일치, 공개 주소의 알림 UI 동작을 추가 확인한다.

| 탭 S6 실제 터치·청음·전화 후 복귀·네트워크 전환 | 실기기 미연결로 미검증 |
| 설치형 운영 PWA·화면 잠금·백그라운드 시스템 푸시 | 미구현 |

실제 기기 간 운영은 서버와 인증을 연결한 뒤 별도로 확인해야 한다. 이번 Pages UI 배포나 로컬 API 시험만으로 다중 기기 운영과 화면 잠금 중 알림이 완성됐다고 표시하지 않는다.

## 업무 UI 연결 후 차량 알림 복구

2026-09-08 후속 사용자 피드백을 반영했다. 새 배너에서 빠졌던 흔들리는 종 아이콘과 배너 전체 확인 동작을 복구하고, 배너를 오른쪽 업무 상세 영역 안에 배치해 왼쪽 방문 목록의 높이를 줄이지 않도록 했다. 우선 확인과 순서 변경은 각각 확인하며, 자세한 요청 내용은 기존 알림함에서 확인한다.

차량 상단에 `알림 소리 켜기`를 추가해 알림함을 열지 않고 기존 소리 설정을 켜고 끌 수 있다. 4초 종소리·30/60초 반복·음량·사용자 클릭 후 재생 준비 방식은 유지한다. 읽지 않은 일반 안내가 남아 있어도 마지막 주의 요청을 확인하면 예정된 반복 음까지 즉시 취소한다.

새 런타임 회귀 검사 3개는 실제 알림 UI 제어 코드와 업무/알림 서비스를 사용하고 DOM·시계·오디오 기기만 대역으로 교체한다. 자동 검증은 총 69개다. Chrome에서 소리 준비 완료 표시, 종 흔들림, 두 배너 개별 확인과 수량 유지, 1024×600 배치(목록 끝 x=296, 배너·상세 시작 x=310)를 직접 확인했다. 실물 스피커 청취 결과와는 구분한다.
