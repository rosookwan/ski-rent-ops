# 리프트권·차량·예약·출력 업무 최종 정리안

작성일: 2026-09-08

이 문서는 대화에서 요청한 업무를 모은 구현 전 요구사항이다. 기능 코드나 배포를 변경하는 문서가 아니다. 날짜 기본값, 화면 배치, 집계 방식은 아래와 같이 제안한다.

핵심 방향은 **큰 글자, 큰 작업 버튼, 적은 화면 이동, 최소 입력**이다. 매장과 차량은 같은 물품 이동 기록을 기준으로 수량을 보고, 현재 해야 할 일과 예외를 바로 확인한다.

## 1. 화면 구성과 공통 사용성

| 화면 | 주로 하는 일 |
|---|---|
| 매장 · 배달·수거 | 출발 전 물품 싣기, 차량별 방문 순서 조정, 전달·수거·환불 업무 배정 |
| 매장 · 리프트권 예약·발권 | 고객별 여러 날짜 예약, 오늘·내일 예약 조회, 권종별 발권 대상과 남은 수량 확인 |
| 매장 · 사전 입력·준비 | 입력폼 발송, 응답 확인, 장비 준비표와 팀 스티커 출력 |
| 차량 · 통합 업무 화면 | 현재 차량 보관 수량, 다음 업무, 매장 변경 안내, 수거·전달·환불 처리 |
| 매장 · 반납 확인·마감 | 차량에서 받은 장비 최종 확인, 리프트권 이동·환불·회수 집계 확인 |

- 차량의 간단히/자세히는 자세히를 기반으로 하나로 통합한다. 별도 모드 선택을 기본 작업에 요구하지 않는다.
- 한 영역에 한 역할을 준다. 비슷한 카드, 색상 배지, 안내 문구를 반복하지 않는다.
- 차량은 위에서부터 `현재 보관 수량 → 매장 변경 안내 → 이번 업무 → 큰 처리 버튼` 순서로 고정한다.
- 현재 수량, 고객, 장소, 시간, 해야 할 일, 이번 업무에 필요한 메모는 펼쳐서 표시한다.
- 수량의 출처와 환불 예정분도 보조 줄로 바로 표시한다. 중요한 정보를 작은 아이콘, 더보기, 아코디언 안에만 넣지 않는다.
- 과거 이력은 이름이 적힌 큰 `이동 기록 보기` 버튼으로 연결할 수 있다. 현재 업무 메모는 그 안에 숨기지 않는다.
- 주요 동작은 문맥에 맞는 큰 버튼 2~3개를 중심으로 둔다. 예: `수거 완료`, `일부만 받았어요`, `고객에게 전화`.
- 일반 본문은 20px 안팎, 핵심 숫자는 28~36px, 매장 주요 버튼은 높이 64px 이상, 차량 주요 버튼은 72px 이상을 목표로 한다. 실제 매장 화면과 차량 태블릿에서 확인한다.
- 색상만으로 상태를 구분하지 않고 `수거`, `전달`, `환불`, `매장 변경` 등의 글자를 함께 쓴다.
- 날짜는 `오늘`, `내일`, `모레`, 큰 달력 버튼으로 고른다. 수량은 큰 `− / 숫자 / +`와 숫자 키패드로 입력한다.
- 고객 정보는 기존 예약·접수에서 불러온다. 새 고객의 이름·연락처만 처음 한 번 입력하는 흐름을 기본으로 한다.
- 통신이 끊기거나 처리 결과가 불확실하면 현재 화면에 마지막 갱신 시각과 미반영 상태를 표시한다. 확인되지 않은 처리를 완료로 표시하지 않는다.
- 새 알림이나 순서 변경 때문에 현재 누르고 있는 고객·처리 버튼의 대상이 바뀌지 않게 한다.

## 2. 리프트권 예약 입력과 날짜별 조회

### 고객 한 명에게 여러 이용일 등록

대표자 이름과 연락처는 한 번 입력하고, 날짜별로 권종 수량만 고른다. 예약이 없는 고객도 리프트권 예약부터 만들고 나중에 장비 접수와 연결할 수 있다.

예시 고객: 홍길동 / 010-1111-2222

| 이용일 | 3시간권 | 4시간권 | 6시간권 |
|---|---:|---:|---:|
| 2026-09-09 수 | 4매 | 3매 | 0매 |
| 2026-09-10 목 | 0매 | 0매 | 2매 |

입력 흐름:

1. 기존 고객 선택 또는 대표자 이름·연락처 입력.
2. 이용일을 `내일` 또는 달력에서 선택.
3. 3시간권·4시간권·6시간권의 큰 수량 버튼을 누름.
4. `다른 날짜 추가`로 다음 날짜를 한 줄 더 만듦.
5. `예약 저장`으로 한 번에 저장.

권종은 매장에서 설정한 목록을 사용한다. 같은 고객·이용일·권종은 수량을 합쳐 보여주되, 유효 조건이나 전달 조건이 다르면 구분한다. 날짜를 추가해도 이름과 연락처를 다시 입력하지 않는다.

### 이용일과 발권 예정일

- 예약 목록은 **이용일** 기준으로 조회한다.
- `오늘 발권할 권`은 **발권 예정일** 기준으로 조회한다.
- 기본 발권 예정일은 이용일로 제안한다. 미리 발권할 건은 큰 `오늘 미리 발권` 버튼이나 발권일 선택으로 바꾼다.
- 9월 9일 이용 예약을 9월 8일 발권하도록 지정하면, 9월 9일 예약 목록과 9월 8일 발권 업무에 각각 나타난다.
- 실제 발권 완료일은 별도로 기록한다. 발권을 먼저 했다고 고객의 이용일을 바꾸지 않는다.
- 일괄 날짜 변경은 선택한 예약에만 적용하고 기존 완료 기록은 보존한다.

### 조회와 합계

상단에 `오늘 / 내일 / 날짜 선택`을 큰 버튼으로 둔다. 선택한 날짜는 `9월 9일 수요일`처럼 분명하게 표시한다.

`예약 조회`에서는 권종별 총 예약 수량을 보여준다. 위 예시만 있다면 9월 9일 예약 합계는 3시간권 4매, 4시간권 3매, 6시간권 0매다.

`발권할 권`에서는 권종마다 다음 수량을 같은 표에서 확인한다.

| 구분 | 의미 |
|---|---|
| 예약 수량 | 취소되지 않은 해당 발권 업무의 예약 수량 |
| 확보 완료 | 이미 발권했거나 보유권을 해당 예약에 배정하여 실제 확보한 수량 |
| 추가 발권 필요 | 예약 수량 중 아직 확보하지 못한 수량 |

운영 화면에서는 **추가 발권 필요 수량**을 가장 크게 표시한다. 대상 고객 목록에는 이름·연락처, 이용일, 권종별 수량, 확보 여부를 간결하게 표시한다. 목록에서 `발권 완료`, `일부 발권`, `보유권 사용`으로 처리한다.

- 발권 완료는 실제 권을 확보한 수량만 기록한다. 예약 저장으로 자동 발권 처리하지 않는다.
- 추가 발권 필요 수량은 취소되지 않은 수요에서 실제 확보·배정된 수량을 뺀 값이며 음수가 되지 않는다.
- 보유권 사용은 해당 예약의 이용 조건을 충족하는 권을 배정했을 때만 반영한다. 같은 실물 권을 같은 시간대 여러 예약에 중복 배정하지 않는다.
- 아직 고객에게서 회수하지 않은 권은 `회수 대기`로 표시한다. 실제 확보 완료로 표시하지 않는다.
- 취소된 미발권 수량은 발권 대상에서 제외한다. 이미 발권된 권의 예약 취소와 실물 환불은 별도로 처리한다.
- 발권 예정일이 지났는데 미확보인 건은 `이전 날짜 미발권`으로 현재 업무에 드러나게 표시한다.
- 매장에서 미리 확보한 예비권과 고객 예약 수량을 구분한다. 예비권을 예약에 배정할 때 중복 확보가 생기지 않게 한다.

## 3. 매장에서 차량에 물품 싣기

배달 출발과 수거 출발 모두 매장에서 리프트권을 실을 수 있다. 이 작업을 특정 고객 배달 건에만 종속시키지 않는다.

카운터의 배달·수거 화면에 `차량에 실을 물품` 영역을 배치한다.

1. 큰 차량 선택 버튼으로 1호차·2호차 등을 선택.
2. 장비·의류·헬멧·리프트권의 이번 추가 수량을 입력.
3. 리프트권의 용도를 `고객 전달`, `차량 예비분`, `환불할 권` 중에서 선택.
4. 고객 전달이면 기존 고객과 약속 장소·시간을 연결. 예비분은 고객 없이 등록 가능.
5. 실제 적재 후 `차량에 실었어요`를 눌러 반영.

항상 `기존 차량 보관 / 이번 추가 / 등록 후 총수량`을 함께 보여준다. 예: 6시간권 기존 2매 + 이번 추가 3매 = 총 5매. 등록은 현재 총수량 덮어쓰기가 아닌 실제 추가 이동이다.

카운터 입력 중인 예정량은 차량 현재 수량에 포함하지 않는다. 적재 등록 후 차량에 `카운터에서 6시간권 3매 추가`를 표시한다. 기사님의 읽음 확인은 추가 적재를 한 번 더 만들지 않는다.

물품을 싣고 출발할 때마다 추가 등록할 수 있다. 이전 운행에서 남은 물품은 그대로 유지한다. 등록 실수는 해당 적재 기록을 정정하여 수량과 이력을 함께 맞춘다.

## 4. 리프트권 회수·재전달

리프트권의 이동을 고객 한 건의 반납 상태만으로 관리하지 않는다. 권 또는 조건이 같은 수량 묶음의 현재 보유자와 다음 전달 대상을 관리한다.

기본 이동:

`매장 → 오전 고객 → 차량 → 오후 고객 → 차량 또는 매장`

- 장비와 리프트권을 함께 회수한 뒤 리프트권만 다음 고객에게 전달할 수 있다.
- 매장을 거치지 않는 차량에서 고객으로의 재전달을 지원한다.
- 회수 업무와 다음 전달 업무를 연결하고, 다음 카드에는 `리프트권만 전달`을 크게 표시한다.
- 다음 고객에게 권을 전달하면 차량의 리프트권 수량만 줄고 장비는 그대로 남는다.
- 실제 받은 권만 전달 가능 상태로 바뀐다. 4매 회수 예정 중 2매만 받았다면 2매 확보와 2매 미회수를 구분한다.
- 고객에게서 돌려받음, 차량 보관, 매장에 들어옴, 다른 고객에게 전달함을 구분한다.
- 장비의 차량 수거와 매장의 최종 반납 확인은 기존 역할 구분을 유지한다. 리프트권 재전달을 위해 허구의 매장 입고 기록을 만들지 않는다.
- 고객에게 판매한 이용 조건과 실물 리프트권의 권종·유효 조건을 구분할 수 있게 한다. 권종 이름이 같아도 실제 사용 가능 조건이 다른 권을 합쳐 판단하지 않는다.
- 재사용권은 실제 유효 종료시각을 이번 업무에서 바로 보여준다. 사용 가능 여부와 잔여시간 판단은 발권처의 권종 규칙을 따른다.
- 관리번호나 스캔을 활용할 수 있도록 설계하되, 모든 권의 긴 번호를 매번 손으로 입력하게 만들지 않는다.
- 고객을 바꿔 전달하는 동작은 신규 발권이나 환불로 집계하지 않는다.

## 5. 차량이 리프트권을 가져가 환불

여기서 환불은 **차량이 권을 발권처에 가져가 반납하고 환불받는 업무**를 기본 사례로 정리한다. 고객에게 돈을 돌려주는 결제 환불과는 구분한다.

### 환불할 권 2매의 예

1. 카운터에서 환불할 권종과 2매를 선택하고 담당 차량·발권처를 지정.
2. 권이 매장에 있으면 `차량에 실었어요`로 옮김. 이미 차량에 있으면 목적을 환불로 지정하며 다시 적재하지 않음.
3. 차량에는 `리프트권 2매 환불` 작업이 큰 카드로 표시됨.
4. 발권처에서 실제 권을 넘기고 환불을 확인한 수량에 대해 `2매 환불 완료` 처리.
5. 차량 보관 수량과 환불 대기 수량에서 해당 2매가 빠지고, 환불 처리 매수·실제 금액이 기록됨.

### 상태와 수량

- 환불 예정 또는 환불하러 이동 중이면 아직 차량에 있는 권은 현재 보관 수량에 포함한다.
- 환불 예정분은 고객 전달 가능 수량에서 제외하고, 상단에 `환불할 권 2매`를 바로 표시한다.
- 2매 중 1매만 환불되면 1매만 차감하고 나머지 1매는 환불 대기 상태로 남긴다.
- 환불을 받지 못했으면 차량 보관 수량을 유지하고 `환불 미완료`로 표시한다.
- 환불 예정 취소는 용도와 업무를 바꾸는 기록이다. 실물 이동이 없다면 차량 수량을 바꾸지 않는다.
- 실제 환불 금액을 기록한다. 확정 단가가 등록되어 있는 경우만 기본값을 채우고 실제 처리 금액으로 수정할 수 있게 한다.
- 환불이 끝났다는 이유만으로 고객 예약 수량을 자동 취소하지 않는다. 예약이 계속 필요하면 대체권 확보가 필요한 상태를 보여준다.
- 신규 발권, 재전달, 환불, 회수 기준 금액, 고객 결제 환불을 구분하여 중복 집계하지 않는다.
- 기존 장당 1,000원 회수 기준 금액을 리프트권 환불 금액으로 자동 적용하지 않는다.

## 6. 차량 현재 보관 수량

차량 화면 공통 상단은 화면 이동 중에도 유지한다. `오늘 업무`, `차량 보관 내역`, 고객 상세 사이를 이동해도 현재 수량을 계속 볼 수 있어야 한다.

표시 품목은 장비, 의류, 헬멧, 권종별 리프트권이다. 장비의 스키·보드 구분도 보조 줄에 표시하고 부츠 등 구성품을 중복 합산하지 않도록 단위를 정한다.

| 실제 이동 | 차량 현재 수량 |
|---|---:|
| 매장에서 차량에 적재 | 증가 |
| 고객에게 회수 | 증가 |
| 고객에게 전달 또는 재전달 | 감소 |
| 차량에서 매장에 인계 | 감소 |
| 발권처에 실물 인계 후 환불 완료 | 감소 |

현재 수량은 이전부터 남은 수량에 실제 입고를 더하고 실제 출고를 뺀다. 일부 처리·정정·취소도 원래 이동 기록과 연결해서 반영한다.

- 현재 차에 있는 전체 물품을 보여주고, 매장에서 실은 분량과 고객에게서 회수한 분량 중 **지금 남은 수량**을 구분한다.
- 환불 예정분은 전체 보관에 포함하되 고객 전달 가능분과 구분한다.
- 예비권에 고객을 배정하는 것만으로 수량이 줄지 않는다. 실제 전달 완료 때 줄어든다.
- 고객의 접수 전체가 완료되어야 차감되는 구조로 만들지 않는다. 해당 물품의 실제 이동 기준으로 반영한다.
- 오늘 회수한 누적 수량은 별도 집계다. 재전달·환불·매장 인계로 현재 수량이 줄어도 오늘의 회수 기록은 보존한다.
- 자정에 차량 보관 수량을 0으로 초기화하지 않는다. 차에 남은 물품은 다음 날로 이어진다.
- 읽음 확인, 화면 이동, 중복 클릭, 같은 요청 재시도로 수량이 중복 반영되지 않아야 한다.

## 7. 매장이 변경하는 업무 우선순위

- 기본 순서는 날짜·차량별 시간순이다.
- 매장은 큰 `위로`, `아래로`, `맨 위` 버튼으로 대기 업무 순서를 계속 조정한다. 드래그는 보조 조작으로만 둔다.
- 방문 순서와 예정 시간은 다른 정보다. 순서를 옮겨도 고객과 약속한 시간을 바꾸지 않는다.
- 매장 지정 순서를 저장하고 차량에 즉시 반영하도록 연결한다. 기사님이 확인할 때까지 적용을 기다리는 방식으로 만들지 않는다.
- 차량에는 `매장에서 홍길동 팀을 3번째 → 1번째로 변경` 안내와 해당 업무 강조를 표시한다.
- 매장에서 기사님의 변경 확인 여부를 볼 수 있게 한다. 이후 새로운 변경은 다시 확인 대상으로 표시한다.
- 현재 보고 처리 중인 고객은 유지하고 대기 목록을 갱신한다. 완료 업무는 대기 순서에서 제외한다.
- 큰 `시간순으로 복원` 버튼을 제공한다.
- 기존 `우선 확인 요청` 기능은 유지한다. 순서 변경의 확인과 우선 확인 요청의 읽음은 서로 다른 사건이다.
- 같은 우선 확인 요청의 배너와 알림함은 같은 읽음 상태를 공유한다. 별개의 순서 변경을 확인했다고 우선 요청까지 읽음 처리하지 않는다.
- 중요한 변경은 화면 본문에도 표시한다. 종 모양 알림함을 열어야만 알 수 있는 구조로 만들지 않는다.
- 저장·기기 전달·기사님 읽음을 구분한다. 기기 연결이 끊겼을 때 전달 완료로 표시하지 않는다.

관련 알림 계획: [매장·차량 알림 기능 개발계획서](15-notification-development-plan.md).

## 8. 고객 입력폼과 장비 준비

`대표자 이름·연락처 → 입력폼 보내기 → 고객이 일행별 작성·제출 → 매장 확인 → 준비표 인쇄 → 장비 세팅 → 준비 완료 → 실제 지급`

- 예약이 없어도 입력 요청을 먼저 만들 수 있다. 기존 예약이 있으면 고객 정보와 연결한다.
- 대표자별 전용 링크를 발송하고 이름·연락처 등 이미 아는 내용은 다시 입력시키지 않는다.
- 고객은 일행별 이름, 스키·보드, 키, 발 사이즈, 필요한 의류 등을 선택한다. 사이즈를 모르면 `현장 확인`을 고를 수 있다.
- 대표자가 일행 전체를 입력할 수 있게 한다. 일행 추가·삭제는 큰 버튼으로 제공한다.
- 매장은 제출 인원과 예정 인원을 함께 확인한다. 일부만 입력한 팀도 드러나게 표시한다.
- 고객 응답과 매장이 확정한 준비·지급 정보를 구분한다. 고객 수정으로 확정 접수나 지급 기록을 조용히 덮어쓰지 않는다.
- 인쇄 후 고객이 수정하면 `출력 후 변경됨`을 눈에 띄게 표시하고 바뀐 사람과 항목을 바로 보여준다.
- 제출 완료, 매장 확인, 인쇄 여부, 장비 준비 완료, 실제 지급 완료를 구분한다.

## 9. A4 준비표와 팀 스티커

### A4 장비 준비표

- 응답 상세에 큰 `이 팀 준비표 인쇄`, 날짜별 준비표에 큰 `선택한 팀 인쇄` 버튼을 둔다.
- 여러 팀을 선택해 한 번에 인쇄할 수 있다.
- A4 세로 한 장에 **20명 기준**으로 배치한다. 20명을 초과하면 다음 장으로 이어지고 표 머리글을 반복한다.
- 한 사람을 한 줄로 표시한다: `대표자/팀 · 이름 · 스키/보드 · 키(cm) · 발(mm) · 의류 · 준비 확인칸`.
- 팀이 바뀌는 곳은 구분선으로 표시하고, 각 행의 팀 번호를 유지해 페이지가 나뉘어도 일행을 찾을 수 있게 한다.
- 실제 출력은 10.5~11pt 안팎과 9mm 안팎의 행 높이부터 검토한다. 운영 화면의 큰 버튼·본문 규격을 종이에 그대로 적용하지 않는다.
- 준비 날짜·대상 인원·출력 기준 입력본·출력 시각·페이지 번호를 표시한다.
- 고객 입력 사이즈와 실제 지급 사이즈가 다른 경우 혼동하지 않게 표시한다.
- 인쇄창을 연 것만으로 실제 출력 또는 장비 준비를 완료했다고 처리하지 않는다.

### 팀 구분 스티커

- 큰 `팀 스티커 출력` 버튼으로 접수에 있는 대표자 이름·연락처를 가져온다.
- 대표자 이름과 팀 번호를 가장 크게 표시하고 연락처, 장비 구성, 배달 시간·장소, 담당 차량을 함께 넣는다.
- 기본은 선택한 팀마다 1장 출력이다. 4~5팀을 선택하면 팀별 스티커를 한 번에 출력한다. `한 장 더 출력`도 큰 버튼으로 둔다.
- 매번 이름·전화번호를 다시 입력하지 않는다. 변경된 접수로 다시 출력할 때 기존 출력본과 구분할 수 있게 한다.
- 처음에는 일반 인쇄 흐름으로 검토하고, 프린터가 정해지면 매장 PC와 제조사 지원 도구를 연결해 직접 출력하도록 확장한다.
- 예를 들어 Brother의 지원 프린터는 Windows PC의 드라이버·b-PAC·브라우저 확장을 사용하는 웹 인쇄 구성이 제공된다. 실제 채택은 매장 PC 운영체제와 프린터 모델을 기준으로 확인한다. [Brother 공식 웹 인쇄 안내](https://support.brother.com/g/s/es/htmldoc/dev/bpac_webapplication_eng2.pdf)
- 라벨 폭과 인쇄 크기를 정하고, 젖은 장비·추위에서의 부착 유지와 제거 상태를 실물로 시험한다.

## 10. 기록과 집계를 연결하는 기준

화면마다 다른 수량을 직접 관리하지 않고 같은 예약·확보·물품 이동 기록에서 계산한다.

| 기록 | 관리하는 내용 |
|---|---|
| 고객·예약 | 대표자, 연락처, 이용일별 권종·수량, 취소된 수량 |
| 발권 업무 | 발권 예정일, 실제 확보 수량, 예약에 배정된 보유권, 미확보 수량 |
| 물품 현재 보관 | 매장·차량·고객 중 실제 보유자, 권종·유효 조건, 전달·환불 예정 용도 |
| 물품 이동 | 매장 적재, 고객 지급, 고객 회수, 재전달, 매장 인계, 환불 인계와 정정 |
| 환불 처리 | 발권처, 실제 환불 매수·금액·시각·담당자, 연결된 권 또는 묶음 |
| 업무 순서 | 날짜·차량별 대기 순서, 변경자·시각, 기사님 확인 여부 |
| 입력·출력 | 고객 입력본, 매장 확인, 준비 상태, 출력 대상과 기준 입력본 |

현재 보관 수량, 오늘 회수 누적, 신규 발권 매수, 환불 매수, 회수 기준 금액, 고객 결제는 서로 다른 집계다. 반납·인계·재전달을 한 번 더 기록했다고 실제 실물이나 금액이 늘어나지 않게 한다.

## 11. 구현 후 확인할 대표 시나리오

| 사례 | 확인할 결과 |
|---|---|
| 홍길동에게 9/9 3시간권 4매·4시간권 3매, 9/10 6시간권 2매 예약 | 고객 정보를 한 번만 입력하고 날짜별 조회·권종 합계가 맞음 |
| 9/9 이용분을 9/8 미리 발권하도록 지정 | 9/9 예약과 9/8 발권 대상에 각각 표시됨 |
| 예약 4매 중 2매만 발권 | 확보 2매, 미확보 2매로 표시됨 |
| 이미 확보한 권 또는 사용 조건이 맞는 회수권을 예약에 배정 | 추가 발권 필요 수량만 줄고 신규 발권 매수가 늘지 않음 |
| 미발권 예약 취소 / 발권 후 예약 취소 | 수요는 줄되 이미 있는 실물 권은 환불·이동 없이 사라지지 않음 |
| 기존 차량 2매에 매장에서 3매 추가 | 총 5매가 되며 기사님 읽음 확인 후에도 5매 유지 |
| 수거하러 출발하면서 예비권 적재 | 고객 배달 예약 없이 적재 가능 |
| 장비와 권을 함께 회수하고 권만 다른 고객에게 전달 | 장비는 차량에 남고 전달한 권만 빠짐 |
| 회수 예정 4매 중 2매만 실제 인수 | 확보한 2매와 미회수 2매 구분, 미확보 권 전달 방지 |
| 차량에 이미 있는 2매를 환불 대상으로 지정 | 차량 수량은 그대로, 전달 가능 수량에서만 제외 |
| 환불 2매 요청 중 1매 성공 / 모두 미완료 | 성공한 수량만 차감, 남은 권과 환불 업무 유지 |
| 환불한 권의 예약이 계속 유효 | 대체권 확보 필요 상태 표시, 예약을 자동 취소하지 않음 |
| 매장에서 방문 순서 변경 | 차량 순서와 변경 안내 갱신, 현재 처리 대상 유지 |
| 순서 변경만 확인 / 우선 확인 요청만 확인 | 서로의 읽음 상태나 수량을 바꾸지 않음 |
| 화면 이동·재접속·중복 클릭·날짜 변경 | 현재 보관 이월, 중복 수량 방지, 연결 상태 표시 |
| 고객 입력 20명·21명 및 여러 팀 출력 | 한 사람 한 줄, 20명 기준 페이지 구성, 팀 구분 유지 |
| 인쇄 후 고객 사이즈 수정 | 변경된 사람과 항목 표시, 준비 상태 조용히 덮어쓰지 않음 |
| 스티커 5팀 일괄 출력 | 대표자·연락처 재입력 없이 팀별 1장 생성 |

## 12. 구현 순서 제안

1. 예약, 발권·확보, 리프트권 이동, 환불, 차량 현재 수량의 공통 규칙을 먼저 정한다.
2. 매장 예약·발권 화면과 출발 적재, 차량 통합 화면을 큰 버튼 중심으로 연결한다.
3. 매장 지정 순서와 기존 우선 확인 요청을 실제 기기 간 공유에 연결한다.
4. 입력폼 제출·매장 확인·A4 준비표 출력을 연결한다.
5. 실물 프린터를 정한 뒤 팀 스티커 직접 출력을 연결한다.

이 문서 작성은 요구사항 정리 단계다. 실제 발권처 자동 발권·자동 환불, 고객 메시지 발송, 운영 서버 연결, 물리 프린터 연동과 배포는 완료된 것으로 간주하지 않는다.
