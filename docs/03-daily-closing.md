# 스키샵 하루 마감 보고서 설계안

상태: 신규 설계 권고 · 2026-09-07

## 보고서 목적과 기준

카운터의 대여 기록과 결제 기록을 사용해 ‘오늘 어떤 거래를 확정했고, 얼마를 받거나 돌려줬으며, 아직 얼마를 받아야 하는지’를 확인합니다. 매장 모니터에서 보고 마감 확정·인쇄·PDF 저장·표 데이터 내보내기를 할 수 있도록 설계합니다.

대여 확정액, 실제 수납액, 카드사 입금액은 서로 다른 값입니다. 첫 구현은 직원이 기록한 거래·결제 내역으로 집계하며, 카드 단말기·은행 자동 대조가 이미 되는 것으로 표시하지 않습니다. 이 보고서는 운영용이며 세무 신고용 매출 인식 기준을 대신하지 않습니다.

## 매장 화면

간단 모드는 상단에 다음 숫자를 크게 표시합니다.

| 항목 | 정의 |
|---|---|
| 오늘 신규 확정액 | 오늘 확정한 대여·이용권 거래의 할인 후 금액 |
| 오늘 거래 조정액 | 기존 확정 건의 연장·추가·취소·가격 정정 증감 |
| 오늘 받은 대금 | 오늘 기록한 현금·카드·이체 등 고객 대금 수납 합계 |
| 오늘 환불액 | 오늘 실제로 돌려준 고객 대금 합계 |
| 오늘 대금 순수납 | 받은 대금 − 실제 환불액 |
| 마감 시점 미수금 | 마감 시점에 받을 돈이 남은 건의 합계 |
| 보증금 잔액 | 돌려줄 가능성이 있는 보증금의 미정산 잔액, 대금과 별도 |
| 물품 확인 대기 | 수거 후 매장 확인 대기·일부 반납·미반납 건수 |

자세한 모드에서는 결제수단별 내역, 상품별 확정액·할인액, 제휴업체별 내역, 미수금, 보증금, 현금 대조와 정정 이력을 펼칩니다. 각 숫자를 누르면 해당 거래 목록으로 이동하고 다시 대여 상세 화면을 열 수 있게 합니다.

## ‘하루’와 날짜 기준

매장별 시간대와 영업일 마감 시각을 설정합니다. 예를 들어 다음 날 새벽까지 영업한다면 00시에 무조건 다른 영업일로 바꾸지 않습니다. 실제 마감 경계는 매장 확인이 필요한 설정값입니다.

각 기록에는 발생 시각, 입력 시각, 귀속 영업일을 보관합니다. 지연 입력이나 정정이 있으면 그 사실을 표시합니다. 여러 기기의 시간을 신뢰해 임의로 마감일을 정하지 않고 서버 기준과 매장 설정을 사용합니다.

## 집계할 거래와 금전 기록

| 사건 | 대여 확정·조정 집계 | 대금 수납 집계 | 보증금 집계 |
|---|---|---|---|
| 견적 저장·인쇄 | 없음 | 없음 | 없음 |
| 대여 확정 | 할인 후 거래 금액 | 결제했을 때만 | 보증금을 받았을 때만 |
| 예약금·중도금·잔금 수령 | 중복 확정하지 않음 | 받은 날짜에 수납 | 없음 |
| 대여 기간 연장 | 확정된 추가 금액 | 추가로 받은 날짜에 수납 | 별도 변동 시만 |
| 취소·가격 감소 | 감소 조정 기록 | 실제 돌려준 시점에 환불 | 별도 변동 시만 |
| 기사님 수거 완료 | 없음 | 없음 | 없음 |
| 매장 반납 완료 | 없음 | 없음 | 실제 반환·정산 시만 |
| 보증금 수령·반환 | 없음 | 대여 대금에 섞지 않음 | 각각 입출금 기록 |

물품 완료 상태를 바꿨다고 결제를 자동 완료하거나 매출을 다시 생성하지 않습니다. 반납 시 자동으로 감사 문자를 보내지 않는 기존 기준도 유지합니다.

미수금은 각 거래의 확정·조정 후 청구액에서 연결된 대금 순수납액을 빼서 계산합니다. 음수 잔액은 미수금에서 상계해 숨기지 않고 ‘초과 수납·환불 대기’로 별도 표시합니다. 보증금은 직원이 정산 처리하지 않은 이상 대여 대금에 자동 충당하지 않습니다.

취소·금액 감소와 실제 환불은 별도 기록입니다. 예를 들어 100,000원을 모두 받은 거래를 90,000원으로 조정하면 10,000원 환불 대기가 생깁니다. 실제 10,000원을 환불한 뒤에 잔액이 0원이 됩니다. 환불만 기록하고 원거래 조정을 누락하면 다시 받을 돈처럼 보일 수 있으므로 연결된 조정 내역을 확인합니다.

## 단골·제휴업체 처리

‘가격을 할인받는 관계’와 ‘돈을 지불하는 주체’를 구분합니다.

| 사례 | 가격 기준 | 청구·수납 대상 |
|---|---|---|
| 단골 고객 | 선택한 단골 요금·추가 할인 | 고객 |
| 펜션 소개 고객이 직접 결제 | 해당 제휴 요금 | 고객 |
| 제휴업체가 나중에 일괄 결제 | 해당 제휴 요금 | 제휴업체 |

제휴업체 후불을 사용할 때는 대여 고객과 별도로 청구 대상 업체를 지정합니다. 업체가 한 번에 여러 건을 결제하면 금액을 해당 거래에 배분하고, 미배분 금액은 별도로 표시합니다. 상품 할인액과 업체 수수료·공급 원가는 다른 항목으로 두며 수수료 자동 공제는 실제 계약 규칙을 정한 뒤 구현합니다.

처음부터 고객 모두를 제휴 후불로 간주하지 않습니다. 매장의 실제 운영 여부를 설정에서 선택합니다.

## 타 스키샵 거래와 정산

타 스키샵과의 매입·판매·장비 대차도 기록하는 후속 화면은 [전체 화면 구성안의 거래처 장부](08-screen-map-and-expansion-plan.md#2-거래처-장부)에 정리합니다. 업체에 받을 돈과 줄 돈을 따로 집계하고 고객 미수와 구분합니다. 업체 거래 확정, 실제 수납·지급, 물품 인수·반환은 서로 다른 사건입니다.

업체에서 사온 리프트권 금액과 빌려온 장비 비용을 고객 매출에 더하지 않습니다. 업체 판매는 고객 판매와 구분해 한 번만 집계하고, 물품 입출고를 거래처 장부와 재고 화면에서 중복 등록하지 않습니다. 현금 수납·지급은 아래 현금 대조의 해당 입금·출금에 한 번만 포함합니다. 업체 간 상계는 실제 현금 이동이 없으므로 현금·이체 수납으로 잡지 않습니다.

마감의 받을 돈과 줄 돈은 각 거래의 잔액으로 표시합니다. 부분 정산·선입금·환불 대기·미배분 금액을 보존하며, 돈 정산을 완료해도 반환되지 않은 업체 장비는 별도 확인 목록에 남습니다.

## 할인과 상품별 보고

상품별로 정가 기준액, 단골·제휴 요금 적용 차액, 상품 추가 할인, 전체 할인 배분액, 최종 확정액을 보여줍니다. 전체 할인을 상품별로 배분했으므로 상품 합계가 전체 확정액과 일치해야 합니다.

리프트권 판매는 장비 대여와 별도 구분합니다. 공급가가 있는 경우 ‘판매가 − 등록 공급가’의 참고 차액을 계산할 수 있으나, 운영비·수수료를 모두 반영한 순이익으로 표시하지 않습니다. 공급가가 없으면 차액은 ‘미산정’으로 표시합니다.

## 현금 대조

현금 서랍의 예상액은 실제 현금 이동으로 계산합니다.

`예상 마감 현금 = 시작 시재 + 현금 대금 수납 − 현금 대금 환불 + 현금 보증금 수령 − 현금 보증금 반환 + 기타 기록된 현금 입금 − 기타 기록된 현금 출금`

마지막에 직원이 실제 현금을 입력하면 차이를 표시합니다. 은행 이체와 카드 결제는 현금 서랍 금액에 포함하지 않습니다. 매장 경비·은행 입금 등 현금 출금은 별도 사유로 기록합니다.

카드 결제 기록과 카드사가 은행에 입금한 금액은 수수료·정산일 등이 달라질 수 있으므로 같은 숫자로 취급하지 않습니다. 자동 대조를 붙이기 전에는 수동 대조 여부를 표시합니다.

## 3일 대여의 마감 예시

금액은 가상이며 [대여·가격 설계안의 350,000원 예시](02-rental-pricing-quotes.md)와 연결됩니다. 3일 대여 건을 첫날 확정하고 마지막 날 반납합니다.

| 구분 | 첫날 | 둘째 날 | 셋째 날 |
|---|---:|---:|---:|
| 신규 확정 대여·이용권 금액 | 350,000원 | 0원 | 0원 |
| 현금 대금 수납 | 100,000원 | 0원 | 0원 |
| 카드 대금 수납 | 200,000원 | 0원 | 0원 |
| 이체 대금 수납 | 0원 | 50,000원 | 0원 |
| 대금 순수납 | 300,000원 | 50,000원 | 0원 |
| 마감 시점 이 거래의 미수금 | 50,000원 | 0원 | 0원 |
| 현금 보증금 수령 | 20,000원 | 0원 | 0원 |
| 현금 보증금 반환 | 0원 | 0원 | 20,000원 |
| 보증금 잔액 | 20,000원 | 20,000원 | 0원 |
| 물품 상태 | 대여 중 | 대여 중 | 매장 확인 후 반납 완료 |

첫날 시작 시재가 50,000원이라면 예상 마감 현금은 170,000원입니다. 다른 현금 이동 없이 그대로 이월했다면 둘째 날 170,000원, 셋째 날 보증금 반환 후 150,000원입니다.

대여 기간이 3일이라고 동일한 350,000원을 매일 확정액에 더하지 않습니다. 향후 이용일별 실적 분석이 필요하면 금액을 배분한 별도 분석 지표를 만들며, 확정 거래·수납 집계와 혼합하지 않습니다.

## 마감 확정과 정정

마감 화면은 실시간 미리보기와 확정본을 구분합니다. 매장 관리 권한이 있는 직원이 결제 내역·현금 차이·미수·보증금·미반납을 확인하고 마감 확정합니다. 미수·미반납이 있다고 마감을 불가능하게 만들지는 않으며 다음 영업일의 확인 목록으로 넘깁니다.

마감 확정 시 대상 영업일, 집계 범위, 기준 시각, 거래 버전, 담당자와 요약값을 저장합니다. 확정 이후의 정정은 이전 마감본을 조용히 바꾸지 않고 연결된 조정 기록과 새 마감 버전을 남깁니다. 과거 자료를 열었을 때 당시 확정본과 최신 정정본을 구분할 수 있어야 합니다.

수납·환불·보증금 거래와 마감 확정은 중복 클릭으로 여러 번 기록되지 않도록 합니다. 실시간 숫자는 최신 자료가 반영된 상태인지 확인할 수 있게 마지막 갱신 시각을 표시합니다.
