## 2. 같은 템플릿을 유지한 방법

1. 공통 셸은 `pos-main-v1`의 앵커 P01(job `8d6e31bf-6f35-4a6b-bb11-65a3f1ab8ebc`)을 모든 화면의 첫 참조 이미지로 넣었다.
2. 셸이 다른 세 종류는 **기준 화면을 먼저 뽑아 직접 검수한 뒤** 그 job id를 나머지의 둘째 참조로 넣었다: 관리 = M01(레일 7개), 팝업 = P20(부모 화면 + 팝업 판), 기사 = D01(레일 없음 · 보라색 · 행 목록). 카드 목록은 P02R이 기준이다.
3. 팝업은 [부모 화면, 팝업 기준] 두 장을 참조로 준다. 부모 화면이 어둡게 깔린 채로 그려진다.
4. 프롬프트에는 `docs/38`에서 얻은 교훈을 처음부터 넣었다: 활성 메뉴는 "위에서 몇 번째 버튼", 헤더는 매장명·알림 종·나가기까지 "항상 완전", 작은 글자는 16px 그대로, 카드는 `docs/38` 7-5 배치(금액과 버튼 한 줄 · 쪽마다 제목 한 줄).
5. 카드 목록을 확정 배치로 다시 그린 P02R을 만들었다. `pos-main-v1`의 P05·P06·P08은 옛 배치(폭 전체 버튼 · 제목 2개) 그대로다.

## 4. 크레딧

33장 × 3 = **99 크레딧**. 워크스페이스는 개인 워크스페이스 그대로다(별도 선택 없음).

이 묶음 전후 잔액은 1,552 → 1,453(99)으로 장수와 정확히 맞는다. 직전 기록(1,617, `docs/38` 6-8)과의 차이 65는 이 세션에서 쓴 것이 아니다(같은 계정의 다른 작업). P10은 첫 제출이 서버 오류(503)로 접수되지 않아 과금 없이 한 번 다시 제출했다.

## 5. 메모 (구현으로 넘길 것)

1. **재생성 0장.** 33장 모두 레일·헤더·문구·배치에 구조 문제가 없었다. `docs/38`에서 배운 것(활성 메뉴를 "위에서 몇 번째"로, 헤더는 "항상 완전", 기준 화면 먼저)을 프롬프트에 처음부터 넣은 효과다.
2. **기록만 한 표기 결함**(재생성 안 함 · `docs/38` 6-3 기준): M02 헬멧 타일의 배지 한 곳 `헹상`(→ 정상), M03 헤더 알약 `정산 대거`(→ 정산 대기)와 카드 3열 배치(구현은 2열), P10 `발권처 환불` 카드가 배지 대신 보라 테두리, P25·P27·P33은 어둡게 깔린 배경 화면의 글자 일부가 뭉개짐, P30 날짜 칸의 팀 수 글자가 작음.
3. **그림은 크기를 보증하지 않는다.** 이번 시안도 글자와 바가 실제보다 작게 그려졌을 수 있다. 카드 목록은 `docs/38` 7절에서 실제 크기로 확인했지만, 나머지(팝업 · 새 접수 단계 · 관리 타일 · 기사 행 목록)는 구현할 때 같은 방식(`pos-main-v1/fit-check`)으로 1024×600 · 907×648에서 잰다. 특히 팝업은 780×480 안에 선택 버튼 3묶음 + 정보 줄 + 버튼 줄이 들어가는지 확인이 필요하다(P24).
4. **팝업 공통 규칙**(P20 기준): 제목은 `대표자 · 동작 수량`, 부제는 접수번호·일정 같은 사실만, 닫기는 오른쪽 위 48px, 주황 확정 버튼은 하나이고 오른쪽 끝, 수량은 −/+ 52px, 금액은 숫자판(P21·P29), 선택은 큰 버튼(선택 = 진한 채움). 알림 팝업(P32)만 주황 버튼이 없다.
