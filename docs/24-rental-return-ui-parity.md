# 렌탈·반납 통합 화면 원본 대조

2026-09-09. UI 개선 6의 `04 렌탈·반납 현황.dc.html`에 맞춰 목록, 상세의 네 탭, 반납 팝업을 통합했다. 원본의 HTML 배치와 수치, Pretendard 폰트 파일, Makaryo 색상 토큰을 사용한다. 공통 CSS의 줄높이, box-sizing, 검색 안내 글자 스타일이 덮어쓰지 않도록 이 화면에만 적용 범위를 지정했다.

`rentals`와 `returns`는 같은 목록을, `rental`과 `return-detail`은 같은 상세를 표시한다. 메뉴에는 **렌탈·반납 현황** 하나를 표시한다. 기존 포스/관리 전환, 스키노트 로고, 알림과 상단 메뉴는 유지했다.

## 서버에서 원본과 비교한 결과

원본은 58149 포트, 앱은 58148 포트에서 별도로 실행했다. Chrome, 브라우저 배율 100%, deviceScaleFactor 1에서 같은 데이터를 넣은 독립 테스트 컨텍스트로 비교했다. 원본과 실제 앱의 샘플 지급/반납 수량은 서로 다르므로 시각 검증용 데이터만 일치시켰으며, 앱의 샘플 수량을 디자인에 맞춰 변경하지 않았다.

목록의 시간별/빌린 순서, 일부 반납/완료/지연 필터, 빈 검색 결과, 상세 네 탭, 직접반납/예정 변경 팝업을 포함한 **48개 화면, 1,160개 요소**에서 좌표·크기·폰트·줄높이·자간·색상·여백·모서리·테두리 측정값 차이는 **0**이었다. 비교 범위는 목록/상세 본문과 팝업이며 기존 앱의 공통 메뉴·상단 바는 픽셀 비교 대상에 포함하지 않았다.

| 해상도 | 비교 화면 수 | 측정값 불일치 요소 | 최대 원시 픽셀 차이 |
| --- | ---: | ---: | ---: |
| 1366×768 | 12 | 0 | 0.00440% |
| 1024×768 | 12 | 0 | 0.00386% |
| 1440×900 | 12 | 0 | 0.00982% |
| 1920×1080 | 12 | 0 | 0.03781% |

픽셀 차이는 임계값으로 제거하지 않은 원시 PNG 차이로 기록했다. 둥근 모서리와 아이콘 가장자리에서 top-level 문서와 앱 iframe의 래스터 처리 차이가 남는다. 1366×768 기본 목록은 픽셀 차이 0, 1024×768 기본 반납 상세도 0이다. 전체 화면이 바이트 단위로 완전히 같다는 뜻은 아니다. 자동 검사 기준은 측정값 불일치 0, 원시 픽셀 차이 0.05% 이하, RGB 최대 채널 차이 40 이하이다.

## 기능과 다른 화면 확인

- 빌드·JavaScript 구문 검사 통과.
- 기존 기능 테스트 72개 통과.
- 통합 목록, 검색, 필터, 정렬, 직접반납, 차량 인수, 수량 정정, 품목/전체 일정 변경, 납품 예약의 반납 일정, 버전 충돌, 미지급 장비·권 지급, 키보드와 화면 이동 등 브라우저 검사 12개 통과.
- 기존 포스/관리 메뉴 이동 검사 6개 통과.
- 실제 데이터 화면은 1024·1366·1440·1920px와 390·360px에서 문서 가로/세로 넘침, 버튼 크기, 폰트 로드를 확인했다.
- 외부 변경 요청(POST 등) 0건. 실제 결제·환불·문자 발송 연결은 기존처럼 없다.

기존 `npm run test:visual`은 변경 전부터 현재 차량 화면에 없는 `[data-mode="detail"]` 선택자에서 중단된다. 변경 전 HEAD의 별도 빌드를 열어서도 해당 선택자가 없음을 확인했다. 이번 통합 화면의 시각 검증 결과는 별도의 `test:rental-parity`와 `test:rental-board` 결과이다.

반납 수량은 기존 공통 물품 원장을 사용한다. 직접반납 정정은 고객 보유로, 차량 인수 정정은 차량 보관으로 되돌린다. 초기 샘플의 단순 보관 기록에는 정정할 이동 이력이 없으므로 그 수량의 정정은 안내하고 막는다. 기간 연장·장비 교환·수납·환불·연락 양식은 기존 체험용 동작을 유지한다.
