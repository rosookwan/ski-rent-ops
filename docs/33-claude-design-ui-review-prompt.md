## 전달할 프롬프트

스키·보드 렌탈샵에서 사용하는 **SKINOTE 포스**의 현재 구현을 UI/UX 관점에서 검수해 주세요. 먼저 첨부한 화면과 실제 동작을 분석하고, 수정이 필요한 위치와 이유를 제시해 주세요. 이번 요청의 산출물은 검수 보고서와 핵심 수정안입니다.

운영자는 처음 쓰는 아르바이트 직원일 수 있습니다. 혼잡한 카운터에서 고객을 기다리게 하지 않고, ‘반납은 여기서 하면 되겠네’, ‘잘못 처리했으면 여기로 가면 되겠네’가 예측되어야 합니다. 화면의 미관뿐 아니라 **업무를 끝내기까지의 이동, 입력량, 오처리 위험, 예외에서의 복귀**를 중심으로 평가해 주세요.

### 반드시 유지할 업무 조건

1. 메뉴는 `오늘 할 일 → 1 접수·예약 → 2 준비·지급 → 3 이용 중·변경 → 4 반납·회수 → 5 정산·마감` 순서입니다. 차량 운행과 관리는 고정 진입점을 둡니다. 다른 메뉴를 거쳐도 같은 고객과 접수 맥락을 유지해야 합니다.
2. 한 팀의 **이번 방문**을 통합접수번호로 묶습니다. 이미 빌린 팀에 당일 늦게 오거나 다음날 오는 일행을 추가할 수 있고, 기존 일행에게 의류·장비·리프트권만 추가할 수도 있습니다. 새 방문을 이름이나 전화번호만으로 자동 합치지 않습니다.
3. 기존 일행과 추가 일행의 날짜·가격·물품·지급·반납을 각각 보존합니다. 내일 올 일행이 오늘 지급 대상에 섞여서는 안 됩니다. 추가분 취소가 첫날 대여와 수납을 되돌려서는 안 됩니다.
4. 대표자 정보는 한 번만 입력합니다. 일행은 실명 없이 번호로 접수할 수 있고, 단체 인원과 같은 품목을 한 번에 추가할 수 있습니다. 정상 전량 반납에는 타이핑을 요구하지 않습니다. 반복 입력은 기본값·선택·숫자판으로 줄입니다.
5. `실제 지급`, `현재 고객 보유`, `차량 보관`, `매장 확인`은 다른 수량입니다. 수거 약속과 실제 수거, 매장 입고를 혼동하면 안 됩니다. 1호 차량과 2호 차량의 입고 결과는 같아야 합니다.
6. 물품 반납, 대여료 수납/환불, 보증금 반환은 각각 처리합니다. 조기반납만으로 자동 환불하거나, 발권처 반환을 고객 환불로 표시하지 않습니다.
7. 교환품 전달과 기존품 회수, 분실품 발견과 정상 재고 복귀는 별도 상태입니다. 잘못된 기록은 연결된 후속 기록을 확인하며 정정합니다. 기록 삭제로 모든 상태를 초기화하지 않습니다.
8. 오래된 화면의 확정과 중복 클릭을 막고, 응답을 못 받은 요청은 같은 요청을 다시 확인합니다. 체험 저장, 운영 저장, 문자 링크 준비, 브라우저 인쇄 요청, 실제 종이 출력의 상태를 혼동하지 않게 표시합니다.

### 작은 포스의 필수 기준

- **실제 앱 표시 영역** `1024×600`, `1024×768`, `1366×768`에서 각각 검수해 주세요. 모니터 제품 해상도와 앱 표시 영역을 구분합니다.
- 핵심 고객·접수번호, 선택 대상·수량, 필요한 일정·금액, 취소·확정 버튼이 스크롤 없이 보여야 합니다. 가로 스크롤, 잘림, 화면 밖 확정 버튼, 중첩 스크롤로 문제를 숨기면 안 됩니다.
- 긴 목록은 페이지로 나누되 선택과 합계는 유지합니다. 30명·12종 품목·100건 이상 목록도 확인해 주세요.
- 일반 본문 18px, 보조 정보 16px, 보조 터치 영역 48px 이상, 주요 확정 버튼 56px 이상, 기사 주요 처리 버튼 72px 이상을 기준으로 확인해 주세요. 숫자판과 팝업을 연 상태도 포함합니다.
- 글자를 작게 만들거나 핵심 정보를 접어서 무스크롤을 달성하지 말아 주세요. 모든 요소를 한 화면에 나열하기보다 단계별로 필요한 정보를 남기는 방식으로 제안해 주세요.
- OS 키보드, 실제 프린터와 카드 단말, 현장 사용성은 스크린샷만으로 통과 판정하지 말아 주세요.

### 반드시 따라가 볼 과업

| 과업 | 확인할 지점 |
|---|---|
| 신규 팀 접수 → 준비 → 일부 먼저 지급 | 다음 버튼이 자연스러운지, 미지급이 남는지 |
| 이미 빌린 팀에 오늘 2명/내일 1명 추가 | 대표자 재입력 없이 찾아가는지, 날짜·추가 금액이 분명한지 |
| 기존 일행 의류 추가 | 새 일행 등록과 혼동하지 않는지 |
| 30명 번호 접수·동일 품목 등록 | 입력량, 페이지 이동, 선택·합계 보존 |
| 전량 반납 / 일부만 반납 | 이름·실물·수량 확인과 확정 위치, 남은 정산 안내 |
| 2호 차량 수거분 실제 입고 | 담당 차량·현재 보관·입고 완료의 구분 |
| 부재로 0개 수거 / 장소 변경 | 허위 이동 없이 다음 약속을 남기는지 |
| 교환품만 전달되고 기존품은 못 받은 상태 | 남은 회수 의무를 찾기 쉬운지 |
| 잘못 누른 지급·수거·입고 정정 | 어떤 기록부터 풀어야 하는지 이해되는지 |
| 일부 수납·추가분 수납·고객 환불·보증금 반환 | 범위와 실제 돈의 방향이 명확한지 |
| 미수·미반납·거래처 미정산을 남기고 마감 | 인계와 돈·물품의 구분, 반복 입력 여부 |
| 새 일행 사전입력·부분제출·준비표 재출력 | 요청 대상, 제출/직원 확인/현장 규격, 추가·변경 표시 |
| 연결 끊김·오래된 화면·처리 결과 불명 | 상태 설명과 바로 실행할 해결 버튼 |

### 검수 방식과 결과 형식

먼저 현재 구현에서 유지할 장점 3~5개를 짧게 정리한 뒤, 중요한 결함부터 보고해 주세요. 기능이 없다고 판단할 때는 관련 버튼·팝업·다음 화면까지 확인하고, 보이지 않음과 실제 미구현을 구분해 주세요.

각 결함은 아래 형식으로 작성해 주세요.

| 심각도 | 화면/표시 영역 | 실제 위치 또는 캡처 표시 | 관찰한 문제 | 직원이 실수할 구체적 상황 | 수정안 | 유지해야 할 업무 조건 | 재검수 방법 |
|---|---|---|---|---|---|---|---|

- P0: 다른 고객·수량·돈을 잘못 확정하거나 업무가 사라질 수 있음.
- P1: 정상 과업을 끝내기 어렵거나 핵심 내용·확정이 보이지 않음.
- P2: 위치 탐색·불필요한 입력·시각 우선순위로 지연됨.
- P3: 문구·정렬·간격 등 일관성 개선.

수정안에는 ‘더 직관적으로’ 같은 추상적 표현 대신 **어떤 버튼을 어디에 두고 어떤 이름으로 바꿀지, 어떤 정보를 어떤 단계에 남길지**를 써 주세요. 한 결함이 여러 화면에 반복되면 공통 규칙으로 묶어 주세요.

가장 중요한 화면 3개에 대해 `1024×600` 수정 와이어프레임 또는 주석 달린 화면을 제시해 주세요. 고객 요약·본문·고정 확정 영역의 높이와 버튼 크기도 적어 주세요. 현재 색상·폰트·아이콘 체계를 먼저 파악하고 일관되게 사용해 주세요.

마지막으로 **우선 수정할 5개**, 실제 초보 직원에게 확인할 질문, 실행 환경이 없어 확인하지 못한 항목을 구분해 주세요. 가능하면 처음 사용하는 직원이 메뉴 설명 없이 해당 과업을 시작할 위치를 예측할 수 있는지 평가해 주세요. 실제 사람을 관찰하지 않았다면 사용자 테스트를 통과했다고 쓰지 말아 주세요.
