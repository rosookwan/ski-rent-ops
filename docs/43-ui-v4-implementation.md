## 1. 결과 요약

- 힉스필드 시안 46장(포스 9 + 나머지 33 + 기사 휴대폰 4)을 실제 앱으로 옮겼다. 기능·저장 동작·확정 버튼 문구는 그대로이고 화면 배치와 크기 기준이 바뀌었다.
- 기준: 글자 16px 이상(본문 18 · 제목 22 · 숫자 26~40), 누르는 곳 52px 이상(주 버튼 56, 기사 56/72, 휴대폰 확정 64), 레일 112px(폭 1000px 미만 96px), 헤더·필터 줄 60px, 하단 72px.
- **글자를 자르지 않는다.** 한 줄에 안 들어가면 낮은 순위 조각을 통째로 빼고(품목은 `외 N종`), 이름은 두 줄 → 그래도 넘치면 뒤 낱말을 뺀다. 말줄임표를 쓰지 않는다.
- **스크롤하지 않는다.** 목록은 화면 높이로 쪽을 나누고 쪽수는 하단 바에 둔다. 반쯤 잘린 카드·행이 나오지 않는다.
- 화면 규칙 다섯 가지를 촬영과 업무 검사 도중에 같이 센다. **154곳(포스 촬영 60 + 기사 촬영 11 + 업무 검사 83 · M9 포함) 모두 0건**이고, 0건이 아니면 `npm run pos:rules`가 실패한다.

| 규칙 | v3(기준선) | v4 |
|---|---:|---:|
| ① 16px 미만 글자 | 1,354 | 0 |
| ② 잘린 글자(버튼 밖으로 넘친 글자 포함) | 6 | 0 |
| ③ 반쯤 잘린 카드·행 | 99 | 0 |
| ④ 낮은 누르는 곳 | 631 | 0 |
| ⑤ 허용 안 된 스크롤 | 36 | 0 |

v3 값은 57장 기준(`docs/pos-ui-v4/baseline.json`), v4는 154곳 기준이다(M8까지는 142곳).

## 4. 시안과 다르게 간 곳

`docs/42` 7절에 표로 정리했다. 요점: 카드의 금액과 버튼은 한 줄, 낮은 화면에서는 묶음 제목 한 줄, 정산·마감은 행 전체가 누르는 곳, 새 접수의 `예약·방문`·`임시 저장`은 자료에 없어 넣지 않음, 3단계는 이름표 + 버튼 한 줄 × 5줄, 접수 상세는 같은 품목·날짜를 한 장으로 묶음, 창의 확정 버튼 문구는 지금 앱의 문구.

A4는 업무 검사를 통과했지만 **시안 일치는 미완료**다. 사용자가 비교 그림의 차이를 지적한 뒤 추가 작업 중단과 사유 기록을 요청했다. 업무상 필요한 차이와 미구현 범위·모양 차이는 [`docs/51`](51-pos-ui-design-differences.md)에 구분했다. 화면 코드는 `aa1dae6` 상태로 마무리했으며 A5 기사 업무 처리·차량 보관은 미착수다. 지급·반납 A1(`docs/47`), 변경·교환·문제 해결 A2(`docs/48`), 발권·마감·사이즈·알림 A3(`docs/49`), 관리 상세 A4(`docs/50`)는 작업 브랜치에 있고 main 반영 확인 대기다.

## 5. 검증 스크립트가 바뀐 곳

- `smoke-pos-operating.cjs` · `smoke-pos-keypad.cjs`: 단가·수량·할인은 `직접 입력` 창에서 넣는다(`pos-line-detail`). 새 접수 저장 뒤 `접수 완료` 창을 닫는다. 일행이 있는 팀에 추가하면 새 일행 1명이 기본이라 `pos-person-add`를 누르지 않는다.
- `capture-pos-release.cjs`: 출력이 `docs/pos-ui-v4`, 크기에 907×648 추가, 새 접수 3장과 접수 완료 촬영 추가, 12종 품목은 실제 12종 접수를 연다.
- `capture-pos-driver.cjs`: 휴대폰 360×640 · 390×740 · 412×780과 처리·방문 결과·차량 보관 추가. 줄 수 검사 — 태블릿 3줄@1024×520 · 4줄@1024×600(그대로), 휴대폰 4줄@360×640(새로).
- 업무 검사 5종에 `recorder()`를 걸어 지나가는 화면·창마다 규칙을 잰다(`work/pos-rules/*.json`).
- 높이·글자 기준을 48px → 52px로 올림(`smoke-pos-management.cjs` · `smoke-pos-keypad.cjs`).

입력 이름·동작 이름·확정 버튼 문구(`docs/42` 부록 A)는 바꾸지 않았다.

## 6. 다시 확인하는 방법

```bash

npm run test:pos:operating && npm run test:pos:fulfillment && npm run test:pos:tickets && npm run test:pos:management && npm run test:pos:preinput && npm run test:pos:keypad
```

## 8. 예전 화면 코드 정리와 번들 한도 (2026-09-21)

새 포스 화면이 같은 경로를 나중에 등록해 덮어쓰기 때문에(`core.js`의 `register`는 마지막 등록이 이긴다) **어디서도 도달할 수 없던 예전 화면**을 지웠다. 지우기 전에 파일마다 등록 경로 · 내보내는 값 · 포스 쪽 의존을 조사했다.

| 지운 것 | 크기 |
|---|---:|
| 예전 화면 9개: `rentals.js` · `settings.js` · `partners.js` · `closing.js` · `preparation.js` · `rental-board.js` · `dispatch-board.js` · `vehicle-board.js` · `rental-changes.js` | 215,712 |
| 그 화면의 틀과 스타일: `rental-board.html` · `dispatch-board.html` · `vehicle-board.html` · 같은 이름의 CSS 3개 · `operations.css`, 빌드 보조 `scripts/rental_template.py` | 109,481 |
| 렌더링되지 않던 예전 접수 시안 `design/prototypes/first-look.fragment.html`과 셸의 연결 코드(`core.js` · `build.py` · `check.py`) | 125,618 |
| 그 시안만 쓰던 선택자(`.ski-*` · `#ski-first-look` · `#so-legacy`) 440개 규칙 — `styles.css` · `polish.css` · `responsive.css` · `workflows.css` · `notifications.css` | 약 47,500 |
| 예전 화면만 누르던 검사 스크립트 26개와 `package.json`의 실행 항목 18개 | — |

- **번들 1,632,437 → 1,110,342바이트(−522KB · −32%).** 크기 검사(`scripts/build.py`)는 1,750,000 → **2,000,000**으로 올리고, 넘으면 실제 크기를 알려 주게 했다. 이 값은 실수로 불어나는 것을 잡는 장치이지 플랫폼 제한이 아니다.
- CSS는 선택자 단위로 지우는 스크립트를 썼고, **남아야 할 선택자 집합이 지우기 전후로 같은지**를 파일마다 확인한 뒤에만 저장했다(주석 안의 쉼표를 선택자로 잘못 읽는 문제를 이 확인이 잡아냈다).
- 남긴 것(아직 쓰임): `login.js`(체험판 첫 화면) · `guide.js`(고객 안내 · QR 안내판) · `workflow-preparation.js` + `workflow-ui.js`(고객 사이즈 입력폼) · `notifications.js` · `returns.js` · `operations.js` · `time-picker.js` · 공용 스타일. 이 안에도 안 쓰는 부분이 약 150KB 남아 있다(예: `workflow-ui.js`의 예전 업무 화면 · 예전 알림함). 서로 얽혀 있어 이번에는 건드리지 않았다.
- 확인: 업무 검사 6종 · `test:pwa`(포스 레일 기준으로 고침 · 6항목) · 단위 180 · 반납 25 · 알림 18 · `check` 통과, 촬영 60 + 기사 11 + 업무 검사 83 = 규칙 154곳 0건, 로그인 · 고객 안내 · 고객 입력폼 · QR 안내판 창을 직접 열어 확인.

## 11. 후속 A2 기간·수거 변경·교환·문제 해결 (2026-09-21)

P24·P25·P26에 맞춰 날짜·장소·시간 선택과 달력, 실제 재고 규격 버튼, 문제 해결 여섯 선택지를 붙였다. Pretendard·공용 글자 크기와 기존 확정 문구를 유지했다. 교환의 요청·지급·회수와 정정의 실제 기록 확인은 기존 업무 절차다. 긴 목록은 쪽을 나누고 오류 안내도 겹치지 않게 확인했다.

구현·비교 그림·검사 근거는 [`docs/48`](48-pos-adjustments-ui.md). 업무 검사 6종(지급/반납/변경 24개)·단위 180·반납 25·알림 18·PWA 6·check·빌드 통과, 화면 규칙 195곳 모두 0건. 번들 1,136,213바이트.

새 파일은 `pos-adjustment-forms.js` · `pos-problem-picker.js` · `pos-adjustments.css`. `smoke-pos-fulfillment.cjs`에 A2 업무 다섯 검사를 추가했고, `capture-pos-adjustments.cjs`는 5개 크기 × 4화면과 시안 비교 세 장을 만든다. `feat/pos-ui-v4`의 후속 변경이며 **main·Pages 반영은 확인 대기**다.

## 12. 후속 A3 발권·마감·사이즈 입력·알림 (2026-09-21)

P27·P28·P14·P31·P32에 맞춰 발권 수량·요약, 정산 화면 위의 마감 3단계, 팀별 사이즈 현황·집계, 일행 입력 요청, 업무 알림을 정리했다. 기존 글꼴·공용 크기·확정 문구를 유지했다. 대표자 접수는 개인별 입력을 요구하지 않고 준비표로 이어진다. 실제 발권/고객 지급, 고객 제출/매장 적용, 링크 준비/문자 발송을 구분한다.

## 13. 후속 A4 재고·정비·거래처·고객 상세 (2026-09-21)

M02에 맞춰 재고를 실제 품목 타일 → 실물 목록으로, M04와 P04의 공용 좌우 배치에 맞춰 거래처·고객 상세를 정리했다. 기존 글꼴·공용 크기·실물 선택과 확인을 유지했다. 거래처 약정/실제 입출금/미정산, 고객의 현재 연락처/방문 당시 접수는 각각 보존한다. 자료에 없는 담당자·대여 단가·전화/인쇄 기능은 추가하지 않았다.

구현·비교 그림·검사 근거는 [`docs/50`](50-pos-management-details-ui.md). 업무 검사 6종·단위 180·반납 25·알림 18·PWA 6·check·빌드 통과, 화면 규칙 **291곳 모두 0건**. 번들 1,163,255바이트. A4 다섯 크기 45장과 다음 쪽 2장, 시안 비교 3장을 기록했다. 고객 상세는 전용 시안이 없어 접수 상세의 배치를 기준으로 삼았음을 비교 그림에 표시했다.
