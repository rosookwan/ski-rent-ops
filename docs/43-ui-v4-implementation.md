## 1. 결과 요약

- 힉스필드 시안 46장(포스 9 + 나머지 33 + 기사 휴대폰 4)을 실제 앱으로 옮겼다. 기능·저장 동작·확정 버튼 문구는 그대로이고 화면 배치와 크기 기준이 바뀌었다.
- 기준: 글자 16px 이상(본문 18 · 제목 22 · 숫자 26~40), 누르는 곳 52px 이상(주 버튼 56, 기사 56/72, 휴대폰 확정 64), 레일 112px(폭 1000px 미만 96px), 헤더·필터 줄 60px, 하단 72px.
- **글자를 자르지 않는다.** 한 줄에 안 들어가면 낮은 순위 조각을 통째로 빼고(품목은 `외 N종`), 이름은 두 줄 → 그래도 넘치면 뒤 낱말을 뺀다. 말줄임표를 쓰지 않는다.
- **스크롤하지 않는다.** 목록은 화면 높이로 쪽을 나누고 쪽수는 하단 바에 둔다. 반쯤 잘린 카드·행이 나오지 않는다.
- 화면 규칙 다섯 가지를 촬영과 업무 검사 도중에 같이 센다. **142곳(포스 촬영 55 + 기사 촬영 11 + 업무 검사 76) 모두 0건**이고, 0건이 아니면 `npm run pos:rules`가 실패한다.

| 규칙 | v3(기준선) | v4 |
|---|---:|---:|
| ① 16px 미만 글자 | 1,354 | 0 |
| ② 잘린 글자(버튼 밖으로 넘친 글자 포함) | 6 | 0 |
| ③ 반쯤 잘린 카드·행 | 99 | 0 |
| ④ 낮은 누르는 곳 | 631 | 0 |
| ⑤ 허용 안 된 스크롤 | 36 | 0 |

v3 값은 57장 기준(`docs/pos-ui-v4/baseline.json`), v4는 142곳 기준이다.

## 4. 시안과 다르게 간 곳

`docs/42` 7절에 표로 정리했다. 요점: 카드의 금액과 버튼은 한 줄, 낮은 화면에서는 묶음 제목 한 줄, 정산·마감은 행 전체가 누르는 곳, 새 접수의 `예약·방문`·`임시 저장`은 자료에 없어 넣지 않음, 3단계는 이름표 + 버튼 한 줄 × 5줄, 접수 상세는 같은 품목·날짜를 한 장으로 묶음, 창의 확정 버튼 문구는 지금 앱의 문구.

배치를 그대로 둔 곳(규칙은 0건): 지급·반납·교환·기간 변경·문제 해결 화면과 확인 창, 발권·마감 확정·사이즈 요청·업무 알림 창, 재고·정비(M02), 거래처 상세(M04), 고객 상세, 매장 설정(M06). 시안과의 남은 차이는 모양뿐이라 다음 작업으로 넘긴다.

## 5. 검증 스크립트가 바뀐 곳

- `smoke-pos-operating.cjs` · `smoke-pos-keypad.cjs`: 단가·수량·할인은 `직접 입력` 창에서 넣는다(`pos-line-detail`). 새 접수 저장 뒤 `접수 완료` 창을 닫는다. 일행이 있는 팀에 추가하면 새 일행 1명이 기본이라 `pos-person-add`를 누르지 않는다.
- `capture-pos-release.cjs`: 출력이 `docs/pos-ui-v4`, 크기에 907×648 추가, 새 접수 3장과 접수 완료 촬영 추가, 12종 품목은 실제 12종 접수를 연다.
- `capture-pos-driver.cjs`: 휴대폰 360×640 · 390×740 · 412×780과 처리·방문 결과·차량 보관 추가. 줄 수 검사 — 태블릿 3줄@1024×520 · 4줄@1024×600(그대로), 휴대폰 4줄@360×640(새로).
- 업무 검사 5종에 `recorder()`를 걸어 지나가는 화면·창마다 규칙을 잰다(`work/pos-rules/*.json`).
- 높이·글자 기준을 48px → 52px로 올림(`smoke-pos-management.cjs` · `smoke-pos-keypad.cjs`).

입력 이름·동작 이름·확정 버튼 문구(`docs/42` 부록 A)는 바꾸지 않았다.

## 6. 다시 확인하는 방법

```bash
npm run build
npm run test:pos:operating && npm run test:pos:fulfillment && npm run test:pos:tickets && npm run test:pos:management && npm run test:pos:preinput && npm run test:pos:keypad
npm run dev            # 다른 터미널에서 (포트 58148)
npm run pos:rules      # 포스 촬영 + 규칙 검사
npm run pos:screens:driver && node scripts/check-pos-ui-rules.cjs
npm run check && npm run test:workflows:unit
```

Pages CI는 업무 규칙과 문법·빌드만 확인하고 화면은 보지 않는다. 화면 검사는 위 명령을 로컬에서 돌린다.

## 7. 남은 확인 사항

1. **공개 체험판(`main` · Pages) 반영은 아직 하지 않았다.** 반영 전에 결과 화면을 보고 확인을 받기로 했다(`docs/42` 10절 2번).
2. 매장 포스의 실제 표시 영역: `관리 → 매장 설정 → 매장 정보` 아래 `이 화면 크기 W×H`를 읽어 알려 주면 그 크기를 촬영 기준에 넣는다(`docs/42` 10절 6번).
3. 번들 1,594,581바이트(한도 1,750,000의 91.1%). 새 기능을 넣을 때 남은 여유는 약 155KB다.
4. 배치를 그대로 둔 화면(4절)의 모양 맞추기.
5. `npm run test:navigation`과 `npm run test:pwa`는 이 작업과 무관하게 `main`(`1d1ae7f`)에서도 실패한다(예전 셸의 메뉴 목록·설치 안내를 보는 검사가 v3 포스 셸 이후 갱신되지 않음). v4에서 새로 깨진 검사는 없다. 따로 고칠 일로 남긴다.
