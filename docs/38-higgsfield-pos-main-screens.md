# 38. 힉스필드 시안 요청 · POS 메인 화면 1라운드 (2026-09-20)

UI v3(`docs/37-ui-v3-implementation.md`)를 기준으로 POS 화면 전체를 다시 다듬는다. 이번 문서는 그 첫 라운드로, **포스 메인 화면 8개**를 나눠 힉스필드(이미지 생성)에 요청하는 요청서다. 요청 본문(프롬프트)은 `design/higgsfield/pos-main-v1/requests.json`에 화면별로 들어 있고, 라이브러리 규칙은 `design/higgsfield/README.md`에 있다.

## 1. 사용자 요구 5가지 → 시안 규칙

| 요구 | 프롬프트에 넣은 규칙 |
|---|---|
| 포스에서 쓰기 편할 것 | 터치 대상 52px 이상, 주 버튼 56px, 화면마다 주황 주 버튼은 한 종류. 카드마다 다음 동작 버튼 하나. 아이콘만 있는 버튼은 알림 종뿐 |
| 낮은 해상도에서 글자 잘림 0 | 설계 프레임 1024×600 고정. 말줄임표(…) 금지, 길면 두 줄로 줄바꿈. 카드는 온전한 것만 보이고 반쯤 잘린 카드 금지 |
| 스크롤 최대한 없애기 | 오늘 할 일은 6타일(3×2)로 고정. 목록은 2×2 카드 또는 5~7행이 한 화면에 들어가고, 더 있으면 하단 바의 쪽수(‹ 1/2쪽 ›)로 넘김. 정산·마감은 7건을 48px 행으로 한 번에 |
| 한눈에 보기 | 핵심 숫자 32~40px, 이름·제목 22px, 상태는 색+글자 배지, 주의 카드는 2px 테두리와 테두리 위 상태 글자 |
| 나이 있는 사용자 | 최소 글자 16px, 본문 18px, 진한 글자(#1A1A1A)와 밝은 배경, 16px 간격, 표준 업무 용어(지급·반납·미수·발권)만 사용 |

## 2. 현재(v3) 촬영본에서 본 문제와 이번 시안 방향

| v3 관찰 (1024×600 촬영본) | 이번 시안 |
|---|---|
| 오늘 할 일 9장 카드가 두 줄을 넘어 세 번째 줄이 잘림 | 6개 큰 타일(3×2)로 한 화면 고정. 차량 운행·관리는 레일과 하단 버튼으로 |
| 목록 화면마다 두 번째 줄 카드가 절반만 보임(접수·준비·반납·정산 모두) | 카드 높이 ~170px 고정, 온전한 카드 4장(2×2)만 표시, 쪽수는 하단 바 |
| 레일 라벨 14px, 메타 15px, 배지 14px | 최소 16px, 본문 18px, 레일 112px(라벨 16px, 아이콘 26px) |
| `열기`·`지급` 버튼이 연주황 배경에 주황 글자라 대비가 낮음 | 주 동작은 주황 배경+흰 글자, 보조는 흰 배경+진한 테두리 |
| 필터 줄에 검색 + 칩 5~6개 + 정렬 두 개가 빽빽함 | 검색 + 칩 3개(오늘/내일/전체) + 달력 + 정렬 토글 하나, 칩 52px |
| 새 접수 품목 단계가 드롭다운·텍스트 입력·숫자판 버튼 | 큰 품목 버튼 격자(3×3) + −/+ 스테퍼 + 합계 고정 패널 |
| 접수 상세의 오른쪽 품목 카드가 잘리고 안내 토스트가 버튼을 가림 | 품목을 96px 행 카드 3개로, 왼쪽 요약+버튼 6개(2열) 고정 |
| 정산·마감이 카드 2장만 보이고 나머지는 스크롤 | 수납 대기 7건을 48px 행으로 한 번에 + 오른쪽 `오늘 마감 준비` 숫자·체크리스트 |

유지하는 것: 96→112px 아이콘 레일(9개 고정, 관리는 맨 아래), 56→60px 헤더, 72px 하단 바, 브랜드 주황 `#FE4E10`, 상태색 5종, Pretendard 계열 글꼴, Lucide 계열 아이콘, 표준 용어(`docs/35` 4절).

다음 라운드 후보(이번 범위 밖): 리프트권, 차량 운행(포스), 관리 허브, 팝업(수납 숫자판·지급 수량·반납 확인), 기사 태블릿.

## 4. 생성 방법

1. **앵커**: P01을 먼저 생성한다(2장 만들어 규칙에 맞는 쪽을 고른다). 검수: 레일 9개 라벨이 다 보이는가, 6타일이 모두 온전한가, 글자 오탈자, 숫자 크기.
2. **참조 생성**: 나머지 8장은 고른 P01의 job id를 `image_references`로 넘겨 한 번에 배치 생성한다. 프롬프트마다 "참조 이미지의 레일·헤더·하단·색·글자를 그대로 유지"를 명시했다.
3. **검수 기준**: (a) 잘린 글자·말줄임표 0, (b) 반쯤 잘린 카드 0, (c) 지정한 한글 문구 그대로, (d) 최소 글자 16px 상당, (e) 주황 주 버튼 한 종류. 어긋난 화면만 같은 프롬프트로 다시 생성한다(장당 3 크레딧).
4. **저장**: 결과 PNG를 `design/higgsfield/pos-main-v1/`에 내려받고 `results.json`(job id · URL · 파일명)과 `index.html`을 만든다. 이 문서 6절에 결과와 판단을 적는다.

설정: `gpt_image_2_5` · quality `high` · resolution `2k` · 비율 `27:16` · 장당 3 크레딧 (잔여 1,734).

## 5. 힉스필드 라이브러리 분리 (결정 필요)

힉스필드 MCP에는 폴더·라이브러리를 만드는 도구가 없고, 계정에는 이름 없는 개인 워크스페이스 1개만 있다(`design/higgsfield/README.md` 1절). 그래서 저장소 쪽 라이브러리 폴더 + 화면 안 `스키노트` 워드마크 + 프롬프트 첫 문장 + job id 등록부로 분리한다. 힉스필드 안에서도 완전히 나누려면 사이트에서 이 프로젝트용 워크스페이스를 만든 뒤 `select_workspace`로 전환해 생성해야 한다(크레딧은 워크스페이스별).
