# 38. 힉스필드 시안 요청 · POS 메인 화면 1라운드 (2026-09-20)

UI v3(`docs/37-ui-v3-implementation.md`)를 기준으로 POS 화면 전체를 다시 다듬는다. 이번 문서는 그 첫 라운드로, **포스 메인 화면 8개**를 나눠 힉스필드(이미지 생성)에 요청하는 요청서다. 요청 본문(프롬프트)은 `design/higgsfield/pos-main-v1/requests.json`에 화면별로 들어 있고, 라이브러리 규칙은 `design/higgsfield/README.md`에 있다.

## 1. 사용자 요구 5가지 → 시안 규칙

| 요구 | 프롬프트에 넣은 규칙 |
|---|---|
| 포스에서 쓰기 편할 것 | 터치 대상 52px 이상, 주 버튼 56px, 화면마다 주황 주 버튼은 한 종류. 카드마다 다음 동작 버튼 하나. 아이콘만 있는 버튼은 알림 종뿐 |
| 낮은 해상도에서 글자 잘림 0 | 설계 프레임 1024×600 고정. 말줄임표(…) 금지, 길면 두 줄로 줄바꿈. 카드는 온전한 것만 보이고 반쯤 잘린 카드 금지 |
| 스크롤 최대한 없애기 | 오늘 할 일은 6타일(3×2)로 고정. 목록은 2×2 카드 또는 5~7행이 한 화면에 들어가고, 더 있으면 하단 바의 쪽수(‹ 1/2쪽 ›)로 넘김. 정산·마감은 7건을 48px 행으로 한 번에 |

## 4. 생성 방법

1. **앵커**: P01을 먼저 생성한다(2장 만들어 규칙에 맞는 쪽을 고른다). 검수: 레일 9개 라벨이 다 보이는가, 6타일이 모두 온전한가, 글자 오탈자, 숫자 크기.
2. **참조 생성**: 나머지 8장은 고른 P01의 job id를 `image_references`로 넘겨 한 번에 배치 생성한다. 프롬프트마다 "참조 이미지의 레일·헤더·하단·색·글자를 그대로 유지"를 명시했다.
3. **검수 기준**: (a) 잘린 글자·말줄임표 0, (b) 반쯤 잘린 카드 0, (c) 지정한 한글 문구 그대로, (d) 최소 글자 16px 상당, (e) 주황 주 버튼 한 종류. 어긋난 화면만 같은 프롬프트로 다시 생성한다(장당 3 크레딧).
4. **저장**: 결과 PNG를 `design/higgsfield/pos-main-v1/`에 내려받고 `results.json`(job id · URL · 파일명)과 `index.html`을 만든다. 이 문서 6절에 결과와 판단을 적는다.

설정: `gpt_image_2_5` · quality `high` · resolution `2k` · 비율 `27:16` · 장당 3 크레딧 (잔여 1,734).

## 5. 힉스필드 라이브러리 분리 (결정 필요)

힉스필드 MCP에는 폴더·라이브러리를 만드는 도구가 없고, 계정에는 이름 없는 개인 워크스페이스 1개만 있다(`design/higgsfield/README.md` 1절). 그래서 저장소 쪽 라이브러리 폴더 + 화면 안 `스키노트` 워드마크 + 프롬프트 첫 문장 + job id 등록부로 분리한다. 힉스필드 안에서도 완전히 나누려면 사이트에서 이 프로젝트용 워크스페이스를 만든 뒤 `select_workspace`로 전환해 생성해야 한다(크레딧은 워크스페이스별).

### 6-3. 검수 방법 (2026-09-21)

- 원본을 구역별로 1:1 크기로 잘라 문구를 읽고, 글자 크기는 픽셀로 쟀다. 원본 2592px은 1024px 프레임의 2.531배이므로, 같은 배율로 그린 실제 한글의 글자 높이(16px 굵게 = 36px, 18px = 40px, 22px = 50px)를 기준으로 삼았다. 숫자만 있는 줄은 숫자 높이(글자 크기의 0.72배)로 환산했다. 오차는 ±0.5px 정도다.
- **재생성 기준(사용자 지시, 2026-09-21)**: 고객 이름·전화번호·금액·매장명 같은 샘플 데이터의 오탈자·누락은 기록만 하고 재생성하지 않는다. 크레딧은 구조 문제(레일 메뉴 오류, 잘린 카드, 말줄임표, 글자 크기, 주황 버튼 난립, 메뉴·버튼·상태 같은 업무 용어 오기)에만 쓴다.
- 4절에는 "같은 프롬프트로 다시 생성"이라고 적었지만, 같은 실수가 되풀이되지 않도록 **발견한 문제만 프롬프트 끝에 덧붙여** 다시 만들었다. 한글 문구와 설정 값은 바꾸지 않았고, 덧붙인 문단은 `requests.json`의 `promptRevision`에 적었다.

### 7-4. 실제 크기 검사 (`design/higgsfield/pos-main-v1/fit-check/`)

힉스필드 그림은 글자와 바를 실제보다 작게 그린다(6-7의 1). 그래서 P02 카드 목록을 **요청서의 글자 크기 그대로**(이름 22px · 메타 16px · 품목 18px · 금액 18px · 버튼 52px, Pretendard) HTML로 그려 픽셀로 쟀다. `fit-check/index.html?w=1024&h=600&groups=1`처럼 크기와 묶음 수를 바꿔 연다(`design/` 폴더를 정적 서버로 열어야 글꼴이 붙는다). `design/app` 코드는 아니다.

**발견 1 · 시안 배치 그대로는 1024×600에 안 들어간다.** 이름/메타/품목/금액 네 줄 아래 폭 전체 버튼(52px)을 두면 카드가 약 203px라서, 품목이 3종뿐이어도 2×2 아랫줄이 55px 잘린다. **금액과 버튼을 한 줄에**(왼쪽 금액, 오른쪽 56% 버튼) 놓고 카드 안쪽 여백을 14px로 하면 171px가 되어 들어간다. 글자 크기와 52px 버튼은 그대로다.

**발견 2 · 품목은 한 줄에 몇 종까지 들어가나.** 품목 줄은 상태 칩(`차량 수거 예정`, 108px)과 같은 줄을 쓴다.

### 7-5. 카드 규칙 (글자를 자르지 않는다)

1. 카드 높이는 고정이다(171px = 이름 줄 + 메타 줄 + 품목 줄 + [금액 | 버튼 52px] 줄, 안쪽 여백 14px, 줄 간격 4px). 모든 줄은 **한 줄**이고 줄바꿈·말줄임표를 쓰지 않는다.
2. 자리가 모자라면 **덜 중요한 조각부터 통째로 뺀다.** 빠진 내용은 접수 상세에서 본다.
   - 이름 줄: 팀 이름은 늘 다 보인다. 전화번호는 자리가 있을 때만 옆에 둔다.
   - 메타 줄: `시간 → 장소 → 이용일 → 접수번호` 순으로 들어가는 만큼. 장소가 시간 옆에 안 들어가면 날짜를 뺀 시간(`10:00 수령`)으로 줄여 다시 맞추고, 그래도 안 되면 장소만 둔다(시간대는 묶음 제목에 있다).
   - 품목 줄: 들어가는 종류까지만 적고 **`외 N종`** 으로 끝낸다. 예: `스키 2 · 의류 2 · 헬멧 1 · 보드 1 외 8종`. 하나도 안 들어가면 `품목 12종`.
   - 검색창 안내문과 하단 요약도 같은 방식이다(`이름 · 연락처 뒷자리 · 접수번호` → `이름 · 연락처 · 접수번호` → …, 하단 요약은 뒤쪽 항목부터 뺀다).
3. 조각을 뺄지는 **그 자리의 실제 폭으로 재서** 정한다(글자 수로 어림하지 않는다). 창 크기가 바뀌면 다시 잰다.
4. **쪽 나눔은 높이로 계산한다.** 목록 영역에 묶음 제목(34px)과 카드 줄(171 + 12px)을 위에서부터 채우고, 온전히 안 들어가는 줄은 다음 쪽으로 넘긴다. 반쯤 잘린 카드는 어떤 자료에서도 나오지 않는다.
5. 1000px보다 좁은 창에서는 레일을 v3의 96px로 둔다(16px 라벨 9개가 그대로 들어간다).

### 7-6. 남은 결정

- **묶음 제목이 2개인 쪽 (1024×600)**: 제목 2개 + 카드 두 줄은 426px가 필요한데 목록 영역은 392px다. 7-5의 4번대로면 첫 쪽에 앞 묶음 2장만 보이고 나머지는 빈다(2 준비·지급, 4 반납·회수, 3 이용 중·변경에서 생긴다). 대안은 **높이 640px 미만에서는 쪽마다 제목을 한 줄만** 두고(그 쪽에 보이는 시간대를 함께 적음: `09:00~12:00 · 12:00~17:00 수령`) 카드 4장을 채우는 것이다. 구현 전에 정한다.
- 시안 P05·P06·P08은 제목 2개 + 카드 3~4장을 1024×600에 그렸지만, 위 계산대로 실제 크기에서는 들어가지 않는다. 배치 참고용으로만 본다.
