# 매장 POS 화면 구성과 확장 계획

작성일: 2026-09-07 · 문서 버전: 0.8

상태: 사용자 요청과 공개 제품 자료를 반영한 기능 설계안입니다. 0.9에서 이 설계를 바탕으로 주요 메뉴를 클릭 가능한 화면 시안으로 연결했습니다. 아래의 실제 저장·정산·문자 발송·자동 동기화 규칙은 후속 개발 범위입니다. 현재 화면 구현과 검증 결과는 [화면 체험과 검증 기록](09-clickable-demo-and-validation.md)을 기준으로 합니다.

## 1. 구성 방향

첫 화면은 **오늘 현황**으로 하고, **새 대여 접수**는 언제든 누를 수 있는 주요 버튼으로 둡니다. 카운터는 오늘 처리할 일부터 보고, 예약·대여·물품·돈의 기록을 다시 입력하지 않고 연결해서 사용합니다.

매장은 기존 밝은 POS 디자인을 이어갑니다. 차량은 기존 태블릿 디자인과 간단·자세한 모드를 유지하며, 거래처 장부·원가·관리자 설정은 카운터에서 사용합니다. 고객의 사전 입력과 QR 안내는 휴대폰용 별도 페이지로 만듭니다.

메뉴는 화면마다 늘리지 않고 주요 업무 6개를 고정합니다. 나머지는 ‘관리’ 아래에서 펼칩니다. 간단 모드도 중요한 처리 기능은 유지하고, 자세한 열과 이력만 접습니다. 자세한 모드 전환은 권한을 늘리는 기능이 아닙니다.

| 메뉴 | 처음 보이는 내용 | 상세 화면·내부 탭 |
|---|---|---|
| 오늘 현황 | 오늘 방문·준비할 건, 반납 확인 대기, 확인 요청 | 준비표·렌탈현황·배달/수거로 이동 |
| 새 대여 접수 | 기존 고객·날짜별 장비·리프트권·할인·견적 | 수령 일정, 결제, 예약/대여 확정 |
| 렌탈현황 | 고객별 예약·대여·반납 현황 | 대여 상세, 연장, 교환, 일부 반납, 수납·환불 |
| 배달·수거 | 시간·장소·차량별 업무 | 배정, 기사 확인, 연락 이력, 매장 직접 반납 |
| 거래처 장부 | 업체별 받을 돈·줄 돈, 장비 반환 대기 | 거래 등록, 거래 내역, 정산, 장비 내역 |
| 하루 마감 | 고객·업체의 수납·지급·환불, 미수, 현금 차이 | 거래별 근거, 보증금, 마감 확정·정정 |
| 관리 → 사전 입력·준비 | 발송·응답 목록, 준비할 예약 | 폼 설정, 응답 상세, 날짜별 준비표 |
| 관리 → 고객 | 이름·연락처 검색, 대표자별 이용 이력 | 일행 정보, 요청 메모, 이 고객으로 접수 |
| 관리 → 재고·정비 | 사이즈별 보유·대여·점검·부족 수량 | 장비, 리프트권, 타 매장 장비, 정비 |
| 관리 → 매장 설정 | 상품·요금·권종·할인·운영 기준 | 안내 페이지·QR, 문자 문구, 직원·차량 |

## 2. 거래처 장부

### 화면과 등록 방법

거래처 이름을 선택한 뒤 다음 네 가지 버튼 중 하나를 누릅니다. 업체 등록은 한 번만 하고, 같은 업체에 판매·매입·장비 대차를 모두 기록할 수 있게 합니다.

| 등록 버튼 | 외상일 때 돈의 방향 | 물품 처리 |
|---|---|---|
| 리프트권 사오기 | 우리가 줄 돈 | 날짜·권종·매수 입고, 구입 단가 기록 |
| 리프트권 팔기 | 우리가 받을 돈 | 날짜·권종·매수 출고, 판매 단가 기록 |
| 장비 빌려오기 | 우리가 줄 대여료 | 업체 소유 장비 입고, 사용 가능 기간과 돌려줄 날짜 |
| 장비 빌려주기 | 우리가 받을 대여료 | 우리 장비 출고, 돌려받을 날짜와 수량 |

입력 항목은 거래일, 업체, 품목·사이즈/권종, 수량, 이용일·기간, 단가, 금액, 지급·수령 여부, 약속한 정산일, 메모입니다. 거래 당시의 품목명·단가를 보관합니다. 장비도 날짜별 수량이 다르면 기존 접수와 같은 방식으로 입력하되 실제 인수·반환 수량은 별도로 기록합니다. 무료 대차는 의도한 0원으로 기록하며 물품 반환은 계속 관리합니다.

큰 표시 이름은 **받을 돈 / 줄 돈 / 돌려받을 장비 / 돌려줄 장비**로 합니다. 미수·미지급 같은 용어는 보조로 표시합니다. 당일 전액 정산한 거래도 내역은 남고 잔액은 0원입니다.

거래처 상세에는 ‘새 거래’, ‘돈 받음’, ‘돈 지급’, ‘장비 반환’, ‘거래명세서’ 버튼을 둡니다. 돈 기록과 물품 반환 버튼은 서로 독립적입니다. 돈을 지급했다고 장비까지 반환 완료되지 않습니다.

### 가상 정산 예시

| A스키샵과의 거래 | 거래 금액 | 실제 정산 | 남은 금액 |
|---|---:|---:|---:|
| 리프트권 20매를 매당 30,000원에 사옴 | 600,000원 | 200,000원 지급 | 줄 돈 400,000원 |
| 스키 5대를 하루 10,000원씩 이틀 빌려줌 | 100,000원 | 아직 받지 않음 | 받을 돈 100,000원 |

기본 화면에는 두 잔액을 모두 표시합니다. 서로 퉁쳐서 정산하는 경우 직원이 대상 거래와 금액을 확인해 **상계 처리**합니다. 위 예시에서 100,000원을 상계하면 받을 돈은 0원, 줄 돈은 300,000원이 됩니다. 상계는 실제 현금 입출금으로 집계하지 않으며 양쪽 거래에 기록을 남깁니다. 장비 5대의 반환 의무는 그대로 남습니다.

여러 거래를 한 번에 정산할 때는 배분할 거래와 금액을 보여줍니다. 일부 지급·일부 수령을 허용하고 미배분 선입금, 초과 정산, 환불 대기는 별도로 표시합니다. 정산을 수정할 때는 원기록을 삭제하지 않고 취소·정정 이력을 남깁니다.

### 재고·고객 대여·마감 연결

- 빌려온 장비에는 소유 업체와 실제 보유 장소를 기록합니다. 우리 소유 재고와 구분하고, 확보된 이용 가능 기간 안에서만 고객에게 배정합니다. [Booqable의 임시 재고 안내](https://help.booqable.com/en/articles/99180-how-to-create-and-manage-products)도 일정 기간만 사용 가능한 외부 조달 재고를 별도로 관리합니다.
- 빌려준 우리 장비는 외부에 나가 있는 동안 다른 고객에게 중복 배정되지 않아야 합니다. 반환 예정일이 지났다고 자동 입고시키지 않고 실제 인수·점검을 확인합니다.
- 고객 부족분을 다른 업체에서 빌렸다면 고객 대여 건을 선택해 연결할 수 있게 합니다. 고객 청구와 업체 비용은 별개 거래이며 고객에게 받을 돈을 업체 비용으로 자동 차감하지 않습니다.
- 리프트권 매입/매출은 같은 입출고 기록을 참조합니다. 장부에서 등록한 매입을 재고 화면에서 다시 등록하게 하지 않습니다. 미판매 권종의 업체 반품·거래 취소는 별도 사유와 금액 조정으로 남깁니다.
- 고객 판매, 업체 판매, 업체 매입, 수납·지급을 구분해 [하루 마감](03-daily-closing.md)에 연결합니다. 거래 등록과 실제 돈 이동을 중복 매출로 더하지 않습니다.
- 거래처는 우리 매장의 장부 속 업체 정보입니다. 상대 스키샵이 같은 서비스를 사용해도 고객·가격·장부를 자동 공유하지 않습니다. 상대 장부와 자동 연동하는 기능은 후속 범위입니다.

## 3. 렌탈현황과 대여 상세

렌탈현황은 **누가 무엇을 빌려서 현재 어떤 상태인지** 보는 화면입니다. 배달·수거 화면은 기사님이 방문할 업무를 보는 화면으로 역할을 구분하되 같은 대여 건을 엽니다.

기본 목록은 오늘 처리할 건을 보여주며, 오늘·내일·날짜 범위와 이름/연락처 검색을 제공합니다. 빠른 선택은 ‘수령 예정’, ‘대여 중’, ‘오늘 반납’, ‘매장 확인 대기’, ‘미반납’, ‘완료’입니다. 결제 상태는 별도 조건으로 ‘미수 있음’을 선택합니다.

| 기본 열 | 표시 내용 |
|---|---|
| 고객 | 대표자, 연락 버튼, 접수번호 |
| 이용 | 시작~종료일, 실제 수령일, 날짜별 수량 요약 |
| 물품 | 실제 지급 / 고객에게 남음 / 차량 수거 / 매장 확인 |
| 반납 | 날짜와 오후타임 후·야간타임 후·익일 오전, 장소·방법 |
| 금액 | 최종 금액, 받은 금액, 받을 잔액 |
| 확인 상태 | 일부 반납·점검 대기·변경됨 등 직원에게 필요한 표시 |

대여 상세에는 ‘기본 정보 / 장비·리프트권 / 수령·반납 / 결제·환불 / 연락·변경 이력’을 둡니다. 여기서 기간 연장, 장비 교환, 부분 반납, 반납 장소 변경, 잔금 수령을 합니다. 새 접수에 다시 입력하지 않습니다.

고객 반납 상태, 장비의 세척·정비 상태, 돈의 정산 상태를 구분합니다. 수거 완료는 차량 인수이고, 반납 완료는 매장 확인입니다. 세척·건조·정비가 남으면 고객의 반납은 완료하되 재고는 대여 가능으로 풀지 않습니다. [Axess RESORT RENTAL](https://teamaxess.com/en/software/axess-resort.rental-leisure)은 지급·교환·전체 및 부분 반환을 같은 운영 흐름으로 제공합니다.

요금 이용일과 실제 점유 기간도 구분합니다. 오늘 받고 내일~모레 타면 청구는 이틀이지만 재고는 오늘부터 점유합니다. 날짜별 이용 4개·3개를 실제 7개 지급으로 취급하지 않습니다. 중간 교환·부분 반환은 물품 이동 이력으로 기록하며 남은 수량을 계산합니다.

타임 기준 시각을 넘겼다는 이유만으로 연체료·독촉을 자동 발생시키지 않는 기존 원칙을 유지합니다. 변경 후 추가 요금·환불은 적용 전 직원에게 계산 근거를 보여줍니다.

## 4. 상품·요금·리프트권 설정

‘매장 설정’에서 설정한 상품을 대여 접수, 거래처 장부, 사전 입력폼, 준비표가 함께 참조합니다. 가격·권종·단위를 화면마다 따로 만들지 않습니다.

| 설정 탭 | 관리 내용 |
|---|---|
| 장비 종류 | 스키·보드·의류 등 상품, 등급·사이즈, 수량 단위, 세트 구성, 회수 여부, 표시 순서, 사용 중지 |
| 장비 요금 | 1일 단가, 날짜 조건, 적용 기간, 2·3일 계산 미리보기 |
| 리프트권 | 스키장, 오후·야간·후야·시간권, 성인/소인, 이용시간, 사용 가능한 날짜, 판매가, 기준 매입가, 즐겨찾기·정렬 |
| 간편 할인 | 단골 5,000원·10,000원 기본값의 이름·금액, 장비당/총 금액 적용 대상 |
| 거래처 | 업체명·연락처, 기본 거래 단가, 정산 메모, 사용 여부 |
| 운영 기준 | 수령·반납 장소, 오후·야간·익일 오전 시각, 직원·차량, 영업일 기준 |
| 고객 안내 | 공개 안내 페이지, FAQ, QR 인쇄, 문자 문구 |

퍼센트 할인은 추가하지 않습니다. 총 할인은 반복 클릭 누적, 장비당 할인은 실제 장비 수량 기준이라는 기존 결정을 유지합니다. 리프트권은 두 할인에서 기본 제외합니다.

기준 매입가는 신규 거래의 제안값이고, 실제 거래처 매입 단가는 해당 거래에 저장합니다. 권종·가격표를 바꿔도 과거 접수·장부·견적의 금액을 바꾸지 않습니다. 작성 중 접수에 새 가격 적용이 필요하면 변경 내역을 보여주고 재계산합니다.

권종 추가는 기존 항목 복사 → 이름·대상·날짜·가격 수정으로 쉽게 합니다. 종수가 많아지면 검색·분류·판매 중 항목 필터를 쓰며, 지난 시즌 항목은 삭제 대신 사용 중지합니다. 가격이 비어 있는 항목을 무료로 처리하지 않습니다.

설정 저장 전에 ‘새 접수에서 어떻게 보이는지’ 미리보고 1일·2일·날짜별 다른 수량 예제로 확인할 수 있게 합니다. 리프트 종료 시각은 실제 판매 조건을 등록한 값이며 샘플 시간을 실제 리조트 운영시간으로 표시하지 않습니다.

## 5. 방문 전 사이즈 입력과 준비

하나의 ‘사전 입력·준비’ 메뉴 안에 직원용 화면 3개를 두고, 고객용 모바일 입력 화면을 별도로 만듭니다.

첫 버전의 폼 설정은 준비된 질문의 표시·필수 여부·순서를 조정하는 방식으로 구성합니다. 관리자도 키·발 사이즈·의류 사이즈 같은 익숙한 항목을 켜고 끄며 설정합니다.

| 화면 | 사용하는 사람 | 구성 |
|---|---|---|
| 입력폼 설정 | 관리자 | 질문 표시/숨김, 필수 여부, 장비별 질문, 기본 안내, 미리보기 |

### 고객 입력폼

회원가입 없이 예약에 연결된 전용 링크로 엽니다. 대표자가 일행 정보를 한 번에 입력하고, ‘일행 추가’, ‘모두 같은 이용일’ 버튼을 제공합니다. 첫날 4명·둘째 날 3명이라면 한 사람의 이용일에서 둘째 날을 해제하는 식으로 입력합니다.

기본 질문은 일행 표시명, 이용 날짜, 스키/보드/의류 등 필요한 품목, 키(cm), 발 사이즈(mm), 필요한 경우 의류·헬멧 사이즈입니다. 각 질문은 해당 장비 선택 시에만 보여줍니다. 모르는 사이즈는 ‘현장 확인’으로 제출할 수 있게 하며 관리자가 필수 항목을 정합니다. 안전 조정값을 고객 입력만으로 자동 확정하는 기능은 포함하지 않습니다.

접수에 입력한 대표자·연락처·이용 기간은 링크에 연결해 중복 입력을 줄입니다. 일행 전원의 전화번호나 생년월일을 기본으로 요구하지 않습니다. 고객에게는 필요한 입력 항목과 제출 내용만 보이고 직원 메모·원가·다른 고객 목록은 노출하지 않습니다.

### 발송·응답과 변경 처리

기존 예약·견적·접수에 연결해 보내는 방식을 기본으로 합니다. 먼저 정보를 받는 경우에는 준비 요청 초안을 만들고 직원이 기존 고객·예약에 연결하거나 새 접수로 전환합니다. 이름·전화번호만 같다는 이유로 자동 병합하지 않습니다.

상태는 ‘링크 생성’, ‘발송 결과’, ‘미제출/일부 제출/제출 완료’, ‘직원 확인’, ‘준비 상태’를 구분합니다. 문자 발송 성공이 고객 열람·제출을 의미하지 않으며, 제출 완료도 예약 확정이나 결제 완료를 의미하지 않습니다.

고객이 제출 후 수정하면 바뀐 사람·사이즈·이용일을 표시하고 직원에게 확인할 변경으로 올립니다. 이미 확정한 대여 수량·요금·차량 업무·준비 완료 상태를 조용히 덮어쓰지 않습니다. 직원이 변경 전후를 보고 반영합니다.

링크는 해당 요청에만 접근하는 추측하기 어려운 식별자를 사용하고, 만료·재발급할 수 있게 합니다. 공개 안내 QR과 개인 입력 링크는 별개로 관리합니다. 폼 설정이 바뀌어도 이미 받은 응답은 당시 질문 이름·형식과 함께 보관합니다.

### 날짜별 준비표

준비표의 기본 날짜는 **장비 수령·방문 예정일**입니다. 오늘 수령하고 내일부터 타는 손님도 오늘 준비표에 포함합니다. 이용일별 보기에서는 첫날·둘째 날 필요한 수량을 따로 볼 수 있습니다.

| 방문/수령 | 대표자·일행 | 이용일 | 필요 장비·사이즈 | 상태 |
|---|---|---|---|---|
| 12/19 18:00 매장 | 김민수·일행1 | 12/20~21 | 스키, 키 170cm, 발 260mm, 의류 L | 미준비 |

행별로 ‘미준비 → 준비 중 → 준비 완료 → 지급 완료’를 표시하고, 재고 부족·현장 피팅 필요·고객 변경을 따로 표시합니다. 준비 완료는 지급 완료가 아닙니다. 필요한 부츠 260mm·의류 L 등의 수량 합계와 부족분을 볼 수 있게 합니다. 현장에서는 요청 사이즈와 실제 지급 사이즈를 구분해 기록합니다.

대표자가 예약한 수량과 일행 입력 합계가 다르면 차이를 보여줍니다. 예: 예약 스키 4대, 폼 스키 3명이라면 확인 후 반영합니다. 폼 제출만으로 재고를 확보했다고 약속하지 않습니다. [Checkfront의 스키 렌탈 안내](https://www.checkfront.com/ski-rental-software/)도 사이즈·세트 재고와 방문 전 폼, 일별 명단을 연결하는 기능을 소개합니다.

## 6. QR 이용 안내

매장별 공개 안내 페이지를 만들고 그 **고정 주소를 QR로 변환해 인쇄**하는 방식을 권고합니다. 안내 내용을 수정해도 주소를 유지하면 기존 QR을 계속 사용합니다.

관리자 흐름: 안내 내용 작성 → 휴대폰 미리보기 → 게시 → 안내 주소로 QR 생성 → A4 안내판/PDF 또는 QR 이미지로 인쇄. 주소를 변경해야 할 때는 기존 주소에서 새 안내로 연결되도록 유지합니다. 외부 서비스용 실제 주소가 필요하며 현재 로컬 시안 주소를 손님에게 배포하지 않습니다.

| 안내 항목 | 내용 |
|---|---|
| 방문 | 매장 주소·주차·운영시간, 전화·길찾기 버튼 |
| 이용 순서 | 도착 → 사이즈 확인 → 수령/배달 → 이용 → 반납 |
| 반납 장소 | 만선 티롤 앞 등 장소별 사진·설명·지도 링크 |
| 준비물·문의 | 현장 준비물과 자주 묻는 질문 |
| FAQ | 직접 반납 가능 여부, 연장 문의, 장비 교환, 리프트권 수령 방법 등 |
| 공지 | 당일 변경 사항과 확인 시각 |

안내 페이지는 공통 정보를 제공하며 고객 개인의 반납 장소·시간을 변경하지 않습니다. 고객별 일정 확인은 별도 개인 링크로 제공합니다. 게시한 FAQ와 장소·타임 설정을 연결할 때는 공개할 내용만 선별합니다.

공개 QR에 고객 이름·연락처·예약 정보나 직원 화면 주소를 넣지 않습니다. ‘이용 안내 QR’과 ‘예약별 사이즈 입력 링크’를 명확히 구별합니다. 처음에는 장비마다 QR을 붙일 필요가 없습니다.
