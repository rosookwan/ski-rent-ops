# 접수 배달 예정과 품목별 전달 완료

2026-09-09. 신규 대여의 수령 방법에서 배달을 선택하면 실물 적재 전부터 배달 업무가 표시된다. 장비와 리프트권은 각각 수령 방법, 배달 날짜·시간, 장소, 차량을 정한다. 수거·반납 방법은 기존대로 별도로 유지한다.

## 화면 흐름

1. 새 대여 접수의 **수령·반납 설정**에서 장비/리프트권을 각각 매장 수령 또는 배달로 지정한다.
2. 저장하면 배달 예정 품목과 수량으로 실제 업무 두 건을 생성한다. 재고가 없거나 리프트권 발권 전이어도 해당 날짜/차량의 배달·적재 목록과 차량 업무에 표시된다. 접수 저장은 물품을 지급하거나 차에 싣지 않는다.
3. 장비만 손님이 먼저 가져갔다면 상세의 **장비 배달완료**에서 실제 건넨 수량을 선택한다. 상세의 장비 적재·배달 버튼은 제거했다.
4. 리프트권은 **발권·준비**로 실제 권종과 유효시간을 기록한다. 배달 예정 권은 발권 후에도 매장 보관이다. 적재는 배달 화면의 **실었어요**, 고객 전달은 차량 업무 또는 상세의 **리프트권 배달완료**에서 별도로 처리한다.
5. 일부만 발권/전달하면 남은 수량은 계속 표시된다. 완료한 배달은 적재 목록에서 빠지고 방문 완료 내역과 상세의 품목별 완료 상태에 남는다.

## 데이터와 수량

- `pickupPlan.equipment` / `pickupPlan.liftTicket`를 접수에 저장한다. 일별 이용 수량을 실제 장비 수량으로 더하지 않는다.
- `task.plannedItems`가 아직 실물에 배정하지 않은 수량까지 보존한다. `task.allocate`는 품목, 수량, 고객 리프트권 배정, 중복 배정, 보관 위치를 검사한다.
- 완료 검증은 실물에 배정된 물품과 미배정 예정 수량을 함께 검사한다. 장비 업무를 완료해도 리프트권 업무는 완료되지 않는다.
- 상세에서 직접 전달한 경우 매장→고객 또는 담당 차량→고객의 실제 이동을 기록한다. 가짜 적재·하차 기록을 만들지 않는다.
- 새 장비 배정과 적재/직접 전달, 리프트권 발권·고객 배정은 각각 원자적으로 처리한다. 이미 배정된 물품을 다른 접수에서 자동 지급하지 않는다.

## 검증

- 전체 도메인·API 테스트 79개: 접수 자동 업무 생성, 중복 가져오기, 장비만 완료, 다음 날 미발권 권 유지, 일부 발권/적재/전달, 별도 차량과 권한, 부족 재고 유지 포함.
- 브라우저: 신규 접수부터 두 품목의 최종 전달까지 `npm run test:delivery-plan`의 4개 연속 시나리오 통과. 렌탈 13개(취소한 배달을 완료로 표시하지 않는 검사 포함), 배달 17개, 접수 13개, 화면 이동 6개도 통과.
- UI 개선 7 원본을 수정하지 않고 동일 데이터·폰트·화면 크기로 비교했다. 1366×768, 1024×768, 1440×900, 1920×1080의 32개 상태, 1,108개 요소에서 색상·폰트·좌표·크기 측정 불일치 0개.
- 사용자가 요청한 발권 전 표시, 발권·준비 버튼 문구, 완료 배달의 적재 목록 제외는 비교용 원본 확장에 명시했다. 기존 버튼 스타일은 그대로 사용했다.
- 원시 이미지 최대 차이는 0.07622%이며 팝업 모서리의 안티앨리어싱과 공통 셸이 포함된다. 불투명 내부 최대 차이는 0.01960%였다. 모든 픽셀이 같다는 의미는 아니다.
- 상세 1366/1024 화면과 수령 설정, 미발권 목록, 일부 적재, 최종 완료 화면을 직접 확인했다. 로컬 결과는 `work/delivery-plan/`에 저장한다.
