# 44. 힉스필드 시안 · 매장 설정(구역 · 템플릿 · 할인)과 접수 확정 창

작성 2026-09-21 · 묶음 [`design/higgsfield/pos-settings-v1/`](../design/higgsfield/pos-settings-v1/index.html) · 9장 · 27 크레딧 · 다시 뽑기 0 · 브랜치 `feat/pos-ui-v4`

## 1. 왜 다시 그렸나

v4를 체험해 본 뒤 나온 요청이다(2026-09-21).

1. 수령 장소를 **구역(설천 · 만선 · 기타)** 으로 나눠서 넣는다. 장소가 늘어도 설정 화면이 복잡해지지 않게.
2. **스키장 템플릿**(무주덕유산리조트 · 지산리조트 등)으로 처음 값을 자동으로 채운다.
3. 반납 시간에 **오전타임 후 12:00** 이 있어야 하고, 매장 설정에서 추가한 대로 접수 화면에 나와야 한다.
4. 접수 화면의 수령 장소도 장소가 10개를 넘으면 깨지므로 **구역만 버튼으로** 보이고 장소는 팝업에서 고른다.
5. 접수 직전에 **할인**을 고른다: 장비당 N원(예: 스키 5,000원씩), 장비 전체 %, 리프트권은 따로 %(20 · 25 · 27% 등). 매장 설정에서 정한다.
6. **접수 확정할 때 금액을 계산해 그 자리에서 수납**한다. 장비는 카드, 리프트권은 현금으로 받는 일이 많으니 **둘을 나눠서 결제 수단을 고른다.**
7. (추가) **일행마다 따로 계산**하는 경우(더치페이)의 화면. 나중에 카드 단말을 붙였을 때 쓴다. 지금은 **화면 시안만.**

확인한 사실: 이 기능들은 v4 작업에서 지워진 것이 아니라 **포스 화면에 구현된 적이 없다.** `docs/35`(51 매장 설정 탭 `수령 장소 · 할인 · 수령·반납 시간` / 41-1 선택 그룹 `수령 장소 · 구역 · 할인율`)에는 있었지만, v3부터 포스의 매장 설정은 요금 · 장소(한 줄 목록) · 차량 · 반납 타임 · 직원 · 매장 정보 · 야간 기준만 있었고 v4 시안도 그 상태를 기준으로 그렸다. 접수 확정 때 수납하는 창은 어디에도 없었다(수납은 접수 상세 · 준비·지급 카드 · 정산·마감에서 따로). v4에서 새로 생긴 잘못은 하나다: 3단계 `반납 시간`이 설정의 앞 3개만 보였다.

S08R은 셋째 묶음이다. 첫 판 S08은 일행마다 금액을 나눴는데, **현장 대여는 대표자 이름만 적기 때문에 사람별로는 나눌 수 없다**는 지적(사용자 · 2026-09-21)에 따라 남은 품목에서 수량을 직접 골라 한 묶음씩 결제하는 방식으로 바꿨다(식당의 메뉴별 계산과 같다). 샘플 표기: 의류 줄의 `1별`은 `1벌`의 오기(기록만).

S07R · S08은 사용자 답변(3절 아래)을 받은 뒤 그린 둘째 묶음이다. S07R은 다시 뽑기가 아니라 내용이 바뀐 새 판이다: 할인 칸이 넷으로 바뀌고 `나눠서 결제` 입구가 생겼으며, 첫 판의 `받을/할인` 오기와 예시 할인액도 바로잡혔다.

검수 메모(다시 뽑지 않음 · 구조 결함 아님):

- S05: 첫 줄 `수령일`만 이름표가 버튼 위에 그려졌다. 구현은 지금처럼 다섯 줄 모두 왼쪽 이름표. 두 줄 버튼의 작은 글자가 13px쯤으로 그려졌다 → 구현은 16px.
- S04: 할인 종류 칩이 셋으로 그려졌다(장비당 · 장비 전체 · 리프트권). 답변에 따라 구현은 넷: `장비당 할인` · `% 할인` · `금액 할인` · `리프트권 할인`. 모양이 같아 다시 뽑지 않는다.
- S07(첫 판): 왼쪽 아래 요약의 `받을 47,500원`은 `할인 47,500원`의 오기(한 낱말). 장비 할인액 `−30,000원`은 예시 숫자다(3절 규칙대로면 스키 3 · 의류 2 · 2일은 −42,000원). 주 버튼 글자가 작게 그려졌다 → 구현은 18px.
- S01의 `매장 정보 0`, 팝업 뒤 어두운 배경의 오탈자는 샘플·배경이라 기록만.

## 3. 그림에 안 보이는 동작 (구현 전에 확인할 것)

| # | 항목 | 이렇게 만들 생각 |
|---|---|---|
| 1 | 구역 | 매장 설정에 구역 목록(순서 있음)을 두고, 장소는 구역에 속한다. 지금 있는 장소는 이름이 구역 이름으로 시작하면 그 구역으로, 아니면 `기타`로 옮긴다. |

| 3 | 스키장 템플릿 | 구역 · 수령 장소 · 반납 타임 · 리프트권 권종을 채운다. **요금과 할인은 건드리지 않는다.** 이미 있는 값은 지우지 않고 없는 항목만 추가한다. 무주덕유산리조트 · 지산포레스트리조트부터. **실제 장소 · 권종 목록은 나중에 실제 DB를 연결할 때 한 번에 정리한다(사용자 · 2026-09-21).** 그때까지는 예시 값을 넣어 둔다. |
| 4 | 반납 타임 | 기본값에 `오전타임 후 12:00` 추가. 접수 화면에는 설정에 있는 대로 다 나오고, 폭이 모자라면 앞 3개 + `더 보기`(창에서 고름). |
| 5 | 할인 규칙 | **확정(사용자 · 2026-09-21): 중복 없이 하나만.** 장비 쪽은 `없음` · `장비당 할인`(품목마다 금액 × 수량 × **이용 일수** — 하루 기준, 예: 스키 하루 5,000원) · `% 할인`(장비 합계의 N%) · `금액 할인`(**총 금액에서 N원**) 중 하나. `% 할인`과 `금액 할인`은 누르면 매장 설정에 넣어 둔 값(예: 10 · 20 · 30% / 5,000 · 10,000원)과 `직접 입력`을 고르는 작은 창이 뜨고, 고른 값이 버튼 둘째 줄에 보인다. 리프트권은 따로 `없음` · 20 · 25 · 27% 같은 % 버튼. 계산은 10원 미만 버림. 할인액은 품목 행의 할인으로 나눠 저장한다(지금 자료 구조 그대로). `금액 할인`은 장비 합계에서 뺀다(리프트권은 %만). |

| 6-1 | 나눠서 결제(S08R) | **화면만 먼저 그려 둔다(사용자 · 2026-09-21). 구현은 카드 단말을 붙일 때.** 사람이 아니라 **품목으로 나눈다**: 아직 결제하지 않은 품목이 줄로 나오고(남은 수량 · 하나 값은 할인 뒤 금액), −/+ 로 이번에 계산할 수량을 고르면 오른쪽 `이번 결제`에 금액이 나온다. 결제 수단을 고르고 `고른 품목 결제 · N원`을 누르면 그만큼만 수납으로 기록하고(자료는 이미 품목별 수납 배분을 지원), 남은 품목으로 같은 일을 되풀이한다. `남은 것 모두 고르기`는 마지막 사람용, `똑같이 나누기`는 받을 금액 ÷ N. 품목 종류가 3줄을 넘으면 쪽으로 넘긴다. `금액 할인`은 품목 값에 고르게 나눠 반영한다. |
| 7 | 결제 수단 기본값 | 장비는 카드, 리프트권은 현금. |

## 4. 실제 크기 검사

`fit-check/index.html`을 요청서의 글자 · 버튼 크기 그대로(Pretendard · 16px 이상 · 버튼 52px · 주 버튼 56px) 그려 `fit-check/measure.cjs`로 쟀다. 긴 이름 · 7자리 금액 · 할인 버튼 5개 · 장소 9곳 + 쪽수로 넣었다.

| 크기 | S05 3단계 | S06 수령 장소 창 | S07 접수 확정 창 |
|---|---|---|---|
| 1024×600 | 잘림 0 · 스크롤 0 | 542px(한도 552) · 잘림 0 | **549px(한도 552)** · 잘림 0 |
| 1024×768 | 잘림 0 | 잘림 0 | 잘림 0 |
| 907×648 | 반납 타임 5칸의 이름표가 4px 넘침 · 요약 `수령` 줄 넘침 | 잘림 0 | 잘림 0 |

- 나눠서 결제 창(S08R)은 품목 3줄 + 쪽수 + 긴 품목 이름 · 7자리 금액으로 **526px**(1024×600 · 907×648 · 1024×768 모두 잘림 0). 한 쪽에 품목 3줄까지다.
- 접수 확정 창은 할인 네 칸 · 하단 버튼 네 개로 바꾼 뒤에도 549px다. 1024×600에 **여유 3px로 들어간다.** 줄을 더 넣을 자리는 없다. 창 폭은 880px(지금 창은 760px)로 넓힌다.
- 907×648의 넘침은 구현 규칙으로 푼다: 반납 타임은 폭이 모자라면 앞 3개 + `더 보기`, 요약 줄은 지금처럼 조각을 빼서 맞춘다.
