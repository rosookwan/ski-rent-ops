# 장비·리프트권 탭의 품목별 카드

2026-09-09. 사용자가 장비·리프트권 탭의 수량 의미, 카드형 레이아웃, 수집하지 않는 사이즈 예시 문구를 수정하도록 요청했다.

## 범위

- **조기반납 팝업 재구성은 보류한다.** 사용자가 별도 UI를 제공하기로 했다. 작성 중이던 팝업·관련 장소 설정 변경은 제거하여 기존 배포 소스를 유지했다.
- 이번 변경은 장비·리프트권 탭의 카드와 수량 표시, 일반 대여 상세의 고정 사이즈 예시에 한정한다. 반납·장비교환·조기반납 명령과 결제 계산은 변경하지 않는다.
- 장비교환의 기존→새 규격은 이전 사용자 요청에 따른 실제 교환 입력이므로 유지한다.

## 확인한 문제와 변경

기존 `실제 장비 수량 → 실제 지급`은 장비·의류·리프트권을 합산했다. 스키 4대와 오늘 지급한 리프트권 4매가 `8`로 보이므로 제목과 값의 의미가 맞지 않았다.

이제 각 품목이 독립된 카드이며, 리프트권은 권종과 이용일을 함께 표시한다. 스키·의류는 주황색, 리프트권은 파란색 머리글을 사용한다. 고객 보유는 주황색, 차량 보관은 보라색, 매장 확인은 녹색으로 기존 화면의 의미를 따른다.

| 표시 | 의미 |
| --- | --- |
| 대여 수량 / 예정 수량 | 해당 품목의 전체 예정 수량 |
| 실제 지급 | 해당 품목 중 실제 고객에게 지급한 수량. 반납 후에도 지급 사실은 유지 |
| 지급 전 | 아직 고객에게 지급하지 않은 예정분 |
| 고객 보유 | 현재 고객에게 남은 물품 |
| 차량 보관 | 수거했으나 매장 인계 전인 물품 |
| 매장 확인 | 직접반납 또는 차량 인계를 통해 매장이 확인한 물품 |

- 스키·보드는 대, 의류는 벌, 리프트권은 매를 사용한다. 교환 구성품은 별도 카드로 표시하며 본체 수량을 늘리지 않는다.
- 예: R-025는 스키 실제 지급 4대, 9/9 오후권 실제 지급 4매, 9/10 오후권 예정 3매·실제 지급 0매다. 이 값을 장비 8대 또는 11대로 합산하지 않는다.
- R-025 스키를 1대 더 반납하면 실제 지급은 4대를 유지하고 고객 보유가 3→2대, 매장 확인이 1→2대로 바뀐다.
- 이용일별 스키 수량 4대/3대와 할인 전 요금 80,000원/60,000원도 작은 날짜별 카드로 유지한다. 이용일별 수량을 실물 지급 수량에 더하지 않는다.
- 우측 요약은 기존 전체 물품 합계를 유지하면서 품목별 수량을 덧붙여 합계의 구성을 확인할 수 있게 한다.
- 수령 예정인 R-027은 스키 0대·의류 0벌을 표시하고 `장비 지급 확인` 후에만 각각 2대·2벌로 바뀐다.
- R-027의 `발 사이즈 260 / 240mm · 의류 L / M` 고정 예시를 삭제했다. 메모가 비어 있으면 빈 안내 상자를 만들지 않는다. 다른 실제 접수 메모는 유지한다.

## 검증

- 품목 카드 브라우저 검사 5개 통과: 장비/리프트권/이용일 분리, 지급 전→실제 지급, 부분반납과 금액 유지, 차량→매장 인계, 화면 폭별 레이아웃.
- 1366×768, 1024×768, 907×648, 390×740에서 R-025·R-027의 실제 화면을 캡처하고 확인했다. 숫자 내부 글꼴이 26px 이상이고 카드·수량 영역이 서로 겹치거나 화면 밖으로 넘치지 않는지 검사했다.
- 기존 렌탈·반납 브라우저 13개, 장비교환 4개 통과. 교환 부츠 1개와 스키 본체 2대가 카드에서 별도로 유지되는 사례를 확인했다.
- `npm test`: 94/94 통과. `npm run check`: JS 44개·인라인 스크립트·정적 빌드 통과.
- 장비·리프트권 탭은 사용자가 재구성을 요청했으므로 이전 시안과 동일하다고 주장하지 않는다. 새 카드 전용 검사로 확인하고, 나머지 목록·반납·결제·이력·반납 팝업만 원본 비교를 유지한다.
- 나머지 화면 원본 비교는 4개 해상도 × 11개 상태(44개)에서 측정한 위치·크기·스타일 차이 0으로 통과했다.
