# 45. 힉스필드 시안 · 시스템 관리 콘솔(관리자 히든 화면)

작성 2026-09-21 · 묶음 [`design/higgsfield/admin-console-v1/`](../design/higgsfield/admin-console-v1/index.html) · 8장 · 24 크레딧 · 다시 뽑기 0 · **시안 요청까지만 — 구현은 하지 않았다.**

## 1. 무엇을 위한 화면인가

매장 직원이 쓰는 포스 · 관리 화면과 별개로, **서비스를 운영하는 사람(사장님 본인)** 만 들어가는 화면이다. 여러 매장의 라이선스와 계정을 만들고 지우고, 스키장 템플릿을 고치고, 누가 언제 무엇을 했는지 본다.

- 보는 기기: **MacBook 브라우저만**(사용자 · 2026-09-21). 포스 · 휴대폰 같은 작은 화면은 고려하지 않는다. 설계 프레임 1440×810(16:9 — MacBook 1440×900에서 브라우저 위쪽을 뺀 보이는 영역에 가깝다).
- 마우스 · 키보드 기준이라 포스보다 촘촘하게 그렸다: 본문 · 표 15px, 표 한 줄 48px, 버튼 · 입력 40px, 제목 22px, 숫자 32px.
- 색 · 글꼴은 스키노트 그대로, 구분을 위해 **어두운 사이드바 + 빨간 `시스템 관리` 표시**를 쓴다. 주황은 화면마다 주 버튼 하나와 활성 메뉴 막대에만, 되돌릴 수 없는 동작은 빨강.

## 2. 들어가는 방법 (추천안)

숨기는 것은 편의이지 보안이 아니다. **지키는 것은 아이디 · 비밀번호와 잠금 · 기록**이고, 숨은 입구는 직원이 실수로 들어오지 않게 하는 정도로 본다.

| 방법 | 내용 | 비고 |
|---|---|---|
| ① 숨은 주소(기본) | 운영 서버의 `/admin`. 어떤 메뉴 · 링크에도 없고 검색에 잡히지 않게(`noindex`) 한다. MacBook에서는 즐겨찾기로 연다. | **공개 체험판(Pages)에는 넣지 않는다** — 정적 파일이라 비밀번호를 지킬 수 없다. |
| ② 숨은 버튼(보조) | 로그인 화면의 `스키노트` 로고를 3초 안에 5번 누르면 관리자 로그인으로 간다. | 주소를 잊었을 때 · 매장 기기에서 급히 볼 때. |
| ③ 단축키(보조) | 로그인 화면에서 `⌘ + Shift + A`(윈도우는 `Ctrl + Shift + A`). | MacBook용. |

세 방법 모두 같은 `관리자 로그인`(A01)으로 간다. 화면에는 들어오는 방법을 적지 않는다.

구현할 때 지킬 것(시안에 반영한 문구 포함):

- 비밀번호는 서버에서만 확인하고 해시로만 저장한다. 화면 코드 · 저장소 · 체험판에 아이디나 비밀번호를 넣지 않는다.
- 5회 틀리면 10분 잠금, 모든 로그인 시도와 관리 동작을 `사용 내역`에 남긴다(A01의 안내 문구).
- 일정 시간 쓰지 않으면 자동 로그아웃, 가능하면 2단계 확인(문자 · 인증 앱)이나 접속 허용 주소를 나중에 더한다.
- 삭제는 기록을 지우지 않는다: 계정을 지워도 그 계정이 만든 접수 · 수납은 남고 이름만 `삭제된 계정`으로 보인다(A08).

## 3. 화면 구성

사이드바 메뉴 6개: `현황` · `라이선스` · `계정` · `스키장 템플릿` · `사용 내역` · `시스템 설정`. 아래에 로그인한 관리자와 `로그아웃`. 헤더에는 화면 제목, `매장 · 계정 찾기`, 마지막 확인 시각.

| 코드 | 화면 | 하는 일 | 참조 |
|---|---|---|---|
| A01 | 관리자 로그인 | 아이디 · 비밀번호, 잠금 · 기록 안내, `매장 화면으로 돌아가기` | — |
| A02 | 현황 | 사용 중 매장 · 만료 임박 · 오늘 접속 · 오류 숫자, 만료 임박 라이선스 표(`연장`), 최근 사용 내역, 서버 · DB · 백업 · 버전 | — (셸 기준) |
| A03 | 라이선스 | 찾기 · 상태 칩 · `라이선스 발급`, 표(매장 · 번호 · 요금제 · 단말 · 만료일 · 상태), 오른쪽 상세와 `기간 연장` · `단말 수 변경` · `정지` · `삭제` | A02 |
| A04 | 계정 | 찾기 · 매장 · 역할 칩 · `계정 생성`, 표(아이디 · 이름 · 매장 · 역할 · 상태 · 마지막 접속), 행마다 `비밀번호 초기화` · `정지` · `삭제` | A02 |
| A05 | 스키장 템플릿 | 템플릿 목록(적용 매장 수) · `새 템플릿`, 편집기 탭 셋(`구역 · 수령 장소` · `반납 타임` · `리프트권 권종`), `템플릿 삭제` · `되돌리기` · `저장` | A02 |
| A06 | 사용 내역 | 기간 · 매장 · 계정 · 종류 · 내용으로 거르기, `CSV 내려받기`, 표 + 상세(`바꾸기 전 / 바꾼 뒤`) | A02 |
| A07 | 팝업 · 계정 생성 | 매장 · 역할 · 이름 · 아이디 · 임시 비밀번호 · 첫 로그인 때 변경 · 라이선스 한도 안내 | A04 |
| A08 | 팝업 · 삭제 확인 | `지워지는 것 / 남는 것`, 아이디를 직접 입력해야 삭제, `삭제 대신 정지` | A04 |

`시스템 설정`(백업 · 문자 발송 · 관리자 비밀번호 변경 등)은 메뉴에만 있고 이번에는 그리지 않았다. 필요한 항목이 정해지면 같은 틀로 한 장 더 뽑으면 된다.

`docs/44`의 스키장 템플릿(매장 설정에서 고르는 값)은 지금 코드 안의 예시 값이다. A05가 생기면 그 값을 여기서 등록 · 수정하고 매장 설정의 `스키장 템플릿` 창은 이 목록을 읽게 된다 — 사용자가 말한 "실제 DB 연결 때 정리"와 같은 시점이다.

## 4. 생성과 검수

설정: `gpt_image_2_5` · flare · high · 2k · **16:9**(2688×1520) · 장당 3 크레딧. 개인 워크스페이스 그대로. 세 묶음으로 나눠 앞 묶음의 결과를 참조로 넘겼다: ① A02(셸 기준) + A01 → ② A03~A06(A02 참조) → ③ A07 · A08(A04 참조).

8장 모두 구조 결함이 없어 다시 뽑지 않았다. 기록만 한 것: A03 마지막 행의 상태 알약 `정제`(`정지`의 오기 · 칩과 버튼은 바름), 팝업 뒤 어두운 배경의 작은 오탈자.

포스 시안과 달리 실제 크기 검사(fit-check)는 하지 않았다. 작은 화면 제약이 없고 아직 구현 요청이 아니기 때문이다. 구현하게 되면 1440×810에서 표 8행과 오른쪽 상세가 같이 들어가는지만 확인하면 된다.

## 5. 다음에 정할 것(구현 전)

1. 라이선스의 단위: 매장마다 하나(요금제 · 기간 · 단말 수 · 계정 한도)로 그렸다. 실제 과금 방식과 맞는지.
2. 계정 역할: 매장 관리자 · 카운터 · 기사 · 시스템 관리자 넷으로 그렸다.
3. 사용 내역을 얼마나 오래 보관할지, 어떤 동작까지 남길지(지금 그림: 로그인 · 접수 · 수납 · 설정 변경 · 삭제 · 오류 · 백업).
4. `시스템 설정`에 들어갈 항목.
5. 운영 서버의 인증 방식(지금은 접속 키 방식) — 아이디 · 비밀번호 로그인으로 바꾸는 일이 이 콘솔보다 먼저다.
