# 반납 UI 작업 프롬프트

기능 본체는 [반납 기능 계약](10-return-functions.md)에 구현되어 있습니다. 현재 UI 개선 후 아래 순서로 연결합니다. 수량 계산과 API를 재구현하지 않고 `SkiOps.returns` 또는 동일한 HTTP 클라이언트를 사용합니다. Pages는 한 페이지의 메모리만 공유합니다.

## 1. 차량 전체 수거·일부 반납

```text
개선된 차량 UI의 스타일과 배치를 유지하면서 전체 수거·일부 반납을 연결해줘.
먼저 docs/10-return-functions.md와 design/app/return-runtime.js를 읽어줘.

바쁜 기사님이 키보드 없이 몇 번의 터치로 처리하는 것이 핵심이다.
- 현재 방문의 대상 품목·수량을 큰 글자로 보여줘.
- 전체 수거와 일부 반납을 기본 화면에서 바로 선택하게 해줘.
- 일부 반납은 못 받은 품목을 선택하고 큰 − / ＋ 버튼으로 미수거 수량만 조절해줘.
- 실제 받은 수량과 남은 수량을 명확하게 보여줘.
- prepareVehicleReturn(order, 이번업무대상, 미수거목록)으로 payload를 만들어줘.
- 남은 의류·리프트권은 직접반납 기본값을 사용하고 날짜를 자동으로 내일로 바꾸지 마.
- 사유 종류는 보류 중이다. 사유 목록·콤보박스·필수 메모·날짜 타이핑을 추가하지 마.
- newCommand로 만든 요청을 execute에 보내고 응답 후에만 완료 표시해줘.
- 중복 클릭은 같은 요청을 사용하고 버전 충돌 시 최신 상태를 확인하게 해줘.
- 본인의 차량 인수 기록은 undoReturn으로 되돌릴 수 있게 해줘.
- 연결된 매장 확인 때문에 정정이 거절되면 짧은 안내를 보여줘.
- 차량 수거와 매장 최종 완료를 구분해줘.
- Pages는 메모리 체험이며 실제 저장·기기 간 공유로 표시하지 마.

1024×800에서 큰 버튼, 가로 넘침, 키보드 없는 전체·일부·되돌리기를 확인해줘.
다른 날짜의 리프트권이 전체 수거에 섞이지 않는지 확인해줘.
```

## 2. 매장 반납 목록·추가 반납·정정

```text
개선된 매장 POS를 유지하면서 반납 목록과 추가 반납을 연결해줘.
docs/10-return-functions.md의 클라이언트 계약을 사용해줘.

- list({onDate, filter})로 일부 반납/직접반납/리프트권 미회수/기한 경과/매장 확인 대기를 조회해줘.
- dueItems의 남은 품목·수량·예정일을 목록에서 바로 보여줘.
- 고객 보유, 차량 보유, 매장 확인 수량을 구분해줘.
- 의류만 가져오면 receiveDirect로 의류만 처리하고 리프트권은 남겨줘.
- pendingConfirmations의 collectionId와 수량으로 confirmVehicle을 실행해줘.
- 차량 인수분을 receiveDirect로 다시 회수 처리하지 마.
- planReturn으로 남은 품목의 예정일·방법을 변경하게 해줘.
- 리프트권만 다음 날 반납하면 해당 날짜 목록에도 표시해줘.
- correctReturn은 실제 받은 새 총수량, undoReturn은 해당 기록 취소로 연결해줘.
- history에서 원본과 정정 전후 수량·담당자·시각을 보여줘.
- complete/status는 기능 응답을 사용하고 화면이 따로 계산하지 않게 해줘.
- 사유 목록과 분실 종결 UI는 보류해줘.

스키 차량 수거→의류 직접반납→리프트권 다음 날 회수와 완료 후 정정을 확인해줘.
API 연결 시 watch로 갱신하고 로그아웃·매장 전환 때 중지해줘.
```

## 3. 리프트권 단독 접수·회수 집계

```text
개선된 접수와 매장 집계 UI에 리프트권 회수를 연결해줘.
docs/10-return-functions.md의 create/issue/planReturn/report 계약을 사용해줘.

- 장비 없이 리프트권만 접수할 수 있게 해줘.
- 날짜별 구매·이용 수량과 실제 지급 예정/회수 대상 매수를 구분해줘.
- 접수는 create, 실제 지급은 issue로 분리하고 미지급 권을 미회수로 올리지 마.
- 의류·리프트권은 직접반납을 기본 적용해줘.
- 품목별 반납일·방법을 지정하게 하되 장비 기간·요금을 자동 변경하지 마.
- 기존 견적·결제 연결 범위를 확인하고 임의의 결제 완료나 실제 발권으로 표시하지 마.
- report의 회수 매수·기준 금액·매장 확인 매수를 구분해줘.
- 기본 기준은 장당 1,000원이며 차량→매장 인계로 금액이 늘어나면 안 된다.
- current 필드는 현재 잔량이며 기간 집계의 과거 잔량으로 표시하지 마.
- 정정은 원래 회수일 집계를 바꾼다는 기준을 설명해줘.
- 회수 금액을 고객 환불액·현금 수입·정산 완료액으로 표시하지 마.
- 별도 사유 UI는 보류해줘.

리프트권 단독 지급·당일 반납·일부 반납·익일 회수·인계 중복 방지를 확인해줘.
```
