# 51. 시안과 달라진 부분의 사유와 현재 마무리 상태

2026-09-21. 사용자 요청: "지금까지 한거 마무리하고 업무상 필요로 인해 달라진 것들은 사유를 써줘 문서에".

## 현재 상태

- A1~A4의 기준은 `feat/pos-ui-v4`의 `3636a02`다. 그 위에 A5(1) 업무 처리와 (2) 차량 보관 화면 수정을 더했다. A1~A4 재수정은 아래 "2026-09-21 재수정", A5의 비교·검사는 각 재개 기록을 따른다. `aa1dae6`은 그 이전 구현·검사 기록이다.
- **A4의 남은 모양 차이는 아래 재수정 기록을 따른다.** 기존의 "시안에 맞춤", "완료" 보고나 업무 검사 통과를 시각적 일치 확인으로 해석하면 안 된다.
- **2026-09-22 A5:** (1) 업무 처리의 수정·비교·검증은 `bcd67c8`로 작업 브랜치에 푸시했다. (2) 차량 보관은 요소 표 작성 뒤 입고 권한 차이를 먼저 확인했고, 사용자 응답 **"둘다 가능하게 해줘"**를 받아 구현했다. **매장·기사 모두 입고 가능**하다. 기사는 자기 차량에서 수거한 입고 대기 물품만 처리한다. (1)의 실제 문자 발송 미연결·예약금 미수 보류는 그대로다. 아래 구현 전 중단 기록은 당시 이력이며 현재 상태는 문서 끝의 (2) 재개 기록을 따른다. 당시에는 `feat/pos-ui-v4`에만 반영했다. **이후 사용자 배포 요청으로 2026-09-22 A1~A5의 `55d16e9`를 main·Pages에 배포했고, 현재 작업은 아래 A6 공통 바깥 배치다.** 배포 근거는 [`docs/43` 14절](43-ui-v4-implementation.md#14-a1a5-기존-변경-배포-2026-09-22)이다.
- 아래의 업무 사유는 **데이터와 처리 절차를 보존하는 이유**다. 버튼 모양·패널 비율·여백·색·배치를 임의로 바꿔도 된다는 뜻이 아니다.

## 기능·자료가 아직 없는 부분

이 항목들은 업무상 반드시 달라야 하는 디자인이 아니라 **시안 대비 남은 구현 범위**다.

| 화면 | 남은 차이 | 현재 사실 |
|---|---|---|
| M02 재고 | 시안의 `재고 목록 인쇄`가 없고 현재 하단에는 `실물 목록`이 있다. | 이번 A4에서는 재고 인쇄를 구현하지 않았다. 인쇄 대신 다른 버튼을 배치한 것을 시안 충족으로 볼 수 없다. |
| M04 거래처 | 담당자, 단가·일수에 따른 개별 대여 요금 표시 | 현재 거래처 저장은 이름·전화, 약정은 거래처 단위 금액·사유다. 예시 담당자나 단가를 실제 값처럼 넣지 않았다. 이 자료가 필요하면 별도 기능 구현이 필요하다. |

### 막힌 항목 — 다른 기능으로 대체하지 않음

사용자 공통 규칙 6번: **"시안대로 할 수 없는 항목(자료·기능이 없음, 높이가 모자람 등)은 다른 것으로 대체하지 말고 멈추고 사유를 먼저 보고한다."** 아래 두 항목이 이에 해당해 화면 구현을 중단했다.

|---|---|---|
| `출발 문자` | [업무 처리 화면](../design/app/pos-dispatch.js)의 `taskPage()`에는 `tel:` 전화만 있고 출발 문자 동작이 없다. [기존 문자 기능](../src/workflows/service.js)의 `sendFormLink()`는 매장 권한으로 고객 입력폼 링크를 보내는 전용 기능이며, 출발 문자나 기사 발송 기능이 아니다. | 출발 문자를 휴대폰 문자 앱에서 작성하는지, 서버로 발송하는지와 발송할 문구. 기존 입력폼 문자를 대신 보내거나 다른 버튼으로 채우지 않는다. |

### 고친 곳

- 태블릿 헤더는 `배달·수거 처리`와 제목 옆 배지, 고객 정보는 `대표자 팀 · M/D HH:mm · 장소 · 전화번호`의 한 줄로 맞췄다. `전화`를 고객 정보 오른쪽으로 옮겼다.

- 휴대폰 헤더 왼쪽은 `‹ 목록`, 가운데는 `배달 처리`/`수거 처리`, 오른쪽은 알림 종이다. 팀 이름 옆 파란 배지, 날짜·장소, 전화번호, 같은 폭의 `전화 / 출발 문자` 순서로 맞췄다. 아래는 전체 폭의 고객 부재와 보라 확정 버튼을 세로로 놓았다.
- 품목은 대표자 접수의 품목·수량 기준이며 촘촘한 행과 쪽 나눔을 유지했다. `− / 선택 수량 / +`와 확정 수량이 함께 바뀌고, 쪽이나 화면 크기를 바꿔도 선택 수량이 남는다. 미배정·오류 문구가 있으면 한 쪽의 행 수를 줄여 잘림을 막는다.
- `P.button`에 아이콘, `P.row`에 휴대폰 문구, 헤더에 화면별 배치 옵션을 추가했다. 새 CSS는 `data-pos-layout="driver-task"`인 기사 배달·수거 처리에만 적용한다. 기존 매장 업무 처리·발권처 환불·차량 보관에는 적용하지 않는다. 글꼴 파일과 공용 글꼴은 그대로다.

## 2026-09-22 A5(2) 재개 — 차량 보관 비교·검증

사용자 확인: **"둘다 가능하게 해줘"**. 위 구현 전 중단 기록(`8db62bf`) 뒤의 결정이다. 이번 화면은 (2) 차량 보관 하나이며, 매장 직원의 기존 입고와 기사의 자기 차량 입고를 모두 사용할 수 있게 했다. **구현·검증을 마쳤고 비교 그림의 사용자 검토를 기다린다. 다음 화면은 시작하지 않는다.**

### 고친 곳

- 헤더는 `차량 보관`과 제목 옆 `보관 N개` 알약, 본문은 `장비 / 의류 / 헬멧 / 리프트권` 순서의 읽기 전용 집계로 맞췄다. 태블릿은 네 칸, 휴대폰은 2×2다. 리프트권은 `N매`로 표시한다.
- 품목은 `스키 N대`처럼 이름·수량 한 줄, 실제 배달·수거 상태 한 줄, 오른쪽 파랑/갈색 주황 알약으로 맞췄다. 사용자가 정한 촘촘한 행·쪽 나눔을 유지했다. 가상 촬영 자료는 대표자만 있는 접수(`people: []`)이며 사람별로 나누지 않았다.
- 태블릿 아래는 차량·보관·입고 대기 요약, 오른쪽 `업무 목록 → 매장 입고 N개`다. 휴대폰은 위 `‹ 목록`, 맨 아래 전체 폭 보라 `매장 입고 N개`로 맞췄다. 시안 버튼을 다른 동작으로 바꾸지 않았다.
- 기사 버튼은 기존 실물 이동인 `stock.move(kind: receive)`에 연결했다. 서버가 **자기 차량 + 고객에게서 수거함 + 다른 배달·권 배정·환불·분실 처리가 없음**을 확인한 실물만 매장으로 옮긴다. 기사의 차량·입고 대기 수량은 실제 자료로 계산한다. 매장 직원은 기존 `ops.receive`와 `매장 입고 확정` 창을 그대로 쓴다.
- 입고는 위치·반납 집계와 처리자 이력을 바꾸며 **수납 금액은 바꾸지 않는다**. 기사의 전체 접수·정산 접근도 늘리지 않았다. 다른 차량이나 이미 이동한 실물이 섞이면 전부 거절하고, 응답이 끊겨 다시 확인해도 같은 입고를 두 번 기록하지 않는다.
- `P.tile`에 읽기 전용 `metric`, `P.row`에 기존 글자 맞춤을 쓰는 `fitDescription` 옵션을 추가했다. 새 스타일은 기사 `data-pos-layout="driver-stock"`에만 적용한다. 공용 글꼴·글꼴 파일·기존 매장 차량 보관 화면은 그대로다.

## 2026-09-22 A6 공통 바깥 배치 — 시안 요소 표

### 고친 곳

- 매장 포스·관리 헤더가 화면 맨 위의 전체 폭을 차지한다. 왼쪽 메뉴와 본문은 그 아래 같은 높이에서 시작한다.
- 1024×600에서 헤더는 `(0, 0) / 1024×60`, 메뉴는 `(0, 60) / 112×540`, 본문은 `(112, 60) / 912×540`이다. 본문을 추가로 아래로 밀지 않았다.
- 메뉴 9개의 기존 56px 높이는 낮은 표시 영역에서 약 **53.77px**로 함께 줄어든다. 52px 하한은 유지하고, `관리`를 포함한 모든 메뉴를 끝까지 보여 준다. 글꼴·글자 크기·줄바꿈·동작·입력 이름은 바꾸지 않았다.
- 적용은 매장 화면에 한정했다. 기사 화면·로그인·고객 입력 화면의 기존 틀은 유지한다.
- `scripts/capture-pos-release.cjs`에 전체 폭 헤더, 헤더 아래 메뉴·본문, 메뉴 9개/7개가 모두 표시 영역 안에 들어오는 검사를 더했다. 60개 촬영 중 매장 상태 **59개**에서 이 관계를 확인한다.
