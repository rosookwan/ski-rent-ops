# 51. 시안과 달라진 부분의 사유와 현재 마무리 상태

2026-09-21. 사용자 요청: "지금까지 한거 마무리하고 업무상 필요로 인해 달라진 것들은 사유를 써줘 문서에".

## 현재 상태

- 화면 코드의 최신 기준은 `feat/pos-ui-v4`의 `3636a02`다. A1~A4를 시안에 다시 맞춘 내용은 아래 "2026-09-21 재수정"에 있다. `aa1dae6`은 그 이전 구현·검사 기록이다.
- **A4의 남은 모양 차이는 아래 재수정 기록을 따른다.** 기존의 "시안에 맞춤", "완료" 보고나 업무 검사 통과를 시각적 일치 확인으로 해석하면 안 된다.
- **2026-09-22 A5(1) 업무 처리:** D02·D12를 열어 시안 요소 표를 작성했다. `출발 문자` 기능과 `예약금 미수` 자료가 없어 사용자 공통 규칙 6번에 따라 **화면 코드를 고치기 전에 중단**했다. 아래 A5(1) 기록 참조. (2) 차량 보관은 미착수이며, `main`·Pages·운영 서버에는 반영하지 않았다.
- 아래의 업무 사유는 **데이터와 처리 절차를 보존하는 이유**다. 버튼 모양·패널 비율·여백·색·배치를 임의로 바꿔도 된다는 뜻이 아니다.

## 기능·자료가 아직 없는 부분

이 항목들은 업무상 반드시 달라야 하는 디자인이 아니라 **시안 대비 남은 구현 범위**다.

| 화면 | 남은 차이 | 현재 사실 |
|---|---|---|
| M02 재고 | 시안의 `재고 목록 인쇄`가 없고 현재 하단에는 `실물 목록`이 있다. | 이번 A4에서는 재고 인쇄를 구현하지 않았다. 인쇄 대신 다른 버튼을 배치한 것을 시안 충족으로 볼 수 없다. |
| M04 거래처 | 담당자, 단가·일수에 따른 개별 대여 요금 표시 | 현재 거래처 저장은 이름·전화, 약정은 거래처 단위 금액·사유다. 예시 담당자나 단가를 실제 값처럼 넣지 않았다. 이 자료가 필요하면 별도 기능 구현이 필요하다. |
| M04 거래처 | `장부 인쇄`·`전화` 버튼이 현재 거래처 상세에 없다. | A4에서 해당 진입점을 연결하지 않았다. 특히 전화는 다른 접수 상세에 기존 `tel:` 연결이 있으므로, 시스템 전체가 전화를 지원하지 않는다는 사유는 맞지 않는다. |
| 고객 상세 | 고객 상세 전용 시안 | 인계 문서에는 P04 접수 상세의 좌우 배치를 사용하라고 되어 있다. 비교 그림의 P04를 고객 상세 전용 승인 시안으로 표현하지 않는다. |

### 막힌 항목 — 다른 기능으로 대체하지 않음

사용자 공통 규칙 6번: **"시안대로 할 수 없는 항목(자료·기능이 없음, 높이가 모자람 등)은 다른 것으로 대체하지 말고 멈추고 사유를 먼저 보고한다."** 아래 두 항목이 이에 해당해 화면 구현을 중단했다.

| 항목 | 확인한 사실·근거 | 먼저 정해져야 하는 것 |
|---|---|---|
| `출발 문자` | [업무 처리 화면](../design/app/pos-dispatch.js)의 `taskPage()`에는 `tel:` 전화만 있고 출발 문자 동작이 없다. [기존 문자 기능](../src/workflows/service.js)의 `sendFormLink()`는 매장 권한으로 고객 입력폼 링크를 보내는 전용 기능이며, 출발 문자나 기사 발송 기능이 아니다. | 출발 문자를 휴대폰 문자 앱에서 작성하는지, 서버로 발송하는지와 발송할 문구. 기존 입력폼 문자를 대신 보내거나 다른 버튼으로 채우지 않는다. |

### 고친 곳 / 아직 다른 곳(사유)

- **고친 곳:** 화면 코드 수정 없음. 위 시안 요소 표, 사용자 결정인 촘촘한 행 목록 예외, 두 중단 사유를 문서화했다.
- **아직 다른 곳:** 출발 문자·예약금 미수 안내가 없다. 이는 허용한 디자인 차이가 아니라 미구현 기능·자료다. 현재 코드의 `배달 업무` 제목, 전체 날짜 표기, 하단 전화 버튼, 확정 버튼의 수량 누락도 시안과 다르며, 앞의 두 기능이 없다는 이유로 정당화하지 않는다.
- **시안 일치:** 미완료. 구현과 실제 화면 촬영 전이므로 위 항목을 `같음`으로 표시하지 않았다. 비교 그림도 아직 만들지 않았다. 재개 후 `docs/pos-ui-a5/`에는 해당 화면의 1024×600 촬영과 `*-compare.png`만 넣는다.
- **검증:** 문서 링크 62개 경로와 `git diff --check`를 확인했고, 바뀐 파일이 지정 문서 3개뿐이며 앱 코드는 `3636a02`와 같음을 확인했다. 빌드, 업무 검사 6종, `pos:screens:driver`와 줄 수 검사, `pos:rules`, `check`, 단위·반납·알림·PWA는 이번에 실행하지 않았으며 통과로 보고하지 않는다. 구현 후 사용자 지정 순서로 모두 실행해야 한다.
- **할 일:** 위 두 항목의 처리 기준을 확인한 후 (1) 업무 처리만 구현·검증·비교한다. 항목별 `같음 / 다름(사유)`을 보고하고 멈춘다. (2) 차량 보관은 사용자 확인 뒤 시작한다.
- **알고만 있을 것:** 이번 변경은 작업 브랜치의 문서뿐이다. 앱 코드는 `3636a02` 그대로이며 `main`·Pages·운영 서버·사용자 인쇄기 문서·임시 설정 파일은 건드리지 않았다.
